# REBUILD79 — 단답형(blank) 입력칸 미표시 전수 수정

> **작성**: 2026-07-04 KST
> **범위**: `scripts/fix-blank-templates.mjs`(신규), 운영 DB `kisa_questions.blank_template` (76건 UPDATE)
> **목적**: 단답형 드릴에서 **입력칸이 아예 안 뜨는 문항 76건**을 전수 찾아 수정. 원인은 빈칸 표기 불일치.

---

## §1. 근본 원인

- `BlankCard.jsx` 파서는 빈칸을 **`{{N}}` 패턴만** 인식한다.
- 그러나 DB `blank_template` 에는 빈칸이 여러 표기로 저장돼 있었다:
  | 표기 | 예 | 건수 |
  |---|---|---|
  | `(①)(②)` 원문자 | 클래스 (①)나 클래스변수 | 10 |
  | `___①___` 원문자+언더스코어 | DB와 ___①___으로 분리 | 10 |
  | `(가)(나)` 한글 낱자 | (가) 영역의 경우 | 22 |
  | `___(N)___` 괄호숫자 | Integer.___(1)___(tmp) | 24 |
  | `[[N]]` | [[1]]와(과) | 2 |
  | `{{0}}` 0-base | 검사시점({{0}})과 | 일부 |
- 표기가 `{{N}}` 이 아니면 파서가 빈칸을 못 찾아 `<input>` 이 0개 → **입력 불가**. `{{0}}` 은 답 idx(1-base)와 어긋남.

## §2. 정규화 (`fix-blank-templates.mjs`)

- `blank_answers` 개수(nAns) 기준으로 마커를 `{{1}}..{{nAns}}` 로 변환:
  1. `[[N]]` → `{{N}}`
  2. 언더스코어 동반 괄호숫자 `___(N)___` → `{{N}}` (자리수 무관)
  3. 순수 한 자리 괄호숫자 `(1~9)` → `{{N}}` (코드 인자 `setMaxAge(1000)` 등 여러 자리는 제외 — 오탐 방지)
  4. 원문자 `①~⑳`(앞뒤 언더스코어·괄호 흡수) → 번호
  5. 한글 낱자 `(가)~(하)` → 순서 번호
  6. 순수 언더스코어 `_{3,}` 만 있으면 등장 순서로 번호
  7. `{{0}}` 시작이면 전체 +1 시프트(1-base)
- **안전장치**: 변환 후 "고유 빈칸번호 == {1..nAns}" 를 만족할 때만 적용. 불일치는 미적용 + 로그(수동 검토). `--apply` 없으면 dry-run.

## §3. 결과

- dry-run: 정상 60 · 정규화 76 · 실패 0 (초기 실패 26 → 규칙 보강으로 0).
  - 마지막 실패였던 IMP-IV-13 은 코드의 `setMaxAge(1000)` 인자를 빈칸으로 오인한 것 → 순수 괄호숫자를 한 자리로 제한해 해결.
- `--apply` 후 재검증: **136건 전부 정상**(정규화 0·실패 0).
- 프론트 무변경(BlankCard 파서 그대로). DB 데이터만 표준화 → 전 단답형 문항 입력칸 정상 렌더.

## §4. 재현/유지

- 향후 단답형 시드 추가 시 `{{N}}` 표기를 표준으로 쓰고, 의심되면 `node scripts/fix-blank-templates.mjs`(dry-run)로 점검.
