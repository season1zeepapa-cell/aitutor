# DSG-SF-07 · 중요정보 저장

> **단계** 설계 · **분류** 보안기능
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §2.7 (p.152–157)
> **연관 구현약점** [암호화 되지 않은 중요정보 (IMP-SF-05)](./IMP-SF-05-unencrypted-sensitive-info.md) · 사용자 하드디스크에 저장되는 쿠키를 통한 정보 노출

## 설계항목 / 설명

중요정보(비밀번호, 개인정보 등)를 저장·보관하는 방법이 안전하도록 설계한다.

## 보안대책

- ① 중요정보 또는 개인정보는 **암호화해서 저장**
- ② 불필요하거나 사용하지 않는 중요정보가 **메모리에 남지 않도록** 설계

## 가. 취약점 개요

- **사례1 중요정보 평문저장** — 개인정보·인증정보·금융정보를 평문 저장하면 공격자에게 민감 정보 노출
- **사례2 쿠키를 통한 정보노출** — 개인정보·인증정보가 영속적 쿠키(Persistent Cookie)에 저장되면 공격자 접근 기회 증가

## 나. 설계 시 고려사항

- **① 중요정보 암호화 저장** — 중요정보가 다뤄지는 **"안전영역"** 설정, 외부 누출 방지. 서버 DB·파일은 반드시 암호화("암호연산" 설계항목의 안전한 알고리즘·키 사용). 쿠키·HTML5 로컬저장소 등 클라이언트 측 저장 금지(부득이 시 암호화). 중요 로직·주석은 서버 측 언어에서만 처리
- **② 메모리 잔존 방지·캐싱 제한** — 불필요 데이터 메모리 초기화 시큐어코딩 규칙, 민감 페이지 사용자 측 캐싱 비활성화(부득이 시 암호화), 인증정보 포함 웹 폼 자동완성 비활성화

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 중요정보·개인정보 암호화 저장
- **Q1. 중요정보·개인정보가 암호화되어 저장되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 암호화 대상 분류(개인정보보호법 고유식별정보·바이오정보·비밀번호 / 정보통신망법 주민번호·신용카드·계좌 / 위치정보법 위치정보 / 시스템 중요정보) → **요구사항정의서·아키텍처설계서**
  - `1-3` 암호화 구현 프로그램 또는 외부 암호 라이브러리 설계 → **요구사항정의서·아키텍처설계서·프로그램명세서·클래스설계서**
  - `1-4` 암·복호화 코딩규칙 → **개발가이드**
- **Q2. 암호화 여부 점검 테스트 계획이 있는가?**
  - `2-1` 저장 중요정보 암호화 점검 → **단위테스트계획서**

### 요구사항 ② 메모리 잔존 방지
- **Q1. 사용하지 않는 중요정보가 메모리에 남지 않도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 사용 후 메모리 초기화 코딩규칙 → **개발가이드**
  - `1-3` 중요정보 페이지 캐싱 금지 코딩규칙 → **개발가이드**
- **Q2. 메모리 잔존 점검 테스트 계획이 있는가?**
  - `2-1` 메모리 잔존 점검 → **단위테스트계획서**
  - `2-2` 사용자 측 캐싱 점검 → **단위테스트계획서**
