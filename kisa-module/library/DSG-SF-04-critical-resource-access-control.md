# DSG-SF-04 · 중요자원 접근통제

> **단계** 설계 · **분류** 보안기능
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §2.4 (p.127–137)
> **연관 구현약점** [부적절한 인가 (IMP-SF-02)](./IMP-SF-02-improper-authorization.md) · [중요한 자원에 대한 잘못된 권한 설정 (IMP-SF-03)](./IMP-SF-03-incorrect-permission-assignment.md)

## 설계항목 / 설명

중요자원(프로그램 설정, 민감한 사용자 데이터 등)을 정의하고, 정의된 중요자원에 대한 신뢰할 수 있는 접근통제 방법(권한관리 포함) 설계 및 접근통제 실패 시 처리방법을 설계한다.

## 보안대책

- ① 중요자원에 대한 **접근통제 정책**을 수립하여 적용
- ② 중요기능에 대한 **접근통제 정책**을 수립하여 적용
- ③ 관리자 페이지에 대한 **접근통제 정책**을 수립하여 적용

## 가. 취약점 개요

- **사례1 관리자 페이지 노출** — 관리자페이지가 인터넷으로 접근 가능하면 SQL삽입·무차별 대입 등 공격 빌미를 제공
- **사례2 SSI 삽입** — HTML 변수값으로 입력된 SSI 명령문이 서버에서 수행되어 데이터 정보가 누출
- **사례3 부적절한 인가** — 모든 실행경로에 대해 접근제어를 검사하지 않거나 불완전하면 정보 유출
- **사례4 중요자원에 대한 잘못된 권한 설정** — 읽기·수정 권한을 의도치 않게 허가하면 권한 없는 사용자가 자원 사용

## 나. 설계 시 고려사항

- **RBAC / ACL 모델** — 역할기반 접근제어(RBAC)로 역할 기반 권한 부여, 접근제어목록(ACL)으로 자원별 권한 설정. Spring Security ACL 모듈로 ① ACL엔트리 검색·수정 ② 메서드 호출 전 권한 검증 ③ 호출 후 반환 객체 권한 검증
1. **중요자원 접근통제** — 최소권한 설정, ACL/RBAC 적용, **최소권한 원칙 + 권한분리** 정책에 따라 권한 할당, 요구조건 충족 시에만 접근 허가
2. **중요기능 접근통제** — 익명·일반·특권사용자·관리자 영역 구분, RBAC + 비즈니스 로직, 파라미터 변조 확인, 권한상승은 가능한 마지막에 수행 후 즉시 원상복귀
3. **관리자 페이지 접근통제** — URL 추측 불가, 암호화 통신(TLS), 접속 IP 제한 + 80번 아닌 별도 포트, 추가인증. 중앙 집중 접근제어 프레임워크 활용
   - 프레임워크/라이브러리: Java(Spring Security·ACL·RBAC), ASP.NET(.NET Framework·ACL·RBAC), PHP(PHP-RBAC)

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 중요자원 접근통제 정책
- **Q1. 접근통제 정책이 수립·적용되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 중요자원 식별(파일·프로세스·메모리·DB·정보) → **요구사항정의서·아키텍처설계서**
  - `1-3` 접근 사용자/프로그램 분류 → **요구사항정의서·아키텍처설계서**
  - `1-4` 최소권한 할당 설계 → **요구사항정의서·아키텍처설계서**
  - `1-5` 자원별 권한 분리 할당 → **요구사항정의서·아키텍처설계서**
  - `1-6` ACL/RBAC 정책 설정 + 구현 프로그램/라이브러리 → **아키텍처설계서·프로그램명세서·유즈케이스설계서·클래스설계서**
  - `1-7` 프레임워크 컴포넌트 적용 시 모든 요청에 적용 → **아키텍처설계서**
  - `1-8` 개별 프로그램 적용 시 호출방식 코딩규칙 → **개발가이드**
- **Q2. 접근통제 점검 테스트 계획이 있는가?**
  - `2-1` 권한 외 작업 요청 통제 점검 → **단위테스트케이스**

### 요구사항 ② 중요기능 접근통제 정책
- **Q1. 접근통제 정책이 수립·적용되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 중요기능(개인정보조회·변경·관리자등록·등급등록) 식별 → **요구사항정의서·아키텍처설계서**
  - `1-3` 접근 사용자/프로그램 분류 → **요구사항정의서·아키텍처설계서**
  - `1-4` 최소권한 할당 설계 → **요구사항정의서·아키텍처설계서**
  - `1-5` 자원별 권한 분리 할당 → **요구사항정의서·아키텍처설계서**
  - `1-6` ACL/RBAC 정책 + 구현 프로그램/라이브러리 → **아키텍처설계서·프로그램명세서·유즈케이스설계서·클래스설계서**
  - `1-7` 프레임워크 컴포넌트 적용 시 모든 요청에 적용 → **아키텍처설계서**
  - `1-8` 개별 프로그램 적용 시 호출방식 코딩규칙 → **개발가이드**
- **Q2. 접근통제 점검 테스트 계획이 있는가?**
  - `2-1` 권한 외 작업 요청 통제 점검 → **단위테스트케이스**

### 요구사항 ③ 관리자 페이지 접근통제 정책
- **Q1. 접근통제정책이 적용되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 일반 페이지와 다른 포트 사용 → **요구사항정의서·아키텍처설계서**
  - `1-3` 외부 네트워크 접근 차단 → **요구사항정의서·아키텍처설계서**
  - `1-4` 접근 가능 IP 정의·반영 → **요구사항정의서·아키텍처설계서**
  - `1-5` 암호화 통신 사용 → **요구사항정의서·아키텍처설계서**
  - `1-6` 접속자/페이지 정보 로깅 설계 → **아키텍처설계서·프로그램명세서·유즈케이스설계서·클래스설계서**
- **Q2. 접근통제 점검 테스트 계획이 있는가?**
  - `2-1` 접근통제 확인 테스트 → **단위테스트케이스**
  - `2-2` 외부망 접속 IP·포트 확인 → **단위테스트케이스**
  - `2-3` 스니핑으로 요청 암호화 전달 확인 → **단위테스트케이스**
