# DSG-SF-01 · 인증 대상 및 방식

> **단계** 설계 · **분류** 보안기능
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §2.1 (p.103–109)
> **연관 구현약점** 서버사이드 요청 위조 · 적절한 인증 없는 중요기능 허용 (IMP-SF-01) · 부적절한 인증서 유효성 검증 · DNS lookup에 의존한 보안 결정

## 설계항목 / 설명

중요정보·기능의 특성에 따라 인증방식을 정의하고 정의된 인증방식을 우회하지 못하게 설계해야 한다.

## 보안대책

- ① 중요기능·리소스에 대해 **인증 후 사용** 정책 적용
- ② **안전한 인증방식** 사용으로 인증우회·권한 상승 방지
- ③ 중요기능에 대해 **2단계(2-factor) 인증** 고려

## 가. 취약점 개요

중요기능이나 리소스 요청 시 인증 여부를 먼저 확인하지 않고 요청을 처리하면 중요 정보·리소스가 노출될 수 있다(적절한 인증 없는 중요기능 허용).

## 나. 설계 시 고려사항

1. **인증 후 사용 정책** — 분석단계 분류 중요기능에 일괄 인증 요구. 기능↔인증 매핑 컴포넌트 개발 또는 인증 프레임워크/라이브러리로 **중앙집중식 인증** 적용
2. **안전한 인증방식** — 인증정보는 서버 측 저장, 접근 시 서버에서 인증 확인
   - (ㄱ) 일회용 비밀번호: A. 시각/이벤트/질의응답 정보로 생성 B. 시각정보는 특정시간만 유효·연계정보 추측 불가 보호 C. 시간 제한(금융 30~60초) D. 6자리 이상 숫자·문자 E. OTP발생기·인증서버 동일 정보 생성
3. **2단계 인증** — 멀티 디바이스(SMS/ARS)·공인인증서·바이오(지문/홍채). Type1(지식)·Type2(소유)·Type3(생체) 중 2개 이상 사용
   - 프레임워크: Java(Spring Security), ASP.NET(.NET Framework), PHP(Zend Framework·Symfony)

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 인증 후 사용 정책
- **Q1. 중요기능과 중요 리소스가 분류되어 있는가?** → **요구사항정의서**
- **Q2. 인증 정책이 안전하게 적용되도록 설계되어 있는가?**
  - `2-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `2-2` 접근 권한 분류 → **요구사항정의서·아키텍처설계서**
  - `2-3` 접근권한 기반 인증 요구 기능/리소스 분류 → **아키텍처설계서·DB설계서**
  - `2-4` 인증 누락 방지 안전 설계(프레임워크 컴포넌트) → **아키텍처설계서·유즈케이스설계서·클래스설계서**
- **Q3. 접근 우회 취약점 점검 테스트 계획이 있는가?** → **요구사항정의서**

### 요구사항 ② 안전한 인증방식
- **Q1. 안전한 인증방식이 적용되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 지식/소유/생체 기반 인증 → **아키텍처설계서·클래스설계서·유즈케이스명세서**
  - `1-3` 인증정보 암호화 서버 저장 → **아키텍처설계서·DB설계서·클래스설계서·유즈케이스명세서**
  - `1-4` 인증횟수 제한·오류처리 → **유즈케이스명세서·클래스설계서·DB설계서**
  - `1-5` 인증오류/실패 로깅(시간·IP·ID 포함) → **유즈케이스명세서·클래스설계서**
- **Q2. 인증우회/권한상승 점검 테스트 계획이 있는가?**
  - `2-1` 인증실패 로그 기록 점검 → **단위테스트케이스**
  - `2-2` 인증 없이 중요기능 접근 차단 점검 → **단위테스트케이스**

### 요구사항 ③ 2단계 인증
- **Q1. 추가 인증 중요기능이 안전한 인증방식으로 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 개인정보변경·비밀번호재설정·권한관리·관리자기능 추가인증 → **아키텍처설계서·유즈케이스명세서·클래스설계서**
  - `1-3` 안전한 추가 인증방식(OTP·멀티디바이스·인증서·바이오) → **아키텍처설계서·유즈케이스명세서·클래스설계서**
  - `1-4` 사용/실패 시 시간·IP·ID·기능 로깅 → **유즈케이스명세서·클래스설계서**
- **Q2. 추가 인증요구 점검 테스트 계획이 있는가?**
  - `2-1` 추가인증 요구 점검 → **단위테스트케이스**
  - `2-2` 인증오류/실패 로깅 점검 → **단위테스트케이스**
