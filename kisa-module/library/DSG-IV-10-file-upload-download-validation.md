# DSG-IV-10 · 업로드·다운로드 파일 검증

> **단계** 설계 · **분류** 입력데이터 검증 및 표현
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §1.10 (p.93–102)
> **연관 구현약점** 위험한 형식 파일 업로드 (IMP-IV-06) · 부적절한 전자서명 확인 · 무결성 검사 없는 코드 다운로드

## 설계항목 / 설명

업로드·다운로드 파일의 무결성, 실행권한 등에 관한 유효성 검증방법 설계 및 부적합한 파일에 대한 처리방법을 설계한다.

## 보안대책

- ① 업로드되어 저장되는 파일의 **타입·크기·개수·실행권한**을 제한
- ② 업로드되어 저장되는 파일은 **외부에서 식별되지 않도록** 설계
- ③ 파일 다운로드 요청 시 **요청파일명 검증** 수행
- ④ 다운로드 받은 소스코드·실행파일은 **무결성 검사** 실행

## 가. 취약점 개요

- **사례1 위험한 형식 파일 업로드** — 서버에서 실행 가능한 스크립트(asp/jsp/php 등)를 업로드·실행하면 시스템 내부 명령 실행·외부 연결로 시스템 제어 가능
- **사례2 경로조작 파일 다운로드** — 경로 조작 문자를 필터링하지 않으면 접근제한 영역 경로 구성이 가능해져 정보누출·서비스 장애 유발
- **사례3 무결성 검사 없는 코드 다운로드** — 무결성 검사 없이 원격 코드를 받아 실행하면 호스트 변조·DNS 스푸핑·전송 중 변조로 악성코드 실행 가능

## 나. 설계 시 고려사항

1. **타입·크기·개수·실행권한 제한**
   - (ㄱ) 크기 제한 — Spring `MultipartResolver`(maxUploadSize, maxInMemorySize) 등 프레임워크/프로그램 설정
   - (ㄴ) 타입 제한 — 서버·클라이언트 동일 정책, MIME-TYPE과 확장자 동시 검사 공통 필터 모듈
   - (ㄷ) 실행권한 제거 — 저장 디렉터리 권한 확인, 업로드 경로 파일이 실행되지 않도록 서버 설정
   - 대응 프레임워크: Java(Spring), PHP(CodeIgniter), ASP.NET(.NET Framework)
2. **외부 식별 불가 저장** — (ㄱ) URL 직접 접근 불가 경로 + 다운로드 컨트롤러 통제 (ㄴ) 랜덤 파일명, 업로드↔저장 파일명 매핑을 DB 칼럼에 함께 저장
3. **다운로드 요청파일명 검증** — (ㄱ) `..` `/` `\` 경로조작 문자 필터링 (ㄴ) 허가 사용자·파일 확인 + 악성코드/바이러스 검사 (ㄷ) 화이트리스트 정책으로 허용 목록 내 파일만 접근
4. **무결성 검사** — 파일과 체크섬(해시) 값을 함께 받아 무결성 검사 후 사용

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 타입·크기·개수·실행권한 제한
- **Q1. 업로드 파일의 제한 정책과 방법이 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 타입·크기·개수·퍼미션 정의(프레임워크 사용/프로그램 설계) → **아키텍처설계서·유즈케이스설계서·클래스설계서**
- **Q2. 제한 정책 점검 테스트 계획이 있는가?**
  - `2-1` 허용되지 않는 타입·크기·개수 제한 점검 → **단위테스트케이스**
  - `2-2` 저장 파일의 실행 제한 점검 → **단위테스트케이스**

### 요구사항 ② 외부 식별 불가 저장
- **Q1. 안전한 저장위치에 저장되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 저장 경로·파일명 외부 비식별(난수 파일명, 중복 방지 알고리즘) → **유즈케이스명세서·클래스설계서**
  - `1-3` 원본↔저장 파일명 매핑정보 관리 → **유즈케이스명세서·클래스설계서·DB설계서**
- **Q2. 외부 식별 가능 여부 점검 테스트 계획이 있는가?** → **단위테스트케이스**

### 요구사항 ③ 다운로드 요청파일명 검증
- **Q1. 요청 파일명 검증이 수행되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 경로 조작 문자 포함 여부·DB 유효성 점검 → **유즈케이스명세서·클래스설계서·DB설계서**
- **Q2. 다운로드 정책 점검 테스트 계획이 있는가?**
  - `2-1` 조작된 파일명(`../ ..\`)·파라미터 조작 차단 점검 → **단위테스트케이스**

### 요구사항 ④ 무결성 검사
- **Q1. 무결성 확인이 가능하도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 무결성 검사값(해시) 제공 → **유즈케이스명세서·클래스설계서·DB설계서**
  - `1-3` 무결성 검사 후 다운로드 설계 → **유즈케이스명세서·클래스설계서**
- **Q2. 무결성 점검 테스트 계획이 있는가?**
  - `2-1` 변조 파일 다운로드 차단 점검 → **단위테스트케이스**
