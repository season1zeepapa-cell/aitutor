# DSG-IV-02 · XML 조회 및 결과 검증

> **단계** 설계 · **분류** 입력데이터 검증 및 표현
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §1.2 (p.50–53)
> **연관 구현약점** [XML 삽입 (IMP-IV-09)](./IMP-IV-09-xml-injection.md) · [부적절한 XML 외부개체 참조 (IMP-IV-08)](./IMP-IV-08-xml-external-entity.md)

## 설계항목 / 설명

XML 조회시 질의문(XPath, XQuery 등) 내 입력값과 그 조회결과에 대한 유효성 검증방법(필터링 등)과 유효하지 않은 값에 대한 처리방법을 설계해야 한다.

## 보안대책

- ① XML질의문에 사용되는 파라미터는 반드시 **XML쿼리를 조작할 수 없도록 필터링**해서 사용하거나, **미리 작성된 질의문에 입력값을 자료형에 따라 바인딩**해서 사용

## 가. 취약점 개요

XML 문서를 조회할 경우 입력값 조작으로 XQuery나 XPath와 같은 XML 질의문의 구조를 임의로 변경하여 허가되지 않은 데이터를 조회하거나 인증절차를 우회할 수 있다.

## 나. 설계 시 고려사항

1. **XML질의문 파라미터 필터링/바인딩** — XML질의문 파라미터는 조작 불가하도록 필터링하거나 미리 작성된 질의문에 자료형에 따라 바인딩
   - (ㄱ) 공통 검증 컴포넌트(Validator)로 입력값 검증 일괄 적용
   - (ㄴ) Filter 컴포넌트에서 XML삽입 활용 문자(`" [ ] / = @`)를 필터링하도록 작성하여 프레임워크에서 일괄 적용
   - (ㄷ) 개별 컴포넌트에서 XML삽입 유발 문자열(`" [ ] / = @` 등) 제거·치환하는 시큐어코딩 규칙 정의
   - (ㄹ) 외부입력값이 질의문 구조를 못 바꾸는 안전한 API(예: Java API-XQuery) 사용하도록 시큐어코딩 규칙 정의

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① XML질의문 파라미터 필터링/바인딩
- **Q1. 외부 입력값이 XML 데이터 조회에 사용될 때, 입력값이 조회 구문을 변경하지 않도록 보안설계가 적용되어 있는가?**
  - `1-1` 요구사항정의서 대책 + 요구사항추적표 추적 → **요구사항정의서·요구사항추적표·아키텍처설계서**
  - `1-2` 외부 입력값 필터링 기능 설계 또는 안전한 외부라이브러리 사용 → **프로그램명세서·컴포넌트설계서·유즈케이스설계서·클래스설계서**
  - `1-3` XML필터링 코딩규칙·안전한 API 설명이 개발가이드에 정의 → **개발가이드**
- **Q2. XML삽입 취약점 점검 테스트 계획이 수립되어 있는가?**
  - `2-1` XML조회 구문 변경 입력값(쿼리예약어, `" [ ] / = @` 등)으로 구문 변경 점검 → **단위테스트케이스**
