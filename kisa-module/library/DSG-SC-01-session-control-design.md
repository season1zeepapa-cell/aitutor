# DSG-SC-01 · 세션통제

> **단계** 설계 · **분류** 세션통제
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §4.1 (p.171–177)
> **연관 구현약점** [잘못된 세션에 의한 데이터 정보 노출 (IMP-EN-01)](./IMP-EN-01-wrong-session-data-exposure.md)

## 설계항목 / 설명

다른 세션간 데이터 공유금지, 세션 ID 노출금지, (재)로그인시 세션ID 변경, 세션종료(비활성화, 유효기간 등) 처리 등 세션을 안전하게 관리할 수 있는 방안을 설계해야 한다.

## 보안대책

- ① 세션 간 데이터가 **공유되지 않도록** 설계
- ② 세션이 **안전하게 관리**되도록 설계
- ③ 세션ID가 **안전하게 관리**되도록 설계

## 가. 취약점 개요

- **사례1(불충분한 세션관리)** — 일정 규칙의 세션ID 발급이나 과도하게 긴 세션 타임아웃 시 공격자가 사용자 권한을 도용
- **사례2(잘못된 세션에 의한 정보노출)** — 다중 스레드 환경에서 싱글톤 객체 필드에 경쟁조건(Race Condition) 발생 가능. java 서블릿 등에서는 정보 저장 멤버변수를 포함하지 않아 세션 간 데이터를 공유하지 않도록 함

## 나. 설계 시 고려사항

1. **세션 간 데이터 비공유** — 스레드 동작 컨트롤러/싱글톤 서비스 컴포넌트 설계 시 클래스 멤버변수·클래스변수는 세션 간 공유 데이터가 되므로, 읽고 쓰기 가능한 변수를 사용하지 않도록 설계
2. **안전한 세션 관리**
   - 모든 페이지에서 로그아웃 가능 UI 설계 + 로그아웃 시 세션 완전 제거 API(Java `session.invalidate()`) 사용 규칙 정의
   - 세션 타임아웃: 중요기능 **2~5분**, 위험도 낮은 앱 **15~30분**. 이전 세션 미종료 상태에서 새 세션 미생성
   - 브라우저 종료는 서버가 인지 불가 → 미사용 세션 강제 삭제 설계
   - 중복 로그인 불허 시 새 로그인 세션 생성 시 이전 세션 종료/연결 차단 검증 정책
   - 세션ID 쿠키에 **HttpOnly** 설정으로 JS 조회 차단(XSS 대응)
   - 비밀번호 변경 시 활성 세션 삭제 후 재할당
3. **안전한 세션ID 관리**
   - (ㄱ) 생성: 안전한 서버에서 생성, 최소 **128비트** 길이, 안전한 난수 알고리즘으로 예측 불가 값
   - (ㄴ) 사용: URL Rewrite 사용 시 세션ID가 URL에 노출되므로 미사용 설계
   - (ㄷ) 폐기: 로그인 성공 시 이전 세션ID 파기 후 재할당(세션 고정 공격 대응), 장기 접속 시 일정시간 주기적 재할당

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 세션 간 데이터 비공유
- **Q1. 세션 간 데이터가 공유되지 않도록 클래스가 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 스레드 동작 클래스 설계 시 읽기/쓰기 가능 공유 데이터 설계 여부(Servlet·Controller 멤버변수/클래스변수, JSP 선언부 변수) → **프로그램명세서·클래스설계서·유즈케이스명세서**
- **Q2. 세션 간 데이터 공유 점검 테스트 계획이 수립되어 있는가?**
  - `2-1` 여러 세션으로 공유 데이터 값 변경 여부 점검 → **단위테스트계획서**

### 요구사항 ② 안전한 세션 관리
- **Q1. 세션이 안전하게 관리되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 로그인 성공 시 세션 재할당 코딩규칙 → **개발가이드**
  - `1-3` 로그아웃 시 세션 완전 제거 코딩규칙 → **개발가이드**
  - `1-4` 일방적 연결종료 시 세션 제거 설계 → **유즈케이스설계서·클래스설계서**
  - `1-5` 미사용 세션 타임아웃 설정(중요기능 2~5분 / 저위험 15~30분) → **요구사항정의서·아키텍처설계서·유즈케이스설계서·클래스설계서**
  - `1-6` 비밀번호 변경 시 재인증·새 세션 할당 설계 → **유즈케이스설계서·클래스설계서**
- **Q2. 세션 안전 관리 점검 테스트 계획이 수립되어 있는가?**
  - `2-1` 로그인/로그아웃 안전 관리 점검 → **단위테스트계획서**
  - `2-2` 브라우저 강제종료·미사용 세션 안전 관리 점검 → **단위테스트계획서**
  - `2-3` 비밀번호 변경 시 안전 관리 점검 → **단위테스트계획서**

### 요구사항 ③ 안전한 세션ID 관리
- **Q1. 세션ID가 안전하게 관리되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 세션ID 서버 생성 웹서버 환경설정 계획 → **요구사항정의서·아키텍처설계서**
  - `1-3` 세션ID 전송을 쿠키로 제한 + HttpOnly 설정 환경설정 계획 → **요구사항정의서·아키텍처설계서**
  - `1-4` 장시간 접속 시 주기적 세션ID 재할당 환경설정 계획 → **요구사항정의서·아키텍처설계서**
  - `1-5` 로그인 전 세션ID를 로그인 성공 후 재할당 코딩규칙 → **개발가이드**
- **Q2. 세션ID 노출 여부 점검 테스트 계획을 수립하고 있는가?**
  - `2-1` JS로 세션ID값 노출 점검 → **단위테스트계획서**
  - `2-2` 장시간 접속 시 세션ID 재할당 점검 → **단위테스트계획서**
  - `2-3` 로그인 후 세션ID 재할당 점검 → **단위테스트계획서**
