# DSG-IV-01 · DBMS 조회 및 결과 검증

> **단계** 설계 · **분류** 입력데이터 검증 및 표현
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §1.1 (p.43–49)
> **연관 구현약점** [SQL 삽입 (IMP-IV-01)](./IMP-IV-01-sql-injection.md)

## 설계항목 / 설명

DBMS 조회 시 질의문(SQL) 내 입력값과 그 조회결과에 대한 유효성 검증방법(필터링 등)을 설계하고, 유효하지 않은 값에 대한 처리방법을 설계해야 한다.

## 보안대책

- ① 애플리케이션에서 DB연결을 수행할 때 **최소권한의 계정**을 사용
- ② 외부입력값이 삽입되는 SQL질의문을 **동적으로 생성·실행하지 않도록** 설계
- ③ 불가피하게 동적 생성 시, **입력값 검증 수행 후** 사용

## 가. 취약점 개요

DB와 연동된 응용프로그램이 입력 데이터 유효성을 검증하지 않으면, 공격자가 입력값에 SQL 질의문을 삽입해 DB 정보를 열람·조작할 수 있다. 서버가 입력값을 검증 없이 쿼리 실행에 사용하면 인가되지 않은 사용자가 DB 데이터를 무단 조회·삭제할 수 있다.

## 나. 설계 시 고려사항

1. **최소권한 DB 계정** — 침해 시 피해를 국한하도록 읽기·쓰기·삭제·업데이트 권한만 부여
2. **정적 쿼리 구조** — 외부 입력값이 쿼리 구조를 못 바꾸는 API/ORM 사용을 시큐어코딩 규칙으로 지정
3. **동적 쿼리 시 입력값 검증** — (ㄱ) Filter 컴포넌트 (ㄴ) MVC Interceptor (ㄷ) 공통 Validator 컴포넌트
   - 대응 프레임워크/라이브러리: Java(Hibernate·MyBatis·JPA), ASP.NET(AntiSQLi), PHP(MeekroDB·HTML Purifier)

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 최소권한 계정 사용
- **Q1. DB접속 계정이 할당되고 최소권한으로 설정되어 있는가?**
  - `1-1` 요구사항정의서 대책 + 아키텍처설계서 적용계획 + 요구사항추적표 추적 → **요구사항정의서·요구사항추적표·아키텍처설계서**
  - `1-2` 계정별 최소권한 할당 여부 → **아키텍처설계서·초기데이터설계서**
- **Q2. 권한 외 요청 차단 테스트 계획이 수립되어 있는가?**
  - `2-1` 권한 외 요청 차단 점검 테스트 계획 → **단위테스트케이스**

### 요구사항 ② 정적 SQL 사용
- **Q1. 외부 입력값이 쿼리 구조에 영향을 미치지 않도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` ORM 프레임워크 사용 → **아키텍처설계서 보안요구항목**
  - `1-3` 정적 쿼리 코딩법(mybatis `#{변수}`, PreparedStatement) 정의 → **개발가이드**
- **Q2. 쿼리 구조 변경 점검 테스트 계획이 있는가?**
  - `2-1` 특수문자(`' " = & | ! ( ) { } $ % @`)·예약어(UNION/SELECT/…)·함수명(DATABASE()/CONCAT()/…) 테스트 → **단위테스트케이스**

### 요구사항 ③ 동적 쿼리 입력값 검증
- **Q1. 입력값 필터링 기능이 구현되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` SQL필터링 기능 설계/외부라이브러리 → **프로그램명세서·클래스설계서·아키텍처설계서**
  - `1-3` 공통 필터링이 모든 DB 접근 기능에 적용 → **아키텍처설계서 보안요구항목**
  - `1-4` 필터링 코딩규칙 → **개발가이드**
- **Q2. 쿼리 구조 변경 점검 테스트 계획이 있는가?** → **단위테스트케이스**
