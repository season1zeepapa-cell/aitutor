# DSG-SF-05 · 암호키 관리

> **단계** 설계 · **분류** 보안기능
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §2.5 (p.137–144)
> **연관 구현약점** [하드코드된 중요정보 (IMP-SF-06)](./IMP-SF-06-hardcoded-sensitive-info.md) · 주석문안에 포함된 시스템 주요 정보

## 설계항목 / 설명

암호키 생성, 분배, 접근, 파기 등 암호키 생명주기별 암호키 관리방법을 안전하게 설계한다.

## 보안대책

- ① DB데이터 암호화 암호키는 KISA 「암호이용안내서」 정의 방법 적용
- ② 설정파일(xml, Properties) 내 중요정보 암호화 암호키는 **암호화하여 별도 디렉토리에 보관**

## 가. 취약점 개요

- **사례1 하드코드된 암호키** — 코드 내부에 암호화 키를 하드코딩하면 암호화 정보 유출 가능성 증가
- **사례2 주석문 안에 포함된 암호키** — 주석문에 암호키 설명이 포함되면 소스코드 접근 시 쉽게 노출

## 나. 설계 시 고려사항

- **① 암호키 관리 규칙** (ㄱ)
  1. DB와 **물리적으로 분리**된 장소에 별도 보관
  2. 키 생명주기 관리(생성·분배·사용·폐기) 명시적 암호화 정책 적용
  3. 비밀번호·암호화키는 메모리에 저장하지 않음
  4. 부득이 메모리 저장 시 사용 종료 후 **0으로 초기화**
  5. 키 생성·변경 시 **백업기능** 구현
  6. 키 종류에 따라 사용 유효기한 설정
- **① 암호키 관리 수준 — FIPS 140-2** (ㄴ)
  | 레벨 | 내용 |
  |------|------|
  | Level 1 | 기본 보안요구사항만 충족, 최소한의 보안 |
  | Level 2 | 불법 접근 방지 + 침입 후 변조 증거 제공(물리적 보안) |
  | Level 3 | 강력한 변조 탐지·대응, 침입 감지 시 저장 키 삭제 |
  | Level 4 | 외부 전압·온도 감지, 슈퍼쿨링 등 환경 이상 시 암호키 삭제 |
- **① 키 생명주기 프로세스** (ㄷ) 키 생성(생성자·방법 절차) / 키 사용(방법·변경주기·접근통제) / 키 폐기(폐기 조건·절차)
- **① 키 복구 방안** (ㄹ) 퇴사 등 복구 필요 시 암호키는 정보보호 담당자 관리하 관리대장에서 복구, 비밀번호는 임시 비밀번호 발급
- **① 암호키 사용 유효기간 (NIST 권고안)** (ㅁ)
  | 키 종류 | 송신자 사용기간 | 수신자 사용기간 |
  |---------|-----------------|------------------|
  | 대칭키 비밀키 | 최대 2년 | (송신자 사용기간+3년) 이하 |
  | 암호화 공개키 | 최대 2년 | |
  | 복호화 개인키 | 최대 2년 | |
  | 검증용 공개키 | 1~3년 | |
  | 서명용 개인키 | 키 크기에 따라 다름 | |
- **② 설정파일 암호키** — 마스터키로 암호화하여 별도 디렉터리에 보관

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 암호키 관리 정책
- **Q1. 암호키 관리 정책이 수립되고 안전한 관리 방법이 설계에 반영되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 설정파일 중요정보(DB계정정보 등) 암호화 저장 → **요구사항정의서·아키텍처설계서**
  - `1-3` 설정파일 암·복호화 키를 별도 위치 저장 → **요구사항정의서·아키텍처설계서**
  - `1-4` 암호키 관리수준 정의 → **요구사항정의서·아키텍처설계서**
  - `1-5` 키 생성·변경방법 + 백업정책 → **요구사항정의서·아키텍처설계서·유즈케이스설계서**
  - `1-6` 키 사용기간·경과 시 대응(대칭키 2년 등) → **요구사항정의서·아키텍처설계서**
  - `1-7` 사용 종료 후 메모리 0 초기화 코딩규칙 → **개발가이드**
- **Q2. 암호키 관리 점검 테스트 계획이 있는가?**
  - `2-1` 암호키 외부 유출 점검 → **단위테스트케이스**

### 요구사항 ② 설정파일 암호키 별도 보관
- **Q1. 설정파일 중요정보가 안전하게 암호화 저장되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 설정파일 중요정보 암호화 저장 → **요구사항정의서·아키텍처설계서**
  - `1-3` 암·복호화 키 별도 위치 저장 → **요구사항정의서·아키텍처설계서**
- **Q2. 암호화 저장 점검 테스트 계획이 있는가?**
  - `2-1` 중요정보 암호화 저장 점검 → **단위테스트케이스**
  - `2-2` 암호키가 안전한 위치에 저장·사용되는지 점검 → **단위테스트케이스**
