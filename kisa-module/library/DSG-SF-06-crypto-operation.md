# DSG-SF-06 · 암호연산

> **단계** 설계 · **분류** 보안기능
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §2.6 (p.144–152)
> **연관 구현약점** [취약한 암호화 알고리즘 사용 (IMP-SF-04)](./IMP-SF-04-weak-crypto-algorithm.md) · [충분하지 않은 키 길이 사용 (IMP-SF-07)](./IMP-SF-07-insufficient-key-length.md) · [적절하지 않은 난수 값 사용 (IMP-SF-08)](./IMP-SF-08-improper-random-value.md) · 부적절한 인증서 유효성 검증 · [솔트 없이 일방향 해쉬함수 사용 (IMP-SF-14)](./IMP-SF-14-one-way-hash-without-salt.md)

## 설계항목 / 설명

국제표준 또는 검증필 암호모듈로 등재된 안전한 암호 알고리즘을 선정하고 충분한 암호키 길이, 솔트, 충분한 난수 값을 적용한 안전한 암호연산 수행방법을 설계한다.

## 보안대책

- ① 암·복호화 시 KISA 『암호이용안내서』 정의 **알고리즘 + 안전한 키 길이** 사용
- ② 복호화 안 되는 암호화(해시) 시 **안전한 해시 알고리즘 + 솔트값** 적용
- ③ 난수 생성 시 **안전한 난수 생성 알고리즘** 사용

## 가. 취약점 개요

- **사례1 취약한 암호알고리즘** — base64 같은 지나치게 간단한 인코딩으로는 비밀번호 보호 불가
- **사례2 충분하지 않은 키 길이** — 검증 알고리즘이라도 키 길이가 짧으면 단시간에 키 탈취·복호화
- **사례3 적절하지 않은 난수 값** — 예측 가능한 난수는 공격자가 다음 숫자를 예상하여 공격
- **사례4 솔트 없이 일방향 해시** — 솔트 없이 해시 저장하면 레인보우 테이블 전수조사로 비밀번호 탈취

## 나. 설계 시 고려사항

- **① 안전한 알고리즘·키 길이** — KISA 『암호 알고리즘 및 키 길이 이용 안내서』 기준
  - NIST 최소 키길이 권고(예): 128비트(30년~) AES-128 / RSA 3072 / ECC 256, 256비트 AES-256 / RSA 15360 / ECC 512
  - 권고 대칭키: SEED·ARIA-128/192/256·AES-128/192/256·Camelia·Blowfish·MISTY1·KASUMI 등
  - 권고 비대칭키: RSA·KCDSA(전자서명용)·RSAES-OAEP·ElGamal·ECC·ECKCDSA 등
- **② 안전한 해시 + 솔트** — 목적별(메시지인증/키유도/난수생성 vs 단순해시/전자서명)·보안강도별 선택. 국내 권고: SHA-256/384/512(HAS-160, SHA-1은 저강도)
- **③ 안전한 난수** — FIPS 140-2 인증 암호모듈 난수생성기 + **256비트 이상 시드**, 이전 결과를 다음 시드로 쓰는 의사난수생성기 사용

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.
> ⚠️ 원문 진단 세부사항은 요구사항 라벨이 ① → ③(해시) → ③(난수)으로 표기되어 있으나, 실제 내용은 보안대책 ①/②/③에 대응한다(원문 라벨 보존).

### 요구사항 ① 안전한 암호 알고리즘·키 길이
- **Q1. 안전한 알고리즘과 키 길이를 사용하도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 안전한 암호 알고리즘(대칭 SEED·ARIA·AES / 비대칭 RSA·KCDSA·ECC) → **요구사항정의서·아키텍처설계서**
  - `1-3` 안전한 키 길이(대칭 128비트↑ / 비대칭 2,048비트↑) → **요구사항정의서·아키텍처설계서**

### 요구사항 ③ 안전한 해시 + 솔트
- **Q1. 일방향 암호화 해시함수 사용방법이 안전하게 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 안전한 알고리즘(SHA-2 계열: SHA-224/256/384/512) → **요구사항정의서·아키텍처설계서**
  - `1-3` 솔트값(안전한 난수값) 적용 → **요구사항정의서·아키텍처설계서·DB설계서**
- **Q2. 해시 데이터 크랙 점검 테스트 계획이 있는가?**
  - `2-1` 암호화 데이터 복호화 시도 포함 테스트 → **단위테스트계획서**

### 요구사항 ③ 안전한 난수 생성
- **Q1. 안전한 난수생성 알고리즘을 사용하도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 안전한 난수 코딩규칙(JAVA: SecureRandom·Random / C: randomize(seed)) → **개발가이드 코딩규칙**
- **Q2. 생성된 난수 안전성 점검 테스트 계획이 있는가?**
  - `2-1` 난수 안전성 점검 테스트 → **단위테스트계획서**
