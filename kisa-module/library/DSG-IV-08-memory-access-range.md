# DSG-IV-08 · 허용된 범위내 메모리 접근

> **단계** 설계 · **분류** 입력데이터 검증 및 표현
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §1.8 (p.81–85)
> **연관 구현약점** [메모리 버퍼 오버플로우 (IMP-IV-16)](./IMP-IV-16-memory-buffer-overflow.md) · 포맷 스트링 삽입

## 설계항목 / 설명

해당 프로세스에 허용된 범위의 메모리 버퍼에만 접근하여 읽기 또는 쓰기 기능을 하도록 검증방법 설계 및 메모리 접근요청이 허용범위를 벗어났을 때 처리방법을 설계해야 한다.

## 보안대책

- ① C/C++ 같이 메모리를 프로그래머가 관리하는 플랫폼은 메모리 버퍼의 **경계값을 넘어서 읽거나 저장하지 않도록 경계설정·검사**를 반드시 수행
- ② 개발 시 **메모리 버퍼오버플로우를 발생시킬 수 있는 취약한 API를 사용하지 않도록** 함

## 가. 취약점 개요

- **사례1 버퍼 오버플로우** — 스택/힙에 할당된 메모리에 최초 정의 크기를 초과하여 문자열을 저장하면 버퍼 오버플로우 발생
- **사례2 포맷 스트링 삽입** — 외부입력값에 포맷 문자열을 삽입해 메모리를 읽거나 쓰고, 취약 프로세스의 권한을 취득하여 임의 코드 실행

## 나. 설계 시 고려사항

1. **메모리 버퍼 경계설정·검사** — Non-executable Stack, 랜덤스택(ASLR), 스택가드(StackGuard) 등 메모리 보호 정책 적용. 구현단계에 안전한 함수사용법 설명 + 경계값 검사 시큐어코딩 규칙 정의
2. **취약한 API 사용 금지** — 버퍼오버플로우 취약 함수를 식별해 사용 금지, 안전한 함수 사용 시큐어코딩 규칙 정의

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 메모리 버퍼 경계 설정·검사
- **Q1. 메모리를 프로그래머가 관리하는 플랫폼 사용 시, 버퍼오버플로우가 발생하지 않도록 보안설계가 적용되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 리눅스 환경 시 ASLR·StackGuard 등 메모리 보호 설정 사용 설계 → **아키텍처설계서 보안요구항목**
  - `1-3` 배열→배열 복사 시 데이터 길이 검사 코딩규칙 정의 → **개발가이드**
- **Q2. 메모리 버퍼오버플로우 점검 테스트 계획이 수립되어 있는가?**
  - `2-1` 할당 메모리보다 큰 입력값(충분히 긴 문자열)으로 버퍼오버플로우 발생 점검 테스트 계획 → **단위테스트케이스**

### 요구사항 ② 취약한 API 사용 금지
- **Q1. 메모리 버퍼오버플로우 방지를 위한 안전한 API 목록이 정의되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 버퍼오버플로우 유발 API 정의 + 사용 금지 코딩규칙 개발가이드 정의 → **개발가이드**
- **Q2. 메모리 버퍼오버플로우 점검 테스트 계획이 수립되어 있는가?**
  - `2-1` 할당 메모리보다 큰 입력값(충분히 긴 문자열)으로 버퍼오버플로우 발생 점검 테스트 계획 → **단위테스트케이스**
