# DSG-SF-03 · 비밀번호 관리

> **단계** 설계 · **분류** 보안기능
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §2.3 (p.115–127)
> **연관 구현약점** 하드코드된 중요정보 · 취약한 비밀번호 허용 (IMP-SF-09)

## 설계항목 / 설명

생성규칙, 저장방법, 변경주기 등 비밀번호 관리정책별 안전한 적용방법을 설계한다.

## 보안대책

- ① 비밀번호 설정 시 KISA 『비밀번호 선택 및 이용 안내서』 보안지침 적용
- ② 네트워크 전송 시 **암호화 또는 암호화된 통신 채널** 이용
- ③ 저장 시 **솔트 적용 안전한 해시함수** 사용, 해시는 **서버에서 실행**
- ④ 재설정/변경 시 **안전하게 변경할 수 있는 규칙** 정의·적용
- ⑤ **비밀번호 관리 규칙** 정의·적용

## 가. 취약점 개요

- **사례1 취약한 비밀번호 사용** — 안전한 생성규칙 미적용 시 무차별 대입으로 누출
- **사례2 취약한 비밀번호 복구** — 복구 메커니즘이 취약하면 타인 비밀번호 획득·변경·복구
- **사례3 하드코드된 중요정보** — 코드 내 비밀번호 하드코딩 시 관리자 계정 노출, 인증실패 원인 파악 곤란

## 나. 설계 시 고려사항

1. **안전한 비밀번호 생성규칙** — 안전: 2종 이상 문자 + 8자리 이상(대소문자·특수문자·숫자 4종), 또는 10자리 이상(숫자만은 취약). 안전하지 않음: 특정 패턴(`123123`/`qwerty`/`1security`), 개인정보, 이용자 ID(`kisa1`), 사전 단어, 유명 단어, 유사 치환(`O→0`,`I→1`), 초기/예제, 한↔영 발음 변경. KISA 비밀번호 안전성 검증 S/W 고려
2. **전송 암호화** — TLS·VPN 등 적용, NIST TLS 버전별 안전 알고리즘 구성(TLS 1.2 등)
3. **솔트 해시 저장(서버 실행)** — 복호화 불가 일방향 해시 사용. [참고4] SHA-256만으로는 동일 메시지=동일 다이제스트 → 무차별 대입·인식 가능성 문제. **솔트** 추가, 모든 비밀번호 고유 솔트 + 32바이트 이상이면 추측 곤란
4. **안전한 재설정/변경** — (ㄱ) 변경: 주기적·이전 미사용·연관성 없는 비밀번호 (ㄴ) 재설정: I-pin·휴대전화·질의답변으로 권한 확인 + 등록 이메일로 재설정 링크 전송
5. **관리 규칙** — (ㄱ) 변경주기 3개월(또는 6개월) (ㄴ) 만료기간 설정(DB 변경주기 일단위 업데이트, 만료 시 변경 요청·초기화) (ㄷ) 성공 로그인 시간 관리(마지막 로그인 시간 저장·알림으로 계정도용 점검)

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 안전한 생성규칙
- **Q1. 비밀번호 설정 규칙이 안전하게 정의되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 문자구성·길이(최소 8자리)·조합·제한 문자열 규칙 적용 → **요구사항정의서·유즈케이스설계서·프로그램명세서·클래스설계서**
- **Q2. 설정 규칙 점검 테스트 계획이 있는가?**
  - `2-1` 규칙 위배 입력값·예상 결과 포함 → **단위테스트계획서**

### 요구사항 ② 전송 암호화
- **Q1. 안전한 암호 알고리즘/채널로 전송하도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 회원가입·로그인 등 전송 기능 분류 → **요구사항정의서·유즈케이스설계서·프로그램명세서·클래스설계서**
  - `1-3` 안전한 암호 알고리즘 암호화 → **유즈케이스명세서·클래스설계서**
  - `1-4` TLS·VPN 등 안전 통신채널 → **아키텍처설계서**
- **Q2. 암호화 점검 테스트 계획이 있는가?**
  - `2-1` 패킷 스니핑 등 암호화 전송 점검 → **단위테스트계획서**

### 요구사항 ③ 솔트 해시 저장(서버 실행)
- **Q1. 솔트 적용 안전한 해시함수로 암호화하도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` SHA-2 계열(224/256/384/512) 사용 → **요구사항정의서·아키텍처설계서·유즈케이스설계서·클래스설계서**
  - `1-3` 랜덤 솔트값 사용 → **유즈케이스명세서·클래스설계서·DB설계서**
  - `1-4` 솔트값을 암호키 저장 장소에 저장 → **유즈케이스명세서·클래스설계서·DB설계서**
- **Q2. 해시 암호화가 서버에서 실행되도록 설계되어 있는가?**
  - `2-1` 일방향 암호 서버 수행 프로그램 → **유즈케이스설계서·프로그램명세서·클래스설계**
- **Q3. 저장 비밀번호 안전성 점검 테스트 계획이 있는가?**
  - `3-1` 비밀번호 크랙도구 점검 → **단위테스트계획서**

### 요구사항 ④ 안전한 재설정/변경
- **Q1. 비밀번호를 안전하게 변경할 수 있도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 변경 시 기존 비밀번호 확인 → **요구사항정의서·아키텍처설계서·유즈케이스설계서·클래스설계서**
  - `1-3` 안전한 설정규칙 적용 → **유즈케이스명세서·클래스설계서·DB설계서**
- **Q2. 안전하게 재설정할 수 있도록 설계되어 있는가?**
  - `2-1` 안전한 본인인증(휴대전화·I-pin·공인인증서·신용카드) → **유즈케이스설계서·프로그램명세서·클래스설계서**
  - `2-2` 본인 인증 후 재설정 페이지 연결(이메일 전송 등) → **요구사항정의서·아키텍처설계서·유즈케이스설계서·클래스설계서**
- **Q3. 변경/재설정 점검 테스트 계획이 있는가?**
  - `3-1` 권한 있는 사용자만 변경 가능 점검 → **단위테스트계획서**
  - `3-2` 본인인증 우회·재설정 경로 직접 접근 점검 → **단위테스트계획서**

### 요구사항 ⑤ 관리 규칙
- **Q1. 비밀번호 관리 규칙이 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 만료기간·변경 주기 정책 정의 → **요구사항정의서·아키텍처설계서**
  - `1-3` 만료기간·변경주기 관리 DB·프로그램 기능(최종변경일·만료기간·변경주기) → **프로그램명세서·유즈케이스설계서·클래스설계서·DB설계서**
- **Q2. 관리 규칙 점검 테스트 계획이 있는가?**
  - `2-1` 만료기간·변경주기 정책 안전 적용 점검 → **단위테스트케이스**
