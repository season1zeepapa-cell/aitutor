# DSG-IV-07 · HTTP 프로토콜 유효성 검증

> **단계** 설계 · **분류** 입력데이터 검증 및 표현
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §1.7 (p.76–80)
> **연관 구현약점** [HTTP 응답분할 (IMP-IV-13)](./IMP-IV-13-http-response-splitting.md) · 신뢰되지 않은 URL주소로 자동접속 연결

## 설계항목 / 설명

비정상적인 HTTP 헤더, 자동연결 URL 링크 등 사용자가 원하지 않은 결과를 생성하는 HTTP 헤더·응답결과에 대한 유효성 검증방법 설계 및 유효하지 않은 값에 대한 처리방법을 설계해야 한다.

## 보안대책

- ① 외부입력값을 쿠키 및 HTTP 헤더정보로 사용하는 경우, **HTTP 응답분할 취약점을 가지지 않도록 필터링**해서 사용
- ② 외부입력값이 페이지 이동(리다이렉트/포워드)용 URL로 사용되는 경우, **시스템에서 허용된 URL목록의 선택자**로만 사용

## 가. 취약점 개요

- **사례1 HTTP 응답분할** — 요청에 삽입한 인자 값이 응답헤더에 포함되어 전달될 때, 개행문자로 첫 응답을 종료시키고 두 번째 응답에 악성 코드를 주입해 XSS 등이 가능
- **사례2 신뢰되지 않은 URL로 자동 접속연결** — 입력값을 외부 사이트 주소로 사용해 자동 연결하는 서버에서, 공격자가 피싱사이트 등 위험 URL로 접속을 유도

## 나. 설계 시 고려사항

1. **HTTP 응답분할 방지 필터링** — `\r\n`은 헤더/바디 구분자이므로 응답헤더에 삽입되는 외부입력값은 반드시 `\r\n` 제거. Cookie 설정·응답 헤더 설정·Location 삽입 등 응답헤더에 입력값이 들어가는 경우 `\r\n` 필터링 검증절차 적용
2. **허용 URL목록 선택자** — 이동 허용 URL목록을 소스코드 하드코딩 또는 설정파일(XML, properties)에 저장하여 허용된 URL로만 이동

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① HTTP 응답분할 방지 입력값 검증
- **Q1. HTTP 응답분할이 발생하지 않도록 입력값 검증을 수행하도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 응답헤더에 값을 쓰는 기능 식별 + 개행문자 필터링 설계(함수 예: setHeader·addCookie·sendRedirect / 개행문자: CR(`\r`)·LF(`\n`)) → **프로그램명세서·클래스설계서·아키텍처설계서**
  - `1-3` 개행문자 필터링 안전 적용(필터컴포넌트 공통적용 / 각 기능 사용 시 개발가이드 코딩규칙) → **아키텍처설계서·개발가이드**
- **Q2. HTTP 응답분할 취약점 점검 테스트 계획이 수립되어 있는가?**
  - `2-1` CR(`\r`)·LF(`\n`) 포함 입력값으로 응답분할 발생 점검 테스트 계획 → **단위테스트케이스**

### 요구사항 ② 허용된 URL목록 선택자 사용 (오픈 리다이렉트 방지)
- **Q1. 입력값을 페이지 이동 URL로 직접 사용 시 오픈 리다이렉트 취약점이 발생하지 않도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 이동 허용 도메인/주소 목록 정의 → **클래스설계서**
  - `1-3` 허용목록 기반 입력값 검증 방법·모듈 설계 → **클래스설계서·개발가이드**
- **Q2. 오픈 리다이렉트 취약점 점검 테스트 계획이 수립되어 있는가?**
  - `2-1` 외부입력값 조작으로 의도된 페이지 리다이렉트 점검 테스트 계획(임의의 URL주소) → **단위테스트케이스**
