# DSG-SF-02 · 인증수행 제한

> **단계** 설계 · **분류** 보안기능
> **출처** 소프트웨어 보안약점 진단가이드(2021) — 제3장 §2.2 (p.109–114)
> **연관 구현약점** 반복된 인증시도 제한 기능 부재 (IMP-SF-16)

## 설계항목 / 설명

반복된 인증 시도를 제한하고 인증 실패한 이력을 추적하도록 설계한다.

## 보안대책

- ① 로그인 기능 구현 시 **인증시도 횟수 제한** + 초과 시 **인증제한 정책** 적용
- ② 실패한 인증시도 정보를 **로깅**하여 실패 추적 가능하게 설계

## 가. 취약점 개요

로그인 시도 횟수를 검사하지 않으면 횟수와 상관없이 지속적인 로그인 시도(비밀번호 무차별 대입 공격)가 가능해 계정정보가 노출될 수 있다(반복된 인증시도 제한 기능 부재).

## 나. 설계 시 고려사항

1. **인증시도 횟수 제한 + 인증제한 정책** — 로그인 시도를 3~5번 이내로 제한, 초과 시 추가 입력값 요구 또는 계정 잠금. 사용자ID/세션ID별 추적을 위해 DB테이블에 로그인 실패 횟수·계정 잠금 여부·마지막 성공/실패 로그인 시간·로그아웃 시간 저장. 계정정보 입력 시 **CAPTCHA**(자동입력방지) 장치 마련
   - 솔루션: reCAPTCHA(서비스), BotDetect CAPTCHA Generator(솔루션)
2. **실패 로깅** — 반복된 로그인 실패 로깅 정책 설정, 허용되지 않은 로그인 시도 분석 가능하게 설계

## 다. 진단 세부사항 (요구사항별 체크리스트)

> 📋 각 진단방법은 **관련산출물 검토예시**와 짝을 이룬다 — 이것이 복합서술형(진단보고서) 채점 기준이 된다.

### 요구사항 ① 인증시도 횟수 제한 + 인증제한 정책
- **Q1. 로그인 기능 설계 시 인증시도 횟수가 제한되도록 설계되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 로그인 시도 횟수(5회 이내) 제한 정책 반영 → **유즈케이스명세서·클래스설계서**
  - `1-3` 영속성 저장장치(DB/파일)에 인증시도 정보 저장 → **유즈케이스명세서·클래스설계서·DB설계서**
- **Q2. 초과 인증시도에 대한 인증제한 정책이 적용되도록 설계되어 있는가?**
  - `2-1` 제한 횟수 초과 시 계정 잠금·추가정보 요구 → **유즈케이스명세서·클래스설계서**
- **Q3. 인증시도 횟수 제한 점검 테스트 계획이 있는가?**
  - `3-1` 제한 초과 로그인 시도 제한 점검(실패 입력값·제한 정책 적용·영속성 기록 확인) → **단위테스트케이스**

### 요구사항 ② 실패 로깅
- **Q1. 초과된 인증시도에 대한 로깅 정책이 적용되어 있는가?**
  - `1-1` 요구사항정의서·아키텍처설계서·요구사항추적표
  - `1-2` 사용자ID·실패횟수·시도시간·IP주소·계정 상태정보 로깅 포함 → **유즈케이스명세서·클래스설계서**
- **Q2. 초과 인증시도 로깅 점검 테스트 계획이 있는가?**
  - `2-1` 초과된 인증시도 테스트 계획 → **단위테스트케이스**
  - `2-2` 초과 인증시도 로깅 정상 수행 점검 → **단위테스트케이스**
