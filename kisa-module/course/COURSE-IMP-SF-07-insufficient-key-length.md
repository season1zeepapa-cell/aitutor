# 충분하지 않은 키 길이 사용 (IMP-SF-07)

> 2025년 SW보안약점 진단원 기본(양성)과정 — Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려 2-7 (pp.400-402)

## 요약

데이터의 기밀성·무결성을 보장하기 위해 암호화에 사용되는 키의 길이가 충분하지 않은 경우 발생하는 보안약점이다. 검증된 알고리즘을 쓰더라도 키 길이가 짧으면 짧은 시간 안에 키를 찾아낼 수 있어 데이터·패스워드가 복호화될 수 있다. 공개키(RSA)는 2048bit 이상, 대칭키(AES·ARIA·SEED)는 128bit 이상을 사용해야 한다.

## 정의 — 약점이 발생하는 경우

- 데이터의 기밀성, 무결성을 보장하기 위해 암호화에 사용되는 키의 길이가 충분하지 않은 경우

## 위협

- 길이가 짧은 키는 암호화 알고리즘을 취약하게 만들 수 있음
- 검증된 알고리즘이라도 키 길이가 짧으면 짧은 시간 안에 키를 찾아 데이터·패스워드를 복호화 가능

## 대책 — 안전한 키 길이 기준

- 공개키(RSA): 2048bit 이상
- 대칭키(AES, ARIA, SEED): 128bit 이상

## 진단 흐름 — 암호화 키 길이 비교

- 대칭키(AES/ARIA/SEED) 128bit 이상이면 안전, 미달이면 위험
- 공개키(RSA) 2,048bit 이상이면 안전

## 코드 예시 — RSA 키 생성

- 안전하지 않은 코드: `keyGen.initialize(1024);` (1024bit, 위험)
- 안전한 코드: `keyGen.initialize(2048);` (2048bit)

## 시험 포인트

- 약점: 암호화 키 길이가 충분하지 않은 경우
- 공개키 RSA 2048bit 이상 / 대칭키 AES·ARIA·SEED 128bit 이상
- 위협: 짧은 키는 짧은 시간 안에 탐색되어 복호화 가능
- 코드: `initialize(1024)` 위험 → `initialize(2048)` 안전
