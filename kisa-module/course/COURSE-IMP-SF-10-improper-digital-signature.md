# 부적절한 전자서명 확인 (IMP-SF-10)

> 2025년 SW보안약점 진단원 기본(양성)과정 — Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려 2-10 (pp.410-414)

## 요약

전자서명을 검증하지 않거나 검증절차가 부적절하면 위변조된 파일을 통해 악성코드에 감염될 수 있다. 전자서명을 포함하는 파일을 사용할 때는 항상 전자서명을 확인하고, 전자서명 파일의 출처를 확인하여 신뢰할 수 없는 곳에서 생성된 파일을 사용하지 않도록 해야 한다.

## 정의 — 약점이 발생하는 경우

- 전자서명을 검증하지 않거나, 검증절차가 부적절한 경우

## 위협

- 위변조된 파일을 통해 악성코드에 감염될 수 있음

## 대책

- 전자서명을 포함하는 파일을 사용할 때는 항상 전자서명을 확인
- 전자서명 파일의 출처를 확인하여 신뢰할 수 없는 곳에서 생성된 파일은 사용하지 않음

## 진단 흐름

1. 전자서명 포함 파일 사용 시 전자서명의 출처 확인 → 미확인이면 위험
2. 전자서명값 확인 → 미확인이면 위험, 확인이면 안전

## 코드 예시

### JarFile 서명 검증

- 안전하지 않은 코드: `JarFile jf = new JarFile(f);` (검증 인자 없음)
- 안전한 코드: `JarFile jf = new JarFile(f, true);` + 엔트리 순회 후 `en.getCodeSigners()`로 서명자 확인

### 파일 업로드 시 서명 검증

- 안전하지 않은 코드: `new JarFile(f, true)`로 열지만 전자서명 주체 검증 코드 없음
- 안전한 코드: `CodeSigner[] signers = en.getCodeSigners();` 후 `signers != null && signers.length != 0` 조건으로 서명 주체 검증

## 시험 포인트

- 약점: 전자서명 미검증 또는 검증절차 부적절
- 위협: 위변조 파일을 통한 악성코드 감염
- 대책: 항상 서명 확인 + 출처 확인
- 진단: 출처 확인 → 전자서명값 확인 모두 통과해야 안전
- 코드: `new JarFile(f)` 위험 → `new JarFile(f, true)` + `getCodeSigners()` 검증, 조건 `signers != null && signers.length != 0`
