# 취약한 비밀번호 허용 (IMP-SF-09)

> 2025년 SW보안약점 진단원 기본(양성)과정 — Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려 2-9 (pp.406-409)

## 요약

비밀번호 조합규칙(영문·숫자·특수문자 등)이 미흡하거나 길이가 충분하지 않으면 무작위 대입·추측 공격으로 계정 정보가 노출될 수 있다. 비밀번호 설정 시 문자 구성 및 길이 조건(2종 이상 문자 8자리 이상 또는 숫자만 제외 10자리 이상)을 설정하고, 사전 단어·ID 연관 단어·패턴 등의 제약을 적용하며, 변경 시에도 동일 규칙을 적용해야 한다.

## 정의 — 약점이 발생하는 경우

- 비밀번호 조합규칙(영문, 숫자, 특수문자 등)이 미흡하거나 길이가 충분하지 않은 경우

## 위협

- 패스워드 무작위 대입으로 계정 정보 노출
- 패스워드 추측 공격으로 계정 정보 노출

## 대책 — 비밀번호 설정 조건

- 문자 구성·길이: 2가지 종류 이상 문자 구성 8자리 이상, 또는 10자리 이상(숫자로만 구성 제외)
- 패턴/특정정보 제약: 사전적 단어, 널리 알려진 단어, 사용자 ID 연관 단어, 제3자가 쉽게 알 수 있는 개인정보, 패턴 비밀번호, 숫자·영문자 치환형 포함 금지
- 기타: 시스템 초기 설정 패스워드 금지, 발음 변형형 금지(예: '사랑'→'SaRang')
- 참조: KISA '패스워드 선택 및 이용 안내서'

## 진단 흐름

1. 패스워드 조합 규칙 존재 여부 → 없음이면 위험
2. 자릿수·특수문자 등 조합 확인 → 없음이면 위험
3. 변경 시 동일 규칙 적용 → 미적용 위험, 적용이면 안전

## 코드 예시 — 복잡도 검증

- 안전하지 않은 코드: 복잡도 체크 없이 등록
- 안전한 코드:
  - `Pattern.compile("((?=.*[a-zA-Z])(?=.*[0-9]).{10,})")`로 검증
  - 매칭 실패 시 "비밀번호 조합규칙 오류" 반환

## 정규표현식 해설

- `(?=.*[a-zA-Z])`: 영문자(대소문자 무관) 1개 이상 포함
- `(?=...)`: 전방 탐색(lookahead), 문자열을 소비하지 않고 조건 확인
- `(?=.*[0-9])`: 숫자 1개 이상 포함
- `{10,}`: 최소 10자 이상
- 종합: 영문+숫자 포함, 최소 10자 이상. 변형 `(?=.*[0-9@#$%]).{9,}`는 9자 이상 + 숫자/특수문자(@,#,$,%) 포함

## 시험 포인트

- 약점: 조합규칙 미흡 또는 길이 부족
- 위협: 무작위 대입·추측 공격으로 계정 노출
- 길이/구성: 2종 이상 8자리 이상 또는 숫자 제외 10자리 이상
- 변경 시에도 동일 규칙 적용
- 정규식: `(?=.*[a-zA-Z])(?=.*[0-9]).{10,}` = 영문+숫자 포함 10자 이상
