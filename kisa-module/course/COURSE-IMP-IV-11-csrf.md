# 크로스사이트 요청위조 (CSRF)

- **unit_code**: COURSE-IMP-IV-11
- **단원**: Ⅴ. 구현 단계 보안약점 진단 > 입력데이터 검증 및 표현
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정 (pp. 344-345)
- **관련 보안약점**: 입력 데이터 검증 및 표현 > 크로스사이트 요청위조(CSRF)

## 요약

웹 서버로 전달된 요청이 공격자가 심어 놓은 자동화된 코드를 통한 요청인지, 실제 페이지에서 사용자가 일으킨 정상적인 요청인지를 확인하지 않고 처리하는 경우 발생한다. 어떤 형태의 요청이든지 기본적으로 CSRF 취약점을 가질 수 있다.

## 공격 영향

- 미리 작성해 둔 공격코드를 이용하여 희생자의 권한으로 요청이 처리되도록 한다.
- 게시판 자동 글쓰기, 자동 회원 가입, 다른 사용자의 권한을 도용한 중요 기능 실행 등의 공격이 수행될 수 있다.

## 보안대책

1. 입력화면 폼 작성 시 GET 방식 대신 **POST 방식**을 사용한다.
2. 입력화면 폼과 처리 프로그램 사이에 **CSRF 토큰**을 사용하여, 공격자가 직접적인 URL 조작으로 기능을 사용할 수 없도록 한다.
3. 중요 기능에 대해서는 **추가적인 인증이나 다중매체 인증방식**을 적용한다.

## 진단 흐름도

- 사용자 권한변경·신규 등록 등 주요 기능에 권한 확인 절차가 없으면 → **위험**
- 권한 확인이 쿠키·IP·SSL 인증에만 의존하면 → **위험**
- 쿠키·IP·SSL 인증에 의존하지 않으면 → **안전**

## 안전한 코드 (CSRF 토큰)

```java
// 입력화면이 요청되었을 때, 임의의 토큰을 생성한 후 세션에 저장한다.
session.setAttribute("SESSION_CSRF_TOKEN", UUID.randomUUID().toString());

// 입력화면에 임의의 토큰을 HIDDEN 필드항목의 값으로 설정해 서버로 전달되도록 한다.
// <input type="hidden" name="param_csrf_token" value="${SESSION_CSRF_TOKEN}" />

// 요청 파라미터와 세션에 저장된 토큰을 비교해서 일치하는 경우에만 요청을 처리한다.
String pToken = request.getParameter("param_csrf_token");
String sToken = (String) session.getAttribute("SESSION_CSRF_TOKEN");
if (pToken != null && pToken.equals(sToken)) {
    // 일치하는 토큰이 존재하는 경우 → 정상 처리
} else {
    // 토큰이 없거나 값이 일치하지 않는 경우 → 오류 메시지 출력
}
```

## 시험 포인트

- CSRF는 요청이 사용자의 정상 요청인지 확인하지 않고 처리할 때 발생 — 희생자 권한으로 요청 처리
- 보안대책: GET 대신 POST / CSRF 토큰 / 중요 기능은 추가·다중매체 인증
- CSRF 토큰은 세션에 저장 후 HIDDEN 필드로 전달, 요청 토큰과 세션 토큰이 일치할 때만 처리
- 권한 확인이 쿠키·IP·SSL 인증에만 의존하면 위험
