## 요약

메모리·파일·DB 연결과 같은 자원은 사용 후 반드시 해제해야 하는데, 부적절한 흐름처리나 코드누락으로 자원해제가 실행되지 않는 경우 발생하는 보안약점이다. 해제하지 않은 자원(Heap Memory, Socket, DB Connection 등)이 고갈되어 더 이상 할당할 수 없게 되거나, 해제 코드가 잘못된 루틴에 있어 시스템 오류가 발생할 수 있다. 자바의 경우 반환 코드는 finally 블록에 기술하여 반드시 실행되도록 한다.

## 개요 — 정의·영향·대책

- **정의**: 메모리, 파일, DB 연결과 같은 자원들은 사용 후 반드시 해제해야 하는데, 부적절한 흐름처리나 코드누락으로 인해 자원해제가 실행되지 않는 경우 발생한다.
- **영향**: 해제하지 않은 자원(Heap Memory, Socket, DB Connection 등)이 고갈되어 더 이상 할당할 수 없는 상태가 되거나, 자원 해제 코드가 잘못된 루틴에 있어 시스템에 오류가 발생할 수 있다.
- **대책**: 유한한 자원은 반드시 반환되도록 제어문이나 예외처리가 되도록 작성한다. 자바의 경우 반환 코드는 finally 블록에 기술하여 반드시 실행되도록 한다.
- **진단 흐름**: 자원 사용 기능 확인 → 사용 후 해제 기능 확인(없으면 위험) → 제어문·예외처리 등 분기에 따른 모든 흐름 처리 확인, 처리되면 안전 / 미처리면 위험

## 코드 예제 ① — PrintWriter를 finally에서 해제

- **안전하지 않은 코드**: `writeList()`에서 try 블록 안의 마지막에 `if (out != null) { out.close(); }`로 close를 호출한다.
- `out.close()` 실행 전에 오류(IndexOutOfBoundsException 등)가 발생하면 자원이 반환되지 않으며, 할당된 모든 자원을 반환해야 한다.
- **안전한 코드**: try-catch 이후 항상 수행되는 finally 블록에서 `if (out != null) { out.close(); }`로 null 검사를 수행한 뒤 자원을 해제한다.

## 코드 예제 ② — JDBC ResultSet/Statement/Connection 해제

- **안전하지 않은 코드 A**: try 블록 안에서 `rs.close()`, `pstmt.close()`, `conn.close()`를 호출하면 중간에 예외 발생 시 해제가 누락된다.
- **안전하지 않은 코드 B**: 자원 해제 코드를 catch 블록에 두면 예외가 없을 때 자원이 해제되지 않는다.
- **안전한 코드**: finally 블록에서 rs, stmt, conn 각각에 대해 null 검사 후 개별 try-catch로 `close()`를 호출하여, 모든 흐름에서 자원이 반드시 해제되도록 한다.

## 핵심 개념

| 용어 | 정의 |
| --- | --- |
| 부적절한 자원 해제 | 메모리·파일·DB 연결 등 유한한 자원을 부적절한 흐름처리나 코드누락으로 해제하지 못하는 보안약점. 자원 고갈이나 시스템 오류를 유발한다 |
| finally 블록 해제 | 자바에서 예외 발생 여부와 무관하게 항상 실행되는 finally 블록에 자원 반환 코드를 기술하여 자원이 반드시 해제되도록 하는 방법 |
| 분기별 모든 흐름 처리 | 제어문·예외처리 등 모든 분기에서 할당된 자원이 빠짐없이 반환되도록 작성하는 원칙. 각 자원에 null 검사 후 해제한다 |

## 시험 포인트

- 부적절한 자원 해제는 흐름처리·코드누락으로 메모리·파일·DB 연결 등의 자원이 해제되지 않을 때 발생한다.
- 영향: 해제하지 않은 자원(Heap Memory, Socket, DB Connection)이 고갈되거나 해제 코드가 잘못된 루틴에 있어 시스템 오류가 발생한다.
- 대책: 유한한 자원은 제어문·예외처리로 반드시 반환되도록 하고, 자바는 finally 블록에 반환 코드를 기술한다.
- 안전한 코드: try 블록이나 catch 블록이 아닌 finally 블록에서 각 자원을 null 검사 후 해제한다.
