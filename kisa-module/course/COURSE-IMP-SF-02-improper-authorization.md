# 부적절한 인가 (COURSE-IMP-SF-02)

- 단계: Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려
- 항목: 2-2 부적절한 인가
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정 (pp.378-379)
- 관련 라이브러리 항목: IMP-SF-02

## 요약
인가된 특정 사용자만 사용 가능한 페이지에 대해 올바른 접근권한이 체크되지 않는 경우 발생하는 보안약점이다. 권한 없는 사용자에 의해 기능이 사용되거나 데이터가 유출될 수 있다.

## 정의와 영향
- 정의: 인가된 특정 사용자만 사용 가능한 페이지에 대해 올바른 접근권한이 체크되지 않는 경우 발생한다.
- 영향: 권한 없는 사용자에 의해 기능이 사용되거나 데이터가 유출될 수 있다.

## 보안대책
- URL 조작을 통해 리소스에 직접 접근할 수 없도록 차단한다.
- 파라미터 조작을 통해 직접 접근을 차단한다.
- ACL(Access Control List)을 이용하여 권한에 따라 적절한 기능을 사용할 수 있도록 설정한다.

## 진단 흐름
- 중요정보 저장·외부시스템 존재 여부를 확인한다.
- 접근/변경 권한이 사전 정의되어 있는지 확인한다 — 정의되어 있지 않으면 위험.
- 함수 호출 시 권한 소유 여부를 검사하면 안전, 검사하지 않으면 위험으로 판정한다.

## 안전하지 않은 코드 vs 안전한 코드 (삭제 작업)
- 안전하지 않은 코드: `request.getParameter("action")`이 `"delete"`이면 요청 사용자의 권한 확인 없이 삭제 작업을 수행한다.
- 안전한 코드: 세션에서 `User user`를 얻은 뒤(`session.getAttribute("user")`), `checkAccessControlList(user, action)`으로 해당 사용자의 delete 권한을 확인한 후에만 삭제를 수행한다.
- 핵심: 기능 실행 전 ACL 등으로 사용자의 권한 소유 여부를 검사해야 한다.

## 시험 포인트
- 약점 정의: 인가된 특정 사용자만 쓸 수 있는 페이지에 올바른 접근권한 체크가 없는 경우
- 영향: 권한 없는 사용자에 의한 기능 사용 또는 데이터 유출
- 보안대책 3가지: URL 조작 직접접근 차단, 파라미터 조작 직접접근 차단, ACL로 권한별 기능 사용 설정
- 안전한 코드 핵심: 세션 사용자 정보로 `checkAccessControlList(user, action)` 권한 검사 후 작업 수행
