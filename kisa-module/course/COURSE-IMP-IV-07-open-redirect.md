# 신뢰되지 않는 URL 주소로 자동접속 연결 (COURSE-IMP-IV-07)

> 2025년 SW보안약점 진단원 기본(양성)과정 · Ⅴ. 구현 단계 보안약점 진단 · 입력데이터 검증 및 표현 · 1-7 (pp.325-327)

## 요약
사용자로부터 입력받은 값을 검증하지 않고 외부 사이트로 자동 연결(redirect)할 주소로 사용하면 발생한다. 공격자는 외부입력값을 조작하여 사용자를 피싱(phishing)·XSS 공격에 노출시킬 수 있다. 자동 연결 URL·도메인을 화이트리스트로 관리하는 것이 대책이다.

## 개요 — 정의와 위협
- 정의: 사용자로부터 입력받은 값을 검증하지 않고 외부 사이트로 자동 연결(redirect)할 사이트의 주소로 사용하는 경우 발생한다.
- 위협: 공격자는 외부입력값을 조작하여 사용자를 피싱(phishing), 크로스사이트 스크립트(XSS)와 같은 공격에 노출시킬 수 있다.

## 보안대책
- 자동 연결에 사용할 외부 사이트의 URL과 도메인을 화이트 리스트(white list)로 관리한다.
- 사용자 입력값을 자동 연결할 사이트의 주소로 사용하는 경우 화이트 리스트 내의 값인지 확인하고 사용한다.
- 진단 흐름: 자동 연결 기능 존재 → 외부입력값 URL 사용 여부 → 사용 시 URL이 화이트리스트(White List) 방식으로 관리되면 안전, 아니면 위험.

## 안전하지 않은 코드 — 입력 redirect 무검증
- `request.getParameter("redirect")`로 받은 URL을 검증 없이 변수 rd에 저장한다.
- 외부로부터 입력받은 URL이 검증없이 다른 사이트로 이동이 가능하여 안전하지 않다.
- 권한·구분값(bn) 조건을 만족하면 `response.sendRedirect(rd)`로 입력값 그대로 리다이렉트하여 피싱 사이트 등 임의 주소로 이동할 수 있다.

## 안전한 코드 — 허용 URL 배열 인덱싱
- 이동 할 수 있는 URL범위를 제한하여 피싱 사이트 등으로 이동하지 못하도록 한다.
- 허용 URL을 배열(`allowedUrl = { "/main.do", "/login.jsp", "list.do" }`)로 정의한다.
- 입력값 rd를 정수로 파싱하여 배열 인덱스로만 사용(`allowedUrl[Integer.parseInt(rd)]`)하므로, 임의의 외부 URL 문자열을 직접 리다이렉트 대상으로 쓸 수 없다.
- `NumberFormatException`(잘못된 접근입니다.)·`ArrayIndexOutOfBoundsException`(잘못된 입력입니다.) 예외 처리로 비정상 입력을 차단한다.

## 핵심 개념
- **오픈 리다이렉트(Open Redirect)**: 검증되지 않은 외부입력값을 리다이렉트 대상 URL로 사용해 공격자가 사용자를 임의 사이트로 자동 이동시키는 보안약점.
- **URL 화이트리스트**: 자동 연결 URL·도메인을 허용 목록으로 관리하고 입력값이 목록 내 값일 때만 리다이렉트하는 대책.
- **허용 URL 배열 인덱싱**: 외부입력값을 URL 문자열이 아닌 허용 URL 배열의 정수 인덱스로만 사용하여 임의 이동을 차단하는 기법.

## 시험 포인트
- 정의: 검증하지 않은 외부입력값을 redirect 대상 URL로 사용 → 피싱·XSS 공격 노출.
- 대책: 자동 연결 URL·도메인을 화이트리스트로 관리하고 목록 내 값인지 확인 후 사용.
- 안전한 코드는 입력값을 허용 URL 배열의 인덱스로만 사용(`Integer.parseInt` 후 `allowedUrl[index]`)하고 예외 처리로 비정상 입력 차단.
- `response.sendRedirect()`에 외부입력값을 직접 전달하면 취약.
