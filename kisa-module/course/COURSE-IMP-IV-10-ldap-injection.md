# LDAP 삽입 (COURSE-IMP-IV-10)

> 2025년 SW보안약점 진단원 기본(양성)과정 · Ⅴ. 구현 단계 보안약점 진단 · 입력데이터 검증 및 표현 · 1-10 (pp.341-343)

## 요약
응용 프로그램이 사용자의 입력을 검증하지 않고 LDAP 필터문 생성에 사용하면 발생한다. 공격자가 LDAP 필터문을 조작하여 정보를 유출하거나 조작할 수 있다. DN(Distinguished Name)과 필터에 사용되는 입력값에 LDAP 특수문자가 포함되지 않도록 검증하거나, 특수문자를 실행명령이 아닌 일반문자로 인식되도록 처리하는 것이 대책이다.

## 개요 — 정의와 위협
- 정의: 응용 프로그램이 사용자의 입력을 검증하지 않고 LDAP 필터문 생성에 사용되는 경우 발생한다.
- 위협: 공격자가 LDAP 필터문을 조작하여 정보를 유출하거나 조작할 수 있다.

## 보안대책
- DN(Distinguished Name)과 필터에 사용되는 사용자 입력값에는 LDAP 필터에 사용되는 특수문자( `( ) ; , * ! & | =` )가 포함되지 않도록 한다.
- 특수문자를 사용해야 하는 경우에는 특수문자가 실행명령이 아닌 일반문자로 인식되도록 처리한다.
- 진단 흐름: LDAP 조회 쿼리 사용 → 외부입력값을 LDAP 조회에 사용 여부 → 미사용 시 안전, 사용 시 입력값 필터링 모듈·관련 프레임워크 사용되면 안전, 아니면 위험.

## 안전하지 않은 코드 — 입력값 무검증 필터 생성
- InitialDirContext로 LDAP 컨텍스트를 만들고 base=`dc=example,dc=com`에서 검색한다.
- userSN과 userPassword 값을 검증 없이 필터 문자열에 연결한다. `filter = "(&(sn=" + userSN + ")(userPassword=" + userPassword + "))"`
- userSN·userPassword 값에 LDAP 필터를 조작할 수 있는 공격 문자열에 대한 검증이 없어 안전하지 않다.

## 안전한 코드 — 정규식 화이트리스트 검증
- userSN·userPassword 값에서 LDAP 필터를 조작할 수 있는 문자열을 제거하고 사용한다.
- 정규식으로 허용 문자만 검증한다: userSN은 `[\w\s]*`, userPassword는 `[\w]*` 패턴에 일치하지 않으면 `IllegalArgumentException("Invalid input")`을 던진다.
- 검증 통과 후에만 필터 문자열을 생성하여 `dctx.search(base, filter, sc)`를 수행하므로 안전하다.

## 핵심 개념
- **LDAP 삽입(LDAP Injection)**: 검증되지 않은 사용자 입력을 LDAP 필터문 생성에 사용해 공격자가 필터문을 조작, 정보 유출·조작을 일으키는 보안약점.
- **DN(Distinguished Name)**: LDAP 디렉터리에서 항목을 유일하게 식별하는 이름. 필터와 함께 입력값에 특수문자가 포함되지 않도록 검증해야 한다.
- **LDAP 특수문자 필터링**: `( ) ; , * ! & | =` 등 LDAP 필터에 의미를 갖는 특수문자를 입력값에서 제거하거나, 정규식 화이트리스트(`[\w\s]*` 등)로 허용 문자만 통과시키는 대책.

## 시험 포인트
- LDAP 삽입은 입력을 검증하지 않고 LDAP 필터문 생성에 사용할 때 발생 → 필터문 조작으로 정보 유출·조작.
- DN과 필터 입력값에 LDAP 특수문자 `( ) ; , * ! & | =`가 포함되지 않도록 한다.
- 특수문자가 필요하면 실행명령이 아닌 일반문자로 인식되도록 처리(이스케이프)한다.
- 안전한 코드는 정규식 화이트리스트(userSN=`[\w\s]*`, userPassword=`[\w]*`) 검증 후 불일치 시 예외 처리.
- 진단: 외부입력값을 LDAP 조회에 사용 시 입력값 필터링 모듈·관련 프레임워크 사용 여부로 안전/위험 판단.
