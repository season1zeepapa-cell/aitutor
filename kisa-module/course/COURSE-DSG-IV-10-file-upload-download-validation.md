# 업로드·다운로드 파일 검증 (COURSE-DSG-IV-10)

> Ⅳ. 분석·설계 단계 보안약점 진단 · 2025년 SW보안약점 진단원 기본(양성)과정 · pp.159-169
> 관련 라이브러리: DSG-IV-10 · 분류: 입력데이터 검증 및 표현

## 개요

업로드·다운로드 파일의 **무결성, 실행권한** 등에 관한 유효성 검사 방법을 설계하고, **검사 실패 시 대응방안**을 설계해야 한다.

- 업로드되어 저장되는 파일의 **타입, 크기, 개수, 실행권한**을 제한
- 업로드되어 저장되는 파일은 **외부에서 식별되지 않아야 함**
- 파일 다운로드 요청 시 **요청 파일명에 대한 검증**작업 수행
- 다운로드 받은 소스코드·실행파일은 **무결성 검사** 실행
- 관련 보안약점: 입력데이터 검증 및 표현 > **위험한 형식 파일 업로드** / 보안기능 > **부적절한 전자서명 확인, 무결성 검사 없는 코드 다운로드**

## 설계 시 고려사항

**업로드되어 저장되는 파일의 타입·크기·개수·실행권한을 제한한다.**

- 업로드 파일의 크기 제한 — Spring framework는 `MultipartResolver` 컴포넌트의 속성값(`maxUploadSize`, `maxInMemorySize`)을 설정하여 제한한다.
- 파일의 타입 제한
- 업로드되어 저장되는 파일은 실행권한 제거

**업로드되어 저장되는 파일은 외부에서 식별되지 않아야 한다.**

- 저장경로는 외부에서 직접 접근이 불가능한 경로를 사용한다.
- 저장 파일명은 랜덤하게 생성하여 사용한다.

**파일 다운로드 요청 시 요청파일명에 대한 검증작업을 수행한다.**

- 요청 파일명에 경로를 조작하는 문자가 포함되어 있는지 점검한다.
- 허가된 사용자의 허가된 안전한 파일에 대한 다운로드 요청인지 확인한다.
- 서버에 존재하는 파일이 참조되는 경우 **화이트리스트 정책**으로 접근통제한다.

**다운로드 받은 소스코드·실행파일은 무결성 검사를 실행한다.**

## 진단 기준 및 방법

### 요구사항 01 — 업로드 파일 타입·크기·개수·실행권한 제한

**진단항목 01. 업로드 파일의 제한 정책·방법이 설계되어 있는가?**

| 진단방법 | 관련 산출물 |
|---|---|
| 1-1 요구사항정의서 대책 + 아키텍처설계서 적용계획 + 요구사항추적표 추적 가능 여부 | 요구사항정의서, 요구사항추적표, 아키텍처설계서 |
| 1-2 업로드 가능 타입·크기·개수와 저장 시 퍼미션 정의 (프레임워크/라이브러리 속성 제한 또는 프로그램 설계) | 아키텍처설계서, 유즈케이스설계서, 클래스설계서 |

**진단항목 02. 업로드 파일 제한 정책을 점검하는 테스트 계획이 수립되어 있는가?**

| 진단방법 | 관련 산출물 |
|---|---|
| 2-1 허용되지 않는 타입·크기·개수 업로드 제한 점검 | 단위테스트케이스 |
| 2-2 저장된 파일의 실행 제한 점검 | 단위테스트케이스 |

**진단항목 01. 외부에서 식별되지 않는 안전한 저장위치에 저장되도록 설계되어 있는가?**

## 시험 포인트

- 관련 보안약점: **위험한 형식 파일 업로드 / 부적절한 전자서명 확인, 무결성 검사 없는 코드 다운로드**
- 업로드 파일은 **타입·크기·개수·실행권한** 제한 (Spring `MultipartResolver`의 `maxUploadSize`·`maxInMemorySize`)
- 업로드 파일은 **외부 직접 접근 불가 경로 + 랜덤 파일명**, 원본↔저장 파일명 매핑 관리
- 다운로드 요청 파일명의 **경로조작 문자(../ ..\) 필터링**, **화이트리스트** 접근통제
- 다운로드 소스코드·실행파일은 **해시 등 무결성 검사** 후 사용
- 테스트: 식별 가능성, 조작 파일명 차단, 변조 파일 다운로드 차단 점검
