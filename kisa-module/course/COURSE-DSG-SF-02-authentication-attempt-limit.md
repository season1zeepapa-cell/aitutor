# 인증수행 제한 (COURSE-DSG-SF-02)

- 단원: Ⅳ. 분석·설계 단계 보안약점 진단 — 보안기능
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정, pp.179-184
- 관련 라이브러리: DSG-SF-02
- 관련 보안약점: (보안기능) 반복된 인증시도 제한기능 부재

## 개요
인증 반복시도 제한 및 인증실패 등에 대한 인증제한 기능을 설계해야 한다.

- 로그인 기능 구현 시, 인증시도 횟수를 제한하고, 초과된 인증시도에 대해 인증제한 정책을 적용해야 한다.
- 실패한 인증시도에 대한 정보를 로깅하여 인증시도 실패가 추적될 수 있게 해야 한다.

## 설계 시 고려사항

### 1. 인증시도 횟수 제한 및 인증제한 정책
- 로그인 시도횟수를 3~5번 이내로 제한하고, 초과하여 실패하면 추가 입력값을 요구하거나 계정 잠금을 수행한다.
- 사용자ID별·세션ID별 로그인 횟수 추적을 위해 사용자 DB테이블에 다음을 저장하도록 설계한다.
  - 로그인 실패 횟수
  - 계정 잠금 여부
  - 마지막으로 성공·실패한 로그인 시간 정보
  - 로그아웃한 시간 정보
- 일정 횟수 이상 연속 로그인 실패 시 사용자 ID·패스워드 외의 추가 확인 정보를 저장한다.
- 계정정보 입력 시 자동입력방지 문자(CAPTCHA)와 같은 장치를 마련한다.

### 2. 실패한 인증시도 로깅
- 반복된 로그인 실패에 대한 로깅 정책을 설정하고, 로그 기록을 통해 허용되지 않은 로그인 시도를 분석할 수 있도록 설계한다.

## 진단 기준 및 방법

### 요구사항 01 — 인증시도 횟수 제한 및 인증제한 정책 적용
- 01 로그인 시도 횟수(5회 이내) 제한 정책 설계, 인증 실패 횟수 정보를 영속성 있는 저장장치(DB·파일)에 저장하도록 설계 (유즈케이스명세서, 클래스설계서, DB설계서)
- 02 초과 시 계정잠금·추가정보 요구 등 인증제한 정책 설계
- 03 제한 횟수 초과 로그인 시도가 제한되는지 점검 테스트 계획 (단위테스트케이스)
  - 로그인 실패 입력값 사용 / 실패 시 제한 정책 적용 / 영속성 저장장치 기록 확인

### 요구사항 02 — 실패한 인증시도 로깅
- 01 초과된 인증시도 로깅 정책 적용 — 로깅 정보에 사용자ID, 로그인 실패횟수, 로그인 시도 시간, IP주소, 계정 상태정보 포함 (유즈케이스명세서, 클래스설계서)
- 02 초과 인증시도 시 로깅 정상 수행 점검 테스트 계획 (단위테스트케이스)

> 모든 요구사항의 1-1 진단방법은 공통: 요구사항정의서 대책 수립 + 아키텍처설계서 적용계획 + 요구사항추적표 추적 가능 여부 확인.

## 시험 포인트
- 로그인 시도횟수는 3~5회 이내로 제한(진단기준은 5회 이내).
- 초과 시 인증제한 정책: 계정 잠금 또는 추가정보 요구, 자동입력방지 문자(CAPTCHA).
- 인증 실패 횟수 정보는 영속성 있는 저장장치(DB·파일)에 저장.
- 인증실패 로깅 항목: 사용자ID·실패횟수·시도시간·IP주소·계정 상태정보.
- 관련 보안약점: 반복된 인증시도 제한기능 부재.
