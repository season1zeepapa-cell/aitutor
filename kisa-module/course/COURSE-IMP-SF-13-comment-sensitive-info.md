# 주석문 안에 포함된 시스템 주요 정보 (IMP-SF-13)

- **unit_code**: COURSE-IMP-SF-13
- **단계**: Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정, p.422-423

## 요약

소프트웨어 개발자가 편의를 위해 주석문 안에 남겨둔 시스템 주요정보를 제거하지 않은 경우, 소스코드에 포함된 중요정보(ID, 패스워드, 시스템 정보, 실행환경 등)는 역컴파일(decompile)을 통해 쉽게 유출될 수 있고, 이를 활용한 공격이 가능하다. 주석문에는 ID·패스워드 등 보안 관련 내용을 기입하지 않고, 개발 중 남긴 정보는 개발 완료 시 확실하게 삭제한다.

## 개요 — 약점과 대책

- 약점: 소프트웨어 개발자가 편의를 위해 주석문 안에 남겨둔 시스템 주요정보를 제거하지 않은 경우.
- 영향: 소스코드에 포함된 중요정보(ID, 패스워드, 시스템 정보, 실행환경 등)는 역컴파일(decompile)을 통해 쉽게 유출될 수 있으며, 이를 활용해 공격자가 시스템을 공격할 수 있다.
- 대책 ①: 주석문에는 ID, 패스워드 등 보안과 관련된 내용을 기입하지 않는다.
- 대책 ②: 프로그램 개발 시 주석문으로 남겨둔 사용자 계정이나 패스워드 등의 정보는 개발이 완료되면 확실하게 삭제한다.

## 진단 흐름 (점검 순서)

- DB 접속, 관리자 기능 등이 구현된 코드를 확인한다.
- 주석문을 검토하여 민감 정보 포함 여부를 확인한다.
- 민감 정보 포함이 없으면 안전, 있으면 위험.

## 안전하지 않은 코드 (예시)

- daoTest() 주석에 'dbsample : 84d5d0a08a3ec5e2d91a' 등 DB 연결 정보를 노출한다.
- '암호화 전, 후 : 1365ADMIN_01, aa84c40031d808196537ad3dcf81f9af'처럼 계정 ID와 암호화 전후 패스워드를 주석으로 남겨 안전하지 않다.
- 주석으로 DB연결 ID, 패스워드의 중요한 정보를 노출시키는 것이 핵심 결함이다.

## 안전한 코드 (예시)

- ID·패스워드·암호화 전후 값을 노출하던 주석문을 모두 제거한다.
- 동작 코드(pwd 변수, ARIAEngine.decARIA 호출 등)는 그대로 두되 민감 정보 주석만 삭제한다.

## 핵심 개념

- **역컴파일(decompile)**: 컴파일된 실행파일/바이트코드를 소스 형태로 되돌리는 작업. 주석에 남긴 중요정보가 이 과정에서 그대로 노출될 수 있다.
- **시스템 주요 정보**: ID, 패스워드, 시스템 정보, 실행환경 등 공격에 악용될 수 있는 정보. 주석문에 남기면 안 된다.
- **주석문 정리**: 개발 편의로 남긴 계정·패스워드 등의 주석은 개발 완료 시 확실하게 삭제해야 하는 보안 활동.

## 시험 포인트

- 약점: 주석문에 남긴 시스템 주요정보(ID·패스워드·시스템 정보·실행환경)를 제거하지 않음
- 영향: 역컴파일(decompile)을 통해 주석 속 중요정보가 쉽게 유출되어 공격에 악용
- 대책: 주석문에 ID·패스워드 등 보안 관련 내용 미기입, 개발 완료 시 확실하게 삭제
- 안전하지 않은 코드: DB 연결 ID·패스워드, 암호화 전후 값을 주석으로 노출
- 진단 흐름: DB 접속·관리자 기능 코드 확인 → 주석 검토 → 민감 정보 포함 여부
