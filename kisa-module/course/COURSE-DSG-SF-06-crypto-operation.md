# 암호연산 (COURSE-DSG-SF-06)

- 단원: Ⅳ. 분석·설계 단계 보안약점 진단
- 분류: 보안기능(security_feature)
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정, pp.219-228
- 관련 라이브러리: DSG-SF-06

## 개요

국제표준 또는 검증필 프로토콜로 등재된 안전한 암호 알고리즘을 선정하여, 충분한 암호키 길이·솔트·충분한 난수값을 기반으로 암호연산 수행방법을 설계해야 한다.

- 대칭키/비대칭키 암·복호화 시 KISA 『암호 알고리즘 및 키 길이 이용 안내서』의 알고리즘과 안전한 키 길이 사용
- 복호화되지 않는 암호화에 해쉬함수를 쓰는 경우 안전한 해쉬 알고리즘과 솔트값 적용
- 난수 생성 시 안전한 난수 생성 알고리즘 사용

관련 보안약점(보안기능): 취약한 암호화 알고리즘 사용, 충분하지 않은 키 길이 사용, 적절하지 않은 난수값 사용, 부적절한 인증서 유효성 검증, 솔트 없이 일방향 해쉬함수 사용.

## 설계 시 고려사항

### 1) 대칭/비대칭키 알고리즘과 키 길이

- 대칭키 권고: SEED, ARIA-128/192/256, LEA-128/192/256, AES-128/192/256, Camellia, Serpent 등
- 비대칭키 권고: RSA, KCDSA(전자서명용), RSA-OAEP, Schnorr, XMSS, ECKCDSA 등
- NIST 안전성 유지기간·최소 키 길이 권고
  - 보안강도 112비트(11~30년): 대칭 112, RSA 2048, ECC 224
  - 보안강도 128 이상(30년~): 대칭 128/192/256, RSA 3072/7680/15360, ECC 256/384/512

### 2) 해쉬함수와 솔트

- 해쉬함수는 사용목적(메시지인증/키유도/난수생성용 vs 단순해쉬/전자서명용)과 보안강도에 따라 선택
- 안전한 해쉬: SHA-2 계열(SHA-224/256/384/512), SHA-3 계열
- 보안 강화를 위해 솔트값(안전한 난수발생기로 생성한 난수)을 적용

### 3) 난수 생성

- 국가정보원 '암호알고리즘 검증기준 V3.0' 또는 FIPS 140-2 인증 암호모듈의 난수생성기 사용
- 256비트 이상의 시드 사용
- 이전 난수생성 결과를 다음 단계 시드로 사용하는 의사난수생성기(PRNG)로 무작위성 보장
- 참고: 2022.4.1.부터 신규 제출에 대해 FIPS 140-3이 FIPS 140-2를 대체

## 진단 기준 및 방법

- 요구사항01(대칭/비대칭 암호화): 안전한 알고리즘(대칭 SEED·ARIA·AES, 비대칭 RSA·KCDSA·ECC)과 안전한 키 길이(대칭 128비트 이상, 비대칭 2048비트 이상) 설계 확인
- 요구사항02(일방향 해쉬): SHA-2/SHA-3 + 솔트값 적용 설계 확인, 복호화 시도(크랙) 테스트 계획 확인
- 요구사항03(난수생성): 안전한 난수생성 API(JAVA `java.security.SecureRandom`, C `randomize(seed)`) 사용 정의 및 난수 안전성 점검 테스트 계획 확인

## 시험 포인트

- 대칭키 권고: SEED·ARIA·AES·LEA / 비대칭키 권고: RSA·KCDSA·ECC
- 안전한 키 길이: 대칭키 128비트 이상, 비대칭키(RSA) 2048비트 이상
- 일방향 해쉬는 SHA-2/SHA-3 + 솔트값 적용 (솔트 없이 일방향 해쉬는 보안약점)
- 난수생성: 256비트 이상 시드, FIPS 140-2 인증 모듈, SecureRandom
- 키 길이 기준은 KISA 『암호 알고리즘 및 키 길이 이용 안내서』
