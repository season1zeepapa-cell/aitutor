# 인증 대상 및 방식 (COURSE-DSG-SF-01)

- 단원: Ⅳ. 분석·설계 단계 보안약점 진단 — 보안기능
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정, pp.170-179
- 관련 라이브러리: DSG-SF-01
- 관련 보안약점: (보안기능) 적절한 인증 없는 중요기능 허용, 부적절한 인증서 유효성 검증 / (입력데이터 검증 및 표현) 서버사이드 요청 위조 / (API 오용) DNS Lookup에 의존한 보안 결정

## 개요
중요정보·기능과 인증방식을 정의하고, 정의된 중요정보 접근 및 중요기능 수행 허용을 위해 인증 기능이 우회되지 않고 수행될 수 있도록 설계해야 한다.

- 중요 기능이나 리소스에 대해서는 인증 후 사용 정책이 적용되어야 한다.
- 안전한 인증방식을 사용하여 인증우회나 권한상승이 발생하지 않도록 해야 한다.
- 중요 기능에 대해 이중 인증(two factor authentication)을 고려해야 한다.

## 설계 시 고려사항

### 1. 인증 후 사용 정책 적용
- 분석단계에 분류된 중요기능에 대해 "인증 후 사용" 정책이 반드시 적용되도록 한다.
- 각 중요기능마다 개별 인증 구현은 어려우므로, 식별된 중요기능에 일괄적으로 인증을 요구하도록 설계한다.
- 기능-인증을 직접 매핑하는 컴포넌트를 개발하거나, 인증 프레임워크·라이브러리로 중앙집중식 인증을 적용한다.

### 2. 안전한 인증방식 (인증우회·권한상승 방지)
- 인증정보는 서버 측에 저장하여, 인증이 필요한 기능·리소스 접근 시 서버에서 인증 여부를 확인한다.
- 일회용 패스워드(OTP) 도입 시 규칙:
  - OTP는 시각정보·이벤트정보·질의-응답방식으로 취득한 정보를 이용해 생성할 수 있다.
  - 시각정보 기반 연계정보는 특정시간 동안만 유효해야 하며, 이벤트/질의-응답 방식은 연계정보를 추측할 수 없도록 보호한다.
  - OTP에 시간적 제한을 설정한다(금융 영역 30~60초).
  - 중복·유추 불가능하도록 6자리 이상 숫자·문자로 구성한다.
  - OTP 발생기와 인증서버에서 동일한 정보를 생성해야 한다.

### 3. 중요기능에 대한 2단계(2-factor) 인증
- 멀티디바이스(SMS, ARS 등) 추가 인증, PKI 인증서, 바이오정보(지문·안면·홍채)를 이용한 이중인증을 고려한다.
- 다음 중 2개 Type 이상의 인증기법을 사용하도록 설계한다.
  - Type1: 지식기반인증 (패스워드/PIN 등)
  - Type2: 소유기반인증 (토큰/스마트카드 등)
  - Type3: 생체기반인증 (지문/안면/홍채 등)

## 진단 기준 및 방법

### 요구사항 01 — 중요 기능·리소스에 인증 후 사용 정책 적용
- 01 중요 기능·리소스가 분류되어 있는가 (요구사항정의서)
- 02 인증 정책이 안전하게 적용되도록 설계되어 있는가 (요구사항정의서·요구사항추적표·아키텍처설계서, DB설계서, 유즈케이스/클래스설계서)
  - 프레임워크 컴포넌트를 활용해 인증 누락이 발생하지 않도록 설정되었는지 확인
- 03 접근 우회 취약점 점검 테스트 계획이 수립되어 있는가 (요구사항정의서)

### 요구사항 02 — 안전한 인증방식으로 인증우회·권한상승 방지
- 01 안전한 인증방식 적용 설계 (지식/소유/생체 기반), 인증정보 암호화 저장, 인증횟수 제한·오류처리, 인증실패 로깅(인증시도시간·IP·ID 포함) 설계
- 02 인증우회 또는 권한상승 발생 여부 점검 테스트 계획 (인증실패 로그 기록, 인증 없이 중요기능 접근 시도 점검)

### 요구사항 03 — 중요기능에 대한 2단계(2-factor) 인증 고려
- 01 추가인증이 필요한 중요기능(개인정보 변경, 패스워드 재설정, 권한 관리, 관리자 기능 등)에 안전한 인증방식(ID/PW 또는 OTP, 멀티디바이스, PKI 인증서, 바이오정보) 적용 및 로깅 설계
- 02 중요기능에 대한 추가 인증요구 수행 및 인증실패 로깅 점검 테스트 계획

> 모든 요구사항의 1-1 진단방법은 공통: 요구사항정의서 대책 수립 + 아키텍처설계서 적용계획 + 요구사항추적표 추적 가능 여부 확인.

## 시험 포인트
- 중요기능은 "인증 후 사용" 정책 + 중앙집중식 인증으로 인증 누락 방지.
- 인증정보는 서버 측 저장, 서버에서 인증 여부 확인.
- 2-factor 인증은 Type1/Type2/Type3 중 서로 다른 2개 Type 이상 결합.
- OTP 시간제한(금융 30~60초), 6자리 이상 숫자·문자, 발생기와 인증서버 동일 정보 생성.
- 인증오류·실패 로깅에 인증시도시간·IP·ID 포함.
