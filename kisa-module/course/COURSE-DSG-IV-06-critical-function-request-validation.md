# 웹 기반 중요기능 수행 요청 유효성 검증 (COURSE-DSG-IV-06)

> Ⅳ. 분석·설계 단계 보안약점 진단 · 2025년 SW보안약점 진단원 기본(양성)과정 · pp.135-140
> 관련 라이브러리: DSG-IV-06 · 분류: 입력데이터 검증 및 표현

## 개요

사용자 권한확인(인증 등)이 필요한 **중요기능(결제 등)** 에 대한 웹 서비스 요청의 유효성 검증방법과 유효하지 않은 요청에 대한 처리방법을 설계해야 한다. 시스템으로 전송되는 **모든 요청에 대해 정상적인 사용자의 유효한 요청인지 아닌지** 판별할 수 있도록 해야 한다.

- 관련 보안약점: 입력데이터 검증 및 표현 > **크로스사이트 요청위조(CSRF)**

## 설계 시 고려사항

**시스템으로 전송되는 모든 요청에 대해 정상적인 사용자의 유효한 요청인지 판별할 수 있도록 해야 한다.**

- **CSRF 토큰 사용**: 웹은 URL 기반으로 요청을 처리하므로 정상 사용자 요청 구분 정책이 없으면 스크립트·자동화 도구의 요청이 검증 없이 처리된다. 세션별로 CSRF 토큰을 생성해 세션에 저장하고, 작업페이지 요청 시 hidden값으로 클라이언트에 전달한 뒤, 데이터처리 요청 시 전달되는 CSRF 토큰값을 세션 저장값과 비교 검사한다. MVC프레임워크(Spring, Struts)의 **Interceptor** 컴포넌트로 요청을 가로채 토큰값이 일치할 때만 요청을 처리하도록 설계한다.
- **사용자와 상호 처리 기능 적용**: CSRF 토큰 방식도 XSS 취약점이 있는 사이트를 통하면 무력화될 수 있으므로 **CAPTCHA** 같은 상호 처리 기법으로 위조 요청을 차단한다.
- **재인증 요구**: 중요기능의 경우 재인증을 통해 실제 요청 여부를 안전하게 확인한다.

## 진단 기준 및 방법

### 요구사항 01 — 모든 요청에 대해 정상 사용자의 유효한 요청인지 판별

**진단항목 01. 중요기능 요청에 대해 요청 유효성을 판단하여 처리하도록 설계되어 있는가?**

| 진단방법 | 관련 산출물 |
|---|---|
| 1-1 요구사항정의서 대책 + 아키텍처설계서 적용계획 + 요구사항추적표 추적 가능 여부 | 요구사항정의서, 요구사항추적표, 아키텍처설계서 |
| 1-2 정상 절차 요청 검증 기능 안전 설계 (CSRF 토큰 / CAPTCHA로 요청 유효성 검증) | 프로그램명세서, 클래스설계서, 아키텍처설계서 |
| 1-3 요청 유효성 점검 기능을 모든 데이터 처리 요청 또는 각 처리 기능에 적용 | 아키텍처설계서 적용계획, (개별 적용 시) 클래스설계서·개발가이드 |
| 1-4 주요기능 재인증/재인가 처리 방법·모듈 설계 | 클래스설계서 |

**진단항목 02. 요청 유효성 검증 기능을 점검하는 테스트 계획이 수립되어 있는가?**

| 진단방법 | 관련 산출물 |
|---|---|
| 2-1 자동화 스크립트/프로그램 자동 요청을 식별하여 차단되는지 점검 | 단위테스트케이스 |

**관련 산출물**: 요구사항정의서, 요구사항추적표, 아키텍처설계서, 개발가이드, 프로그램명세서, 클래스설계서, 단위테스트케이스 등

## 시험 포인트

- 관련 보안약점은 **CSRF(크로스사이트 요청위조)**
- CSRF 토큰은 세션별 생성·저장 → hidden값 전달 → 요청 시 세션값과 비교 검증
- Spring·Struts의 **Interceptor** 로 토큰값 자동 체크
- CSRF 토큰은 XSS로 무력화 가능 → **CAPTCHA** 등 상호 처리 기법 병행, 중요기능은 **재인증**
- 테스트: 자동화 스크립트 요청 식별·차단 점검
