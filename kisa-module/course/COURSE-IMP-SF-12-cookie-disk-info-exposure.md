# 사용자 하드디스크에 저장되는 쿠키를 통한 정보노출 (IMP-SF-12)

- **unit_code**: COURSE-IMP-SF-12
- **단계**: Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정, p.419-421

## 요약

개인정보, 인증정보, 금융정보와 같은 중요 정보를 영속적인 쿠키(persistent cookie)에 저장하는 경우, 쿠키에 저장된 중요정보 유출로 사용자 권한이나 인증과 같은 보안 체계를 우회한 공격이 수행될 수 있다. 쿠키의 만료 시간은 세션 지속 시간과 관련하여 최소한으로 설정하고, 영속적인 쿠키에는 사용자 권한 등급·세션 ID 등이 포함되지 않도록 한다.

## 개요 — 약점과 대책

- 약점: 개인정보, 인증정보, 금융정보와 같은 중요 정보를 영속적인 쿠키(persistent cookie)에 저장하는 경우.
- 영향: 쿠키에 저장된 중요정보 유출로 인해 사용자 권한이나 인증과 같은 보안 체계를 우회한 공격이 수행될 수 있다.
- 대책 ①: 쿠키의 만료 시간은 세션이 지속되는 시간과 관련하여 최소한으로 설정한다.
- 대책 ②: 영속적인 쿠키에는 사용자 권한 등급, 세션 ID 등이 포함되지 않도록 한다.

## 진단 흐름 (점검 순서)

- 쿠키 전송 기능 확인 → 쿠키 유효기간 확인.
- 쿠키가 비영속(non-persistent)이면 안전.
- 쿠키가 영속(persistent)이면 쿠키 값에 중요 정보 포함 여부를 확인.
- 중요 정보 포함이 없으면 안전, 있으면 위험.

## 안전하지 않은 코드 (예시)

- 로그인 유지(rememberMe) 시 Cookie를 생성하고 setSecure(true), setHttpOnly(true)는 설정한다.
- 그러나 loginCookie.setMaxAge(60*60*24*30*12)로 만료시간을 1년으로 과도하게 길게 설정하여 안전하지 않다.
- 영속 쿠키의 만료 시간이 과도하면 하드디스크에 장기간 남아 정보노출 위험이 커진다.

## 안전한 코드 (예시)

- 동일하게 setSecure(true), setHttpOnly(true)를 설정한다.
- loginCookie.setMaxAge(60*60*24)로 만료시간을 해당 기능에 맞춰 최소(1일)로 설정한다.
- 쿠키 만료 시간은 해당 기능에 맞춰 최소로 사용한다.

## 핵심 개념

- **영속적인 쿠키(persistent cookie)**: 만료 시간이 설정되어 브라우저 종료 후에도 사용자 하드디스크에 저장되는 쿠키. 중요정보 저장 시 유출 위험이 크다.
- **비영속 쿠키(non-persistent / session cookie)**: 만료 시간 없이 메모리에만 존재하고 브라우저 종료 시 사라지는 쿠키. 디스크에 남지 않아 상대적으로 안전하다.
- **setMaxAge**: 쿠키의 만료 시간(초)을 설정하는 메서드. 세션 지속 시간에 맞춰 최소한으로 설정해야 한다.
- **Secure / HttpOnly**: Secure는 HTTPS 전송 시에만 쿠키 전송, HttpOnly는 스크립트 접근 차단. 다만 만료 시간이 길면 디스크 저장 위험은 남는다.

## 시험 포인트

- 약점: 개인정보·인증정보·금융정보 등 중요 정보를 영속적인 쿠키에 저장
- 영향: 쿠키 중요정보 유출로 권한·인증 보안 체계 우회 공격 가능
- 대책: 쿠키 만료 시간을 세션 지속 시간 관련 최소한으로 설정, 영속 쿠키에 권한 등급·세션 ID 미포함
- 안전하지 않은 코드: setMaxAge(60*60*24*30*12) = 1년으로 과도하게 길게 설정
- 안전한 코드: setMaxAge(60*60*24) = 1일로 기능에 맞춰 최소 설정
- 진단 흐름: 영속 쿠키 여부 → 중요 정보 포함 여부 (비영속이거나 미포함이면 안전)
