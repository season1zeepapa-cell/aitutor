# 취약한 암호화 알고리즘 사용 (COURSE-IMP-SF-04)

- 단계: Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려
- 항목: 2-4 취약한 암호화 알고리즘 사용
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정 (pp.383-387)
- 관련 라이브러리 항목: IMP-SF-04

## 요약
중요 정보를 암·복호화할 때 취약한 암호 알고리즘을 사용하는 경우 발생하는 보안약점이다. 외부로 유출된 중요 정보가 복호화되어 노출될 수 있다.

## 정의와 영향
- 정의: 중요 정보를 암·복호화할 때 취약한 암호 알고리즘을 사용하는 경우 발생한다.
- 영향: 외부로 유출된 중요 정보가 복호화되어 노출될 수 있다.

## 보안대책
- 자체적인 암호화 알고리즘을 개발해서 사용하는 것은 안전하지 않으므로, 학계 및 업계에서 이미 검증된 표준화된 알고리즘을 사용한다.
- 취약하다고 알려진 DES, RC5 등의 알고리즘 대신 3TDEA, AES, SEED, LEA, RSA, SHA2, SHA3 등의 안전한 암호 알고리즘을 사용한다.

## 진단 흐름
- 암호화 기능 사용 여부를 확인한다.
- 자체 구현 암호화 알고리즘을 사용하면 위험으로 판정한다.
- 취약하다고 알려진 암호화 알고리즘을 사용하면 위험, 아니면 안전으로 판정한다.

## 안전하지 않은 코드 vs 안전한 코드 (암호화)
- 안전하지 않은 코드: `Cipher.getInstance("DES")` — 키 길이가 짧아 취약한 DES 알고리즘을 사용한다.
- 안전한 코드: `Cipher.getInstance("AES/CBC/PKCS5Padding")` — 강력한 AES 알고리즘을 사용한다.
- 핵심: 취약한 DES 대신 검증된 AES 등 안전한 알고리즘을 사용한다.

## 알고리즘·모드·패딩 개념
- DES: 1976년 IBM 연구팀 개발, 1977년 FIPS 채택. 56비트 키, 64비트 블록 단위 대칭 암호. 컴퓨터 성능 발전으로 현재는 취약한 알고리즘.
- AES: 현재 가장 널리 사용되고 안전하다고 여겨지는 대칭키 암호화 알고리즘 중 하나.
- CBC(Cipher Block Chaining): 이전 암호 블록 결과를 다음 블록에 연결하여 동일 평문이 동일 암호문이 되는 것을 방지(패턴 은닉). 초기화 벡터(IV)가 필요한 운영 모드.
- PKCS5Padding: 데이터 블록 길이가 블록 크기에 맞지 않을 때 마지막 블록을 채우는 표준 패딩 방식.

## 시험 포인트
- 약점 정의: 중요 정보 암·복호화 시 취약한 암호 알고리즘 사용 → 유출 정보가 복호화되어 노출
- 보안대책: 자체 개발 알고리즘 금지, 검증된 표준 알고리즘 사용
- 취약 알고리즘: DES, RC5 / 안전 알고리즘: 3TDEA, AES, SEED, LEA, RSA, SHA2, SHA3
- 안전한 코드: `Cipher.getInstance("AES/CBC/PKCS5Padding")`, 취약한 코드: `Cipher.getInstance("DES")`
- DES는 56비트 키·64비트 블록 대칭암호, CBC는 IV가 필요하며 동일 평문의 동일 암호문화를 방지
