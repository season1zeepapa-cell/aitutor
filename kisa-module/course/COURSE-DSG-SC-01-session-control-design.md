# 세션통제 (COURSE-DSG-SC-01)

- 단원: Ⅳ. 분석·설계 단계 보안약점 진단
- 분류: 세션통제(session_control)
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정, pp.251-258
- 관련 라이브러리: DSG-SC-01

## 개요

HTTP로 연결을 유지하는 경우 세션을 안전하게 할당·관리하여 세션 정보 노출이나 세션 하이재킹 같은 침해사고가 발생하지 않도록 설계한다.

- 다른 세션 간 데이터 공유금지, 세션ID 노출금지, (재)로그인 시 세션ID 변경, 세션종료(비활성화·유효기간) 처리
- 세션간 데이터가 공유되지 않도록 설계
- 세션이 안전하게 관리되도록 함 / 세션ID가 안전하게 관리되도록 함

관련 보안약점(캡슐화): 잘못된 세션에 의한 데이터 정보노출.

## 설계 시 고려사항

### 1) 세션 간 데이터 비공유

- 스레드로 동작되는 컨트롤러 컴포넌트, 싱글톤 객체로 생성되는 서비스 컴포넌트 설계 시 클래스 멤버변수·클래스 변수는 세션간 공유 데이터가 됨
- 클래스 설계 시 읽고 쓰기가 가능한 변수를 사용하지 않도록 설계

### 2) 안전한 세션 관리

- 모든 페이지에서 로그아웃 가능하도록 UI 설계, 로그아웃 시 세션 완전 제거 API 사용(Java `session.invalidate()`)
- 세션 타임아웃: 중요기능 2~5분, 위험도 낮은 애플리케이션 15~30분. 이전 세션 미종료 상태에서 새 세션 생성 금지
- 브라우저 종료는 서버가 인지 못하므로 일정시간 미사용 세션 정보를 강제 삭제하도록 아키텍처링
- 중복 로그인 불허 시 새 로그인 세션 생성 시 이전 세션 종료 또는 새 연결 종료 정책을 설계단계에 고려
- 세션ID 포함 쿠키에 HttpOnly 속성 설정하여 자바스크립트 조회 차단(XSS 대응)
- 패스워드 변경 시 현재 활성화된 모든 세션 삭제 후 재할당

### 3) 안전한 세션ID 관리

- 생성: 안전한 서버에서 생성, 최소 128비트 길이, 안전한 난수 알고리즘으로 예측 불가능한 값
- 사용: URL rewrite는 세션ID가 URL에 노출되므로 사용하지 않도록 설계
- 폐기: 로그인 성공 시 기존 세션ID 파기하고 새 값으로 재할당(세션ID 고정공격 대응), 장기간 접속 시 일정 시간 주기로 재할당

## 진단 기준 및 방법

- 요구사항01(세션 간 데이터 비공유): 스레드 동작 클래스에 읽기/쓰기 공유 데이터(Servlet·Controller 멤버변수·클래스변수, JSP 선언부 변수) 미설계 확인, 다중 세션 값 변경 점검 테스트 계획 확인
- 요구사항02(안전한 세션 관리): 로그인 성공 시 세션 재할당, 로그아웃 시 세션 완전 제거, 일방적 연결종료 시 세션 제거, 타임아웃(2~5분/15~30분), 패스워드 변경 시 재인증 후 새 세션 할당 설계 확인 및 관련 테스트 계획 확인
- 요구사항03(안전한 세션ID 관리): 서버 생성, 쿠키 전송 제한+HttpOnly, 일정시간 주기 재할당, 로그인 후 세션ID 재할당 웹서버 환경설정/코딩규칙 확인, 세션ID 노출·재할당 점검 테스트 계획 확인

## 시험 포인트

- 세션 간 공유 변수(싱글톤·Controller 멤버변수) 사용 금지로 정보노출 방지
- 세션 타임아웃: 중요기능 2~5분, 위험도 낮음 15~30분
- 세션ID 쿠키에 HttpOnly 설정으로 XSS 세션탈취 대응
- 세션ID 최소 128비트, 안전한 난수로 서버 생성, URL rewrite 미사용
- 로그인 성공 시 세션ID 재할당으로 세션ID 고정공격 대응, 패스워드 변경 시 세션 재할당
