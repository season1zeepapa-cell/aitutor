# 운영체제 명령어 삽입 (COURSE-IMP-IV-05)

- **단원**: Ⅴ. 구현 단계 보안약점 진단 > 입력데이터 검증 및 표현
- **유형**: 교재 카드 (course)
- **분류**: 입력 데이터 검증 및 표현 (input_validation)
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정, 318-321쪽
- **관련 진단 라이브러리**: IMP-IV-05

## 요약

외부입력값을 검증·제한하지 않고 운영체제 명령문 생성 및 실행에 사용하는 경우 발생하는 보안약점이다. 공격자가 삽입한 운영체제 명령어가 웹 애플리케이션 서버의 실행 권한으로 실행되어 중요 파일 삭제, 백도어 실행 등 심각한 문제가 발생한다. 애플리케이션 내부에서 OS 명령어를 실행하지 않도록 설계하고, 불가피하면 미리 정의된 허용 목록(화이트리스트)에서 선택하여 사용한다.

## 개요 — 정의와 영향

- **정의**: 외부입력값을 검증·제한하지 않고 운영체제 명령문 생성 및 실행에 사용하는 경우 발생한다.
- **영향**: 공격자가 삽입한 운영체제 명령어가 웹 애플리케이션 서버의 실행 권한으로 실행되어 시스템 내부의 중요 파일이 삭제되거나 백도어가 실행되는 심각한 문제가 발생한다.

## 보안대책

- 애플리케이션 내부에서 운영체제 명령어가 실행되지 않도록 프로그램을 설계한다.
- 외부에서 전달되는 값을 내부 명령에 직접 사용하지 않고, 프로그램 내부에 미리 정의되어 있는 허용 목록(White List)을 검색하여 사용하도록 설계한다.
- **진단 흐름**: OS 명령어 실행 함수 호출에서 외부입력값이 없으면 안전, 있으면 White List 미적용·입력값 미검증일 때 위험으로 판정한다.

## 코드 예제 핵심 — 허용 목록 기반 실행

- **위험 ①**: `args[0]`을 그대로 `Runtime.getRuntime().exec(cmd)`로 실행하면 파라미터로 전달되는 모든 프로그램이 실행될 수 있다. → 허용 목록(`notepad`, `calc`)을 정의하고 `allowedCommands.contains(cmd)`로 검사 후 미포함 시 거부한다.
- **위험 ②**: `request.getParameter("data")`를 `cmd.exe /c` 인자로 그대로 실행하면 위험하다. → 허용 명령(`type`, `dir`)을 배열로 두고 입력값을 인덱스(0 또는 1)로만 받아 허용 배열에서 선택하며, 그 외 값은 변조로 보고 오류 처리한다.
- 핵심은 외부 입력값을 명령어 문자열로 직접 쓰지 않고, 사전 정의된 허용 명령 집합에서만 선택하게 하는 것이다.

## 핵심 개념

| 용어 | 정의 |
| --- | --- |
| 운영체제 명령어 삽입(OS Command Injection) | 검증되지 않은 외부입력값을 OS 명령문 생성·실행에 사용하여 임의 명령이 서버 권한으로 실행되는 약점 |
| 허용 목록(White List) | 프로그램 내부에 미리 정의한 실행 가능 명령 집합. 외부 입력은 이 목록에서만 선택하도록 제한하는 핵심 대책 |
| Runtime.exec | Java에서 OS 프로세스를 실행하는 함수. 외부 입력값을 직접 전달하면 명령어 삽입에 취약 |

## 시험 포인트

- 운영체제 명령어 삽입은 외부입력값을 검증·제한 없이 OS 명령문 생성·실행에 사용할 때 발생한다.
- 영향: 삽입된 명령어가 웹 애플리케이션 서버 실행 권한으로 실행 → 중요 파일 삭제, 백도어 실행 등 심각한 문제
- 보안대책: 내부에서 OS 명령어를 실행하지 않도록 설계 / 불가피 시 미리 정의된 허용 목록(White List)에서 선택
- 안전한 코드는 `allowedCommands`(notepad·calc) `contains` 검사, 또는 입력을 인덱스로 받아 허용 배열(type·dir)에서 선택
