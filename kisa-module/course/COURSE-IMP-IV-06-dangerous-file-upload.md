# 위험한 형식 파일 업로드 (COURSE-IMP-IV-06)

> 2025년 SW보안약점 진단원 기본(양성)과정 · Ⅴ. 구현 단계 보안약점 진단 · 입력데이터 검증 및 표현 · 1-6 (pp.322-324)

## 요약
업로드되는 파일에 대한 안전성을 검사하지 않고 파일 업로드를 허용하면 발생한다. 공격자는 웹쉘 업로드·실행으로 서버를 장악하거나, 키로거를 설치해 인증정보를 탈취하거나, 악성코드 파일로 다운로드 사용자 PC를 감염시킬 수 있다. 화이트리스트 확장자 제한과 안전한 저장 경로 설계가 대책이다.

## 개요 — 정의와 위협
- 정의: 업로드되는 파일에 대한 안전성을 검사하지 않고 파일 업로드를 허용하는 경우 발생한다.
- 위협 ① 웹쉘(webshell)을 업로드·실행하여 해당 웹 애플리케이션 서버를 장악한다.
- 위협 ② 키로거(key logger)를 설치하여 인증 정보를 획득한다.
- 위협 ③ 악성코드가 포함된 파일을 업로드하여 다운로드 받은 사용자의 PC를 감염시킨다.

## 보안대책
- 업로드되는 파일의 크기와 개수를 제한한다.
- 업로드되는 파일의 종류를 제한한다.
- 업로드한 파일을 외부에서 접근할 수 없는 경로(WebRoot 밖)에 저장한다.
- 업로드한 파일의 저장 경로와 파일명을 외부에서 알 수 없도록 한다.
- 업로드한 파일에 실행 권한을 제거하고 저장한다.
- 진단 흐름: 파일 업로드 기능 확인 → (파일 크기·개수·종류 검증 + 파일명 변경 + WebRoot 밖 저장) → 적용 시 안전, 미적용 시 위험

## 안전하지 않은 코드 — 파일명 무검증 사용
- MultipartRequest로 업로드를 받은 뒤 `getFilesystemName()`으로 얻은 파일명을 검증 없이 그대로 사용한다.
- 업로드 되는 파일명을 검증없이 사용하고 있어 안전하지 않다.
- 파일명을 DB(board.filename)에 저장하고 Thumbnail.create()로 처리하지만, 확장자·종류 검증이 없어 위험한 형식 파일(웹쉘 등)이 업로드될 수 있다.

## 안전한 코드 — 화이트리스트 확장자 제한
- 화이트 리스트 방식으로 허용되는 확장자로 업로드를 제한해야 안전하다.
- 파일명에서 마지막 `.` 이후 확장자를 추출(toLowerCase)하여 gif·jpg·png 만 허용하고, 그 외 확장자는 `업로드 불가능한 파일입니다.` 처리 후 차단(return)한다.
- 허용 확장자 검증을 통과한 경우에만 DB 저장 및 Thumbnail.create() 처리를 진행한다.

## 핵심 개념
- **웹쉘(webshell)**: 공격자가 업로드·실행하여 웹 애플리케이션 서버를 원격 제어·장악하는 악성 스크립트 파일.
- **화이트리스트 확장자 제한**: 허용 확장자(gif·jpg·png 등)만 통과시키고 그 외를 차단하는 방식. 블랙리스트보다 안전.
- **WebRoot 밖 저장**: 업로드 파일을 웹 직접 접근 경로 외부에 저장해 URL 직접 실행을 막는 대책.

## 시험 포인트
- 대표 위협: 웹쉘 업로드·실행을 통한 서버 장악, 키로거 설치, 악성코드 감염.
- 대책: 파일 크기·개수·종류 제한, WebRoot 밖 저장, 저장 경로·파일명 비공개, 실행 권한 제거.
- 확장자 검증은 화이트리스트 방식(gif·jpg·png 허용)으로 수행해야 안전.
- `getFilesystemName()`으로 얻은 파일명을 검증 없이 사용하면 취약.
