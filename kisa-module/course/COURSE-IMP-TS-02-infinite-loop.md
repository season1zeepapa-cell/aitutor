# 종료되지 않는 반복문 또는 재귀 함수

- **unit_code**: COURSE-IMP-TS-02
- **단원**: Ⅴ. 구현 단계 보안약점 진단 > 시간 및 상태 항목에 대한 고려
- **분류**: time_state
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정, pp.437-439
- **관련 라이브러리**: IMP-TS-02

## 요약

재귀함수의 순환 횟수를 제어하지 않아 메모리나 프로그램 스택 등의 자원을 과다하게 사용하는 보안약점이다. 귀납조건(base case)이 없는 재귀함수는 무한 루프에 빠져 자원 고갈을 유발하고 정상적인 서비스를 제공할 수 없게 한다.

## 개요 — 정의와 영향

- 재귀함수의 순환 횟수를 제어하지 않아 메모리나 프로그램 스택 등의 자원을 과다하게 사용하는 경우 발생한다.
- 귀납조건(base case)이 없는 재귀함수는 무한 루프에 빠지게 되고, 자원 고갈을 유발함으로써 시스템의 정상적인 서비스를 제공할 수 없게 한다.

## 대응 방안

- 재귀 호출 시, 재귀 호출 횟수를 제한하거나, 초기값을 설정하여 재귀 호출을 제한한다.

## 진단 흐름

1. 자신을 호출하는 재귀함수 존재 확인.
2. 반환하는 제어문(탈출 조건) 확인 — 있음이면 안전, 없음이면 위험.

## 코드 비교

### 안전하지 않은 코드

`factorial(int i)`에서 `return i * factorial(i - 1);`만 존재하여 재귀함수 탈출 조건을 설정하지 않아 무한루프가 된다.

```c
int factorial(int i) {
    // 재귀함수 탈출 조건을 설정하지 않아 무한루프가 된다.
    return i * factorial(i - 1);
}
```

### 안전한 코드

`factorial` 진입부에 탈출 조건을 추가하여 재귀 호출이 종료되도록 한다.

```c
int factorial(int i) {
    // 재귀함수 사용 시에는 아래와 같이 탈출 조건을 사용해야 한다.
    if (i <= 1) {
        return 1;
    }
    return i * factorial(i - 1);
}
```

`main`에서는 `fgets`로 입력받아 `atoi`로 변환 후 `i <= 0`이면 오류 출력, 아니면 `factorial`을 호출한다 (양쪽 코드 동일).

## 시험 포인트

- 재귀함수 순환 횟수 미제어로 메모리·스택 자원을 과다 사용하는 시간 및 상태 분류 보안약점
- 귀납조건(base case) 없는 재귀는 무한 루프 → 자원 고갈 → 서비스 불능
- 대응: 재귀 호출 횟수 제한 또는 초기값(탈출 조건) 설정
- 진단: 재귀함수 존재 확인 → 반환 제어문(탈출 조건) 유무 확인
- 안전한 코드 핵심: factorial에 `if (i <= 1) return 1;` 탈출 조건 추가
