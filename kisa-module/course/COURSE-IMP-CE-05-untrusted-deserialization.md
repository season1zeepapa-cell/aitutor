# 신뢰할 수 없는 데이터의 역직렬화 (COURSE-IMP-CE-05)

- **단원**: Ⅴ. 구현 단계 보안약점 진단 > 코드오류 항목에 대한 고려
- **유형**: 교재 카드 (course)
- **분류**: 코드오류 (code_error)
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정, 472-478쪽
- **관련 진단 라이브러리**: IMP-CE-05

## 요약

송신자가 네트워크로 직렬화된 정보를 수신자에게 전달하는 과정에서 공격자가 전송·저장된 스트림을 조작할 수 있는 경우, 신뢰할 수 없는 역직렬화를 이용하는 보안약점이다. 무결성 침해, 원격 코드 실행, 서비스 거부 공격이 발생할 수 있다. 신뢰할 수 없는 데이터를 역직렬화하지 않도록 구성하고, 서명·검증으로 무결성을 확인하거나 사전 검증된 클래스만 역직렬화하도록 한다.

## 개요 — 정의·영향·대책

- **정의**: 송신자가 네트워크를 이용하여 직렬화된 정보를 수신자에게 전달하는 과정에서, 공격자가 전송 또는 저장된 스트림을 조작할 수 있는 경우 신뢰할 수 없는 역직렬화를 이용한다.
- **영향**: 무결성 침해, 원격 코드 실행, 서비스 거부 공격 등이 발생할 수 있다.
- **대책 ①**: 신뢰할 수 없는 데이터를 역직렬화하지 않도록 응용프로그램을 구성한다.
- **대책 ②**: 암호화 통신을 적용하지 못하는 경우, 송신 측에서 서명을 추가하고 수신 측에서 서명을 확인하여 데이터의 무결성을 검증한다.
- **대책 ③**: 역직렬화 대상의 직렬화 데이터가 사전에 검증된 클래스에만 포함되는지 검증하거나, 제한된 실행 권한을 구성하여 역직렬화 코드를 실행한다.
- **진단 흐름**: 직렬화/역직렬화로 데이터 송수신 시 → 데이터 서명 및 검증 사용하면 안전 → 미사용 시 사전에 검증된 클래스인지 검증, 예이면 안전 / 아니면 위험

## 코드 예제 ① — 서명(SignedObject) 검증 (Java)

- **안전하지 않은 코드**: ObjectInputStream으로 파일을 읽어 `map = (SerializableMap) in.readObject();`를 수행하며, 공격자가 바이트스트림을 조작했는지 점검 없이 역직렬화한다.
- **안전한 코드**: SealedObject를 역직렬화한 뒤 Cipher(AES)로 복호화하여 SignedObject를 추출하고, `signedMap.verify(공개키, sig)`로 서명을 검증한다.
- 서명 불일치 시 GeneralSecurityException을 던지고, 일치할 때만 `signedMap.getObject()`로 map 값을 읽는다.

## 코드 예제 ② — 화이트리스트 클래스 검증 (Java)

- **안전하지 않은 코드**: ByteArrayInputStream/ObjectInputStream에서 `ret = ois.readObject();`로 바이트 배열 입력값을 검증 없이 역직렬화한다.
- **안전한 코드**: ObjectInputStream을 상속한 `WhitelistedObjectInputStream`을 만들고, `resolveClass()`를 오버라이드하여 ObjectStreamClass의 클래스명이 화이트리스트에 있는지 확인한다.
- 화이트리스트에 없으면 `InvalidClassException("Unexpected serialized class")`을 던진다. 업로드 핸들러에서 역직렬화 대상 클래스명(예: "Student") 화이트리스트를 생성해 사용한다.

## 코드 예제 ③ — HMAC 무결성 검증 (Python pickle)

- **안전하지 않은 코드**: 소켓으로 받은 data를 `Pickle.loads(data)`로 검증 없이 역직렬화한다.
- **안전한 코드(클라이언트)**: `pickle.dumps`로 직렬화한 데이터에 `hmac.new('shared-key', pickled_data, sha1)`로 digest를 만들어 헤더로 함께 전송한다.
- **안전한 코드(서버)**: 수신 데이터를 digest와 pickled_data로 분리하고 새 HMAC을 계산하여, `recvd_digest != new_digest`면 무결성 검증 실패 처리, 일치할 때만 `pickle.loads`로 역직렬화한다.

## 핵심 개념

| 용어 | 정의 |
| --- | --- |
| 신뢰할 수 없는 역직렬화 | 공격자가 조작할 수 있는 직렬화 스트림을 검증 없이 역직렬화하여 무결성 침해·원격 코드 실행·서비스 거부를 유발하는 보안약점 |
| 서명·검증(SignedObject/HMAC) | 암호화 통신이 불가할 때 송신 측이 서명(또는 HMAC digest)을 추가하고 수신 측이 검증하여 역직렬화 전 데이터 무결성을 확인하는 대책 |
| 화이트리스트 클래스 검증 | ObjectInputStream의 `resolveClass()`를 오버라이드해 사전에 검증된 클래스명만 역직렬화를 허용하고, 그 외에는 InvalidClassException으로 차단하는 방법 |

## 시험 포인트

- 신뢰할 수 없는 역직렬화는 공격자가 직렬화 스트림을 조작할 수 있는 환경에서 검증 없이 역직렬화할 때 발생한다.
- 영향: 무결성 침해, 원격 코드 실행(RCE), 서비스 거부(DoS) 공격이 발생할 수 있다.
- 3대 대책: 신뢰할 수 없는 데이터 역직렬화 금지 / 서명 추가·검증으로 무결성 확인 / 사전 검증된(화이트리스트) 클래스만 역직렬화 또는 제한된 실행 권한 구성
- 안전한 코드: Java는 SignedObject 서명 검증·resolveClass 화이트리스트, Python pickle은 HMAC digest 비교 후 loads.
