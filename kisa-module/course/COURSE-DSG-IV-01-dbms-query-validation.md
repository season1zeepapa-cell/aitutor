## 개요 — 설계기준과 보안대책

DBMS 조회를 위한 질의문(SQL) 생성 시 사용되는 입력값과 조회결과에 대한 검증방법(필터링 등)을 설계하고, 유효하지 않은 값에 대한 처리방법을 설계해야 한다.

**3대 보안대책**
1. 애플리케이션에서 DB연결을 수행할 때 최소권한의 계정을 사용해야 한다.
2. 외부입력값이 삽입되는 SQL문을 동적으로 생성해서 실행하지 않도록 해야 한다.
3. 외부입력값이 동적으로 SQL쿼리문을 생성해야 하는 경우, 입력값에 대한 검증을 수행한 뒤 사용해야 한다.

## 설계 시 고려사항

- **최소권한 계정**: 침해사고가 발생해도 나머지 부분에 공격자가 접근하지 못하도록, DB연결 계정은 해당 애플리케이션이 사용하는 데이터에 대한 읽기·쓰기·삭제·수정 권한만 설정한다.
- **정적 쿼리 사용**: 쿼리문의 구조가 외부입력값에 의해 변경되지 않는 API를 사용하도록 시큐어코딩 규칙을 지정한다. ORM 프레임워크로 안전한 정적 쿼리 구조를 수행하도록 개발환경을 설정하고, 개발가이드로 정적 쿼리문 사용을 제한한다.
- **동적 쿼리 불가피 시 입력값 검증**: 클라이언트와 서버 양측에서 안전한 값만 사용되도록 검증한다.
  - 필터(Filter)를 이용한 입력값 검증
  - 인터셉터(Interceptor)를 이용한 입력값 검증
  - 라이브러리 또는 Validator 컴포넌트를 이용한 입력값 검증

## 진단기준 및 방법

### 요구사항 ① 최소권한 계정
- **진단 1**: 애플리케이션 DB접속 계정이 할당되고, 각 계정 권한이 최소권한인가?
  - 1-1 요구사항정의서 대책 + 아키텍처설계서 적용계획 + 요구사항추적표 추적 → *요구사항정의서·요구사항추적표·아키텍처설계서*
  - 1-2 애플리케이션별 DB연결 계정할당과 최소권한할당 여부 → *아키텍처설계서·초기데이터설계서*
- **진단 2**: 권한 외 요청 차단 테스트 계획 수립 여부 → *단위테스트케이스*

### 요구사항 ② 정적 SQL(동적 생성 금지)
- **진단 1**: 외부입력값이 쿼리 구조에 영향을 미치지 않도록 보안설계 적용 여부
  - 1-1 요구사항정의서·아키텍처설계서·요구사항추적표
  - 1-2 ORM 프레임워크 사용 여부 → *아키텍처설계서 적용계획*
  - 1-3 개발가이드의 정적 쿼리 코딩 방법(iBatis/myBatis `#{변수}`, PreparedStatement) 정의 여부 → *개발가이드*
- **진단 2**: 입력값의 쿼리 구조 변경 점검 테스트 계획 → *단위테스트케이스*
  - **테스트 입력값**: 특수문자(`' " = & | ! ( ) { } $ % @`), 예약어(UNION, SELECT, THEN, IF, INSTANCE, END, COLUMN), 함수명(DATABASE(), CONCAT(), COUNT(), LOWER())

### 요구사항 ③ 동적 쿼리 시 입력값 검증
- **진단 1**: 동적 쿼리 기능의 입력값 필터링 기능 구현 여부
  - 1-1 요구사항정의서·아키텍처설계서·요구사항추적표
  - 1-2 SQL 필터링 기능 설계 또는 외부 라이브러리 사용 → *프로그램명세서·클래스설계서·아키텍처설계서*
  - 1-3 공통 적용 시 DB 접근 모든 기능에 적용되도록 설계되었는지 확인
  - 1-4 SQL 필터링 코딩규칙의 개발가이드 정의 여부
- **진단 2**: 입력값의 쿼리 구조 변경 점검 테스트 계획 (②와 동일 입력값) → *단위테스트케이스*

## 시험 포인트
