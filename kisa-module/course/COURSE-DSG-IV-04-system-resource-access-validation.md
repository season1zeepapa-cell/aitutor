# 시스템 자원 접근 및 명령어 수행 입력값 검증 (COURSE-DSG-IV-04)

- **단원**: Ⅳ. 분석·설계 단계 보안약점 진단 > 보안설계 기준 및 설계 기준 실습

- **관련 진단가이드 항목**: DSG-IV-04

## 개요 — 설계기준과 보안대책

시스템 자원접근 및 명령어 수행을 위해 사용되는 입력값에 대한 유효성 검증방법과 유효하지 않은 값에 대한 처리방법을 설계해야 한다.

**2대 보안대책**
1. 외부입력값으로 시스템 자원(IP, PORT번호, 프로세스, 메모리, 파일 등)을 식별하는 경우 허가되지 않은 자원이 사용되지 않도록 해야 한다.
2. 서버 프로그램 안에서 쉘을 생성하여 명령어를 실행해야 하는 경우 외부입력값에 의해 악의적인 명령어가 실행되지 않도록 해야 한다.

## 설계 시 고려사항

### 시스템 자원접근
- 외부입력값이 리소스를 결정하는 데 직접 사용되지 않도록 설계. 사용 리소스 목록을 정의하여 지정된 범위 안에서 선택.
- 리소스 목록은 프로퍼티 파일이나 XML 파일로 정의하여 변경 시 프로그램 수정을 최소화.
- 디렉터리 내 모든 파일이라 목록화가 어려운 경우, 지정 경로 파일만 접근하도록 경로조작 문자(`.. / \`)를 제거하는 시큐어코딩 규칙 정의.

### 명령어 수행
- 쉘로 명령어가 실행되는 구조를 가지지 않도록 설계하는 것이 우선.
- 꼭 필요한 경우 외부입력값이 직접 명령어의 일부로 사용되지 않도록 함.
- 허용 값들을 목록화하여 목록 내 값으로만 명령어가 조립·실행되도록 함(프로퍼티/XML 파일). 외부입력값은 목록을 검색하는 **인덱스**로만 사용하여 정보 노출 최소화.

## 진단기준 및 방법

### 요구사항 ① 시스템 자원접근
- **진단 1**: 외부입력값이 자원 식별값으로 쓰일 때 허가된 자원에만 접근하도록 설계 적용 여부
  - 1-1 요구사항정의서·아키텍처설계서·요구사항추적표
  - 1-2 허가된 자원이 식별·기능과 매핑되어 있는지 → *아키텍처설계서·DB설계서*
  - 1-3 자원접근 이력 로그 기록 설계(시간·사용자ID·사용자IP·입력값, 권한 없는 접근 포함) → *아키텍처설계서·유즈케이스설계서·클래스설계서*
- **진단 2**: 허가되지 않은 자원 접근 점검 테스트 계획 → *단위테스트케이스*
  - **테스트 입력값**: 경로조작 문자 `.. / \` 등

### 요구사항 ② 명령어 수행
- **진단 1**: 외부입력값이 OS 명령어/파라미터로 쓰일 때 허가된 명령만 실행되도록 설계 적용 여부
  - 1-1 요구사항정의서·아키텍처설계서·요구사항추적표
  - 1-2 명령어 실행 기능 식별 + 실행 가능 명령어/파라미터 제한 설계 → *아키텍처설계서·클래스설계서·유즈케이스설계서*
  - 1-3 명령어 실행 이력 로그 기록(시간·사용자ID·사용자IP·입력값 + 실행 명령어·파라미터) → *아키텍처설계서·클래스설계서·개발가이드*
- **진단 2**: 허가되지 않은 명령어 실행 점검 계획 → *단위테스트케이스*
  - **검증 문자열**: `| & ;` 등

## 시험 포인트

- 관련 약점 4종: 코드 삽입 / 경로조작 및 자원삽입 / 서버사이드 요청 위조 / 운영체제 명령어 삽입
- 허용 목록은 프로퍼티·XML로 관리, 외부입력값은 인덱스 참조
- 경로조작 입력값 `.. / \` vs 명령어 삽입 검증 문자열 `| & ;`
- 로그 항목: 시간·사용자ID·사용자IP·입력값(권한 없는 접근도 기록)
