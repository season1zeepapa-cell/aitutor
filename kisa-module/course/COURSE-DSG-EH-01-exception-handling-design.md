# 예외처리 (COURSE-DSG-EH-01)

- 단원: Ⅳ. 분석·설계 단계 보안약점 진단
- 분류: 에러처리(error_handling)
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정, pp.242-250
- 관련 라이브러리: DSG-EH-01

## 개요

오류메시지에 중요정보(개인정보·시스템정보·민감정보)가 포함되어 출력되거나, 에러·오류가 부적절하게 처리되어 의도치 않은 상황이 발생하는 것을 막기 위한 안전한 방안을 설계한다.

- 명시적인 예외의 경우 예외처리 블럭을 이용하여 예외발생 시 수행해야 하는 기능이 구현되도록 함
- 런타임 예외의 경우 입력값의 범위를 체크하여 정상 동작 가능한 값만 사용되도록 보장
- 에러 발생 시 상세한 에러 정보가 사용자에게 노출되지 않게 함

관련 보안약점(에러처리): 오류 메시지 정보노출.

## 설계 시 고려사항

### 1) 명시적/런타임 예외

- 각 프로그래밍 언어별 예외처리 문법의 안전한 사용방법을 기술하여 개발가이드 구현단계 작성
- 예시(자바): 발생된 에러 정보를 로깅하는 Logger API 활용
- 런타임 예외: 입력값에 따라 예외 발생 가능한 경우 입력값 범위를 체크하여 사용

### 2) 상세 에러정보 비노출

- 에러 발생 시 프로그램 내에서 지정된 에러페이지로 리다이렉트하거나 WAS 설정으로 지정 페이지를 응답하도록 설계
- 예시: `web.xml`의 `<error-page>`로 404·500·`java.lang.Throwable` 등에 대해 지정 페이지 응답
- 오류메시지에 중요정보(개인정보·시스템정보·민감정보)가 포함되지 않도록 시큐어코딩 규칙 정의

## 진단 기준 및 방법

- 요구사항01(명시적 예외): Exception 유형별 처리방법 정의(시스템정보 미노출·반드시 처리·각각 분리 처리), Exception 로깅 정책(시간·이유 포함, 로그 내 중요정보 암호화), 안전한 예외처리 점검 테스트 계획 확인
- 요구사항02(런타임 예외): 입력데이터 유효 범위 검증으로 예외 미발생하도록 개발가이드 코딩규칙 정의, 예외상황 안전처리 점검 테스트 계획 확인
- 요구사항03(에러정보 비노출): 스택정보·중요정보 외부 미노출 코딩규칙, 지정 에러페이지 서버설정, 예외 로그 생성 서버설정, 상세정보 노출 점검 테스트 계획 확인

## 시험 포인트

- 명시적 예외는 예외처리 블럭으로 처리, 각 예외상황을 분리 처리
- 런타임 예외는 입력값 범위 검증으로 정상 값만 사용 보장
- 에러 발생 시 지정된 에러페이지(`web.xml <error-page>`)로 처리하여 상세정보 비노출
- 오류메시지에 중요정보(개인정보·시스템정보·스택정보) 미포함
- Exception 로그에는 시간·이유 포함, 로그 내 중요정보는 암호화
