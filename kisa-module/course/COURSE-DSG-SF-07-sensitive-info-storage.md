# 중요정보 저장 (COURSE-DSG-SF-07)

- 단원: Ⅳ. 분석·설계 단계 보안약점 진단
- 분류: 보안기능(security_feature)
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정, pp.229-235
- 관련 라이브러리: DSG-SF-07

## 개요

중요정보(비밀번호, 개인정보 등) 저장 시 안전한 저장 및 관리방법을 설계해야 한다.

- 중요정보 또는 개인정보는 암호화해서 저장
- 불필요하거나 사용하지 않는 중요정보가 메모리에 남지 않도록 함

관련 보안약점(보안기능): 암호화되지 않은 중요 정보, 사용자 하드디스크에 저장되는 쿠키를 통한 정보노출.

## 설계 시 고려사항

### 1) 중요정보 암호화 저장

- 중요정보가 다뤄지는 '안전영역'을 설정하고 해당 영역 외부로 누출되지 않도록 설계
- 서버 DB·파일에 저장되는 중요정보는 반드시 암호화하며 '암호연산' 설계항목의 안전한 알고리즘·키 정책 적용
- 쿠키, HTML5 로컬저장소 등 클라이언트 측 하드드라이브에 중요정보 저장 금지, 부득이한 경우 민감정보를 암호화
- HTML 코드는 사용자에게 공개되므로 중요 로직·주석처리는 서버측 언어에서만 처리

### 2) 메모리 잔존 방지

- 개인정보·금융정보 처리 시 필요 없는 데이터는 메모리를 0으로 초기화하여 잔존 방지 (시큐어코딩 규칙)
- 민감정보 페이지는 사용자 측 캐싱 비활성화(제한적 캐시정책), 부득이 캐싱 시 암호화 저장
- 인증정보 등 민감정보 입력 웹 폼은 자동완성 기능 비활성화

## 진단 기준 및 방법

- 요구사항01(암호화 저장)
  - 암호화 대상 중요정보·개인정보 분류 (개인정보보호법 고유식별정보·바이오정보·패스워드, 정보통신망법 주민번호·신용카드·계좌번호, 위치정보법 위치정보, 시스템 계정·설정정보)
  - 안전한 암호화 프로그램 또는 외부 암호 라이브러리 사용 설계, 암·복호화 코딩규칙 정의
  - 저장 중요정보 암호화 점검 테스트 계획 확인
- 요구사항02(메모리 잔존 방지)
  - 중요정보 사용 후 메모리 초기화 코딩규칙, 사용자 측 캐싱 방지 코딩규칙 정의
  - 메모리 잔존·캐싱 점검 테스트 계획 확인

## 시험 포인트

- DB·파일 저장 중요정보는 반드시 암호화('암호연산' 정책 적용)
- 쿠키·HTML5 로컬저장소 등 클라이언트 측 중요정보 저장 금지, 부득이 시 암호화
- 사용 후 메모리를 0으로 초기화하여 중요데이터 잔존 방지
- 민감정보 페이지는 캐싱 비활성화, 입력 폼은 자동완성 비활성화
- 암호화 대상 분류: 고유식별정보·바이오정보·패스워드·신용카드·계좌번호 등
