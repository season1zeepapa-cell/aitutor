## 요약

오류메시지나 스택 정보에 시스템 내부구조가 포함되어 민감한 정보·디버깅 정보가 노출되는 보안약점이다. 공격자는 에러 메시지로 시스템·관리자·DB 정보 등 중요정보를 얻어 추가 공격에 활용할 수 있다.

## 에러처리 보안약점 개요

- 에러를 처리하지 않거나, 불충분하게 처리하여 에러정보에 중요정보(시스템 등)가 포함될 때 발생할 수 있는 보안약점.
- 에러처리 분류 3종: 오류 메시지 정보 노출 / 오류 상황 대응 부재 / 부적절한 예외 처리.

## 개요 — 정의와 영향

- 오류메시지나 스택 정보에 시스템 내부구조가 포함되어 민감한 정보, 디버깅 정보가 노출되는 경우 발생한다.
- 공격자는 에러 메시지를 통해 프로그램 실행 중 발생된 상세한 오류 정보를 얻을 수 있으며, 이 정보는 공격에 활용될 수 있다.
- 오류 정보를 통해 시스템, 관리자, DB 정보 등 중요정보가 노출되어 공격자가 추가 공격에 활용할 수 있다.

## 대응 방안

- 에러 메시지는 에러 상황에 대해 간단한 에러 상태나 에러 상태 문자열을 정의하여 지정된 로그 파일에 로깅한다.
- 예외 발생 시 오류와 관련된 시스템 정보가 유출되지 않도록 `getMessage()` 사용을 금한다.
- 시스템 설정을 통해 오류 발생 시 디폴트 오류 페이지가 사용자에게 전달되도록 환경설정을 한다.

## 진단 흐름

1. 오류 메시지 출력 여부 확인 — 시스템 환경, 사용자 정보, 데이터 등 민감한 정보 포함 시 위험, 없으면 안전.
2. 오류 정보 등 상세 정보 생성 기능 확인 — `getMessage()` 등 민감정보 생성기능 존재 시 위험, 없으면 안전.

## 코드 비교 — 예제 1 (printStackTrace)

### 안전하지 않은 코드

```java
try {
    rd = new BufferedReader(new FileReader(new File(filename)));
} catch(IOException e) {
    // 에러 메시지로 스택 정보가 노출됨
    e.printStackTrace();
}   // 주석처리하면? → 4-2 오류 상황 대응 부재
```

### 안전한 코드

```java
try {
    rd = new BufferedReader(new FileReader(new File(filename)));
} catch(IOException e) {
    // 에러 코드와 정보를 별도로 정의하고 최소 정보만 로깅
    logger.error("ERROR-01: 파일 열기 에러");
} finally {
    try {
        rd.close();
    } catch (IOException ex) {
        logger.error("ERROR-02: 파일 닫기 에러");
    }
}
```

## 코드 비교 — 예제 2 (getMessage)

### 안전하지 않은 코드

```java
public void f() {
  try { g(); }
  catch (IOException e) {
      // 화면에 출력된 시스템 정보로 다른 공격의 빌미를 제공한다
      System.err.print(e.getMessage());
  }
}
```

### 안전한 코드

```java
public void f() {
  try { g(); }
  catch (IOException e) {
      // 에러 코드와 정보를 별도로 정의하고 최소 정보만 로깅
      logger.error("IOException Occured");
  }
}
```

## 시험 포인트

- 에러처리 보안약점 3종: 오류 메시지 정보 노출 / 오류 상황 대응 부재 / 부적절한 예외 처리
- 오류메시지·스택 정보에 시스템 내부구조·민감정보가 포함되면 추가 공격에 활용됨
- 대응: 간단한 에러 상태 문자열을 지정 로그 파일에 로깅, `getMessage()` 사용 금지, 디폴트 오류 페이지 설정
- 위험 코드: `e.printStackTrace()`, `System.err.print(e.getMessage())`
- 안전 코드: `logger.error("ERROR-01: ...")`처럼 에러코드와 최소 정보만 로깅
- 출력을 주석처리만 하면 4-2 오류 상황 대응 부재로 바뀜에 유의
