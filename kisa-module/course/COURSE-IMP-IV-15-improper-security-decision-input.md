# 보안기능 결정에 사용되는 부적절한 입력값

- **unit_code**: COURSE-IMP-IV-15
- **단원**: Ⅴ. 구현 단계 보안약점 진단 > 입력데이터 검증 및 표현
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정 (pp. 363-365)
- **관련 보안약점**: 입력 데이터 검증 및 표현 > 보안기능 결정에 사용되는 부적절한 입력값

## 요약

응용프로그램이 쿠키, 환경변수, 히든필드와 같은 입력값에 대한 신뢰를 전제로 보호 메커니즘을 구현하는 경우 발생한다.

## 공격 영향

- 공격자가 입력값을 조작하여 보호 메커니즘을 우회하거나 권한상승을 시도하여 허가되지 않은 시스템의 기능을 사용할 수 있다.

## 보안대책

1. 상태 정보, 민감한 데이터, 사용자 세션 정보와 같은 중요한 정보는 **서버에 저장**하고 보안 절차도 **서버에서 실행**한다.
2. 사용자 권한, 인증 여부 등 보안 결정에 사용하는 값은 사용자 입력값을 사용하지 않고 **내부 세션값**을 활용한다.

## 진단 흐름도

- 변수를 사용한 인증 여부 확인 기능에서, 세션 정보 등을 **서버 내부에서 검증**하면 → **안전**
- 서버 내부 검증을 미사용하면 → **위험**

## 안전한 코드 (서버 보유 값 사용)

```java
// 안전하지 않은 코드: 서버가 보유한 가격(단가)을 사용자 화면(히든필드)에서 받아 처리
price = request.getParameter("price");
quantity = request.getParameter("quantity");
total = quantity * Float.parseFloat(price);

// 안전한 코드: 서버가 보유한 가격정보(상수)를 이용하여 전체 가격을 계산
price = CONST_HDTV_UNIT_PRINCE;
quantity = request.getParameter("quantity");
total = quantity * Float.parseFloat(price);
```

> 보안 결정(단가 등)에 사용되는 값은 클라이언트 입력값이 아니라 서버 내부 값(상수·세션)을 사용해야 한다.

## 시험 포인트

- 쿠키·환경변수·히든필드 등 신뢰할 수 없는 입력값을 보호 메커니즘에 사용하면 우회·권한상승 발생
- 보안대책: 중요 정보(상태·민감 데이터·세션)는 서버에 저장하고 보안 절차도 서버에서 실행
- 권한·인증 여부 등 보안 결정값은 사용자 입력값이 아닌 내부 세션값 활용
- 안전한 코드: 단가를 히든필드(price) 대신 서버 상수(CONST_HDTV_UNIT_PRINCE)로 계산
