## 요약

C 언어에서 스택 메모리에 저장되는 지역변수는 생성 시 자동으로 초기화되지 않는데, 이 변수를 초기화 없이 사용하는 경우 발생하는 보안약점이다. 초기화되지 않은 스택 메모리 영역의 변수는 이전 함수에서 사용되었던 내용을 포함하고 있어, 공격자가 이를 이용해 메모리에 저장된 값을 읽거나 특정 코드를 실행할 수 있다. 모든 변수는 사용 전에 반드시 올바른 초기값을 할당해야 한다.

## 개요 — 정의·영향·대책

- **정의**: C 언어에서 스택 메모리에 저장되는 지역변수는 생성 시 자동으로 초기화되지 않는데, 이 변수를 사용하는 경우 발생한다.
- **영향**: 초기화되지 않은 스택 메모리 영역의 변수는 이전 함수에서 사용되었던 내용을 포함하고 있다. 공격자는 이러한 약점을 이용하여 메모리에 저장되어 있는 값을 읽거나 특정 코드를 실행할 수 있다.
- **대책**: 모든 변수는 사용 전에 반드시 올바른 초기값을 할당한다.
- **진단 흐름**: 변수 선언 → 초기화 여부(C++의 경우 생성자를 통해 객체의 필드를 초기화) 확인, 초기화되면 안전 / 아니면 위험

## 코드 예제 — switch 분기에서의 초기화

- **안전하지 않은 코드**: `int x, y;`로 초기값 없이 선언한 뒤 `switch(position)` 분기로 값을 할당한다. 변수의 초기값을 지정하지 않으면 공격에 사용될 수 있어 안전하지 않다.
- switch의 모든 분기가 x, y에 값을 할당하지 않으면(예: default가 x만 설정) 초기화되지 않은 채로 `setCursorPosition(x, y)`에 전달될 수 있다.
- **안전한 코드**: `int x=1, y=1;`로 선언 시점에 초기값을 지정한다. 변수의 초기값은 항상 지정하여야 한다.

## 시험 포인트

- C 언어 스택 지역변수는 생성 시 자동 초기화되지 않으므로 초기화 없이 사용하면 보안약점이 된다.
- 초기화되지 않은 변수는 이전 함수의 잔여 내용을 포함하여, 공격자가 메모리 값을 읽거나 특정 코드를 실행할 수 있다.
- 대책: 모든 변수는 사용 전에 반드시 올바른 초기값을 할당하며, C++는 생성자로 객체 필드를 초기화한다.
- 안전한 코드: `int x=1, y=1;`처럼 선언 시점에 초기값을 지정한다.
