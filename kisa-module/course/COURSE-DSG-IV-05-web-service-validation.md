# 웹 서비스 요청 및 결과 검증 (COURSE-DSG-IV-05)

- **단원**: Ⅳ. 분석·설계 단계 보안약점 진단 > 보안설계 기준 및 설계 기준 실습
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정, pp.129-135
- **관련 진단가이드 항목**: DSG-IV-05
- **관련 보안약점**: 입력 데이터 검증 및 표현 > 크로스사이트 스크립트(XSS)

## 개요 — 설계기준과 보안대책

웹 서비스(게시판 등) 요청(스크립트 게시 등)과 응답결과(스크립트 포함 웹 페이지 등)에 대한 검증방법과 적절하지 않은 데이터에 대한 처리방법을 설계해야 한다.

**2대 보안대책**
1. 사용자로부터 입력받은 값을 동적으로 생성되는 응답 페이지에 사용하는 경우 XSS 필터링을 수행한 뒤 사용해야 한다.
2. DB조회결과를 동적으로 생성되는 응답 페이지에 사용하는 경우 HTML 인코딩 또는 XSS 필터링을 수행한 뒤 사용해야 한다.

## 설계 시 고려사항

- **사용자 입력값 → 동적 응답 페이지**: 필터링 또는 인코딩 정책을 적용하는 공통코드를 웹컨테이너 또는 MVC 프레임워크에 적용.
  - 필터(Filter)를 이용한 입력값 검증
  - 인터셉터(Interceptor)를 이용한 입력값 검증
  - 라이브러리 또는 Validator 컴포넌트를 이용한 입력값 검증
- **DB조회결과 → 동적 응답 페이지**: View 컴포넌트에서 출력값에 HTML 인코딩 적용 + DB조회 결과값에 XSS 필터 적용.

## 진단기준 및 방법

### 요구사항 ① 사용자 입력값 XSS 필터링
- **진단 1**: 외부입력값의 XSS 공격코드 필터링 보안설계 적용 여부
  - 1-1 요구사항정의서·아키텍처설계서·요구사항추적표
  - 1-2 XSS 필터 컴포넌트 설계(외부 라이브러리 안전 필터링, **화이트 리스트 정책**) → *프로그램명세서·클래스설계서·유즈케이스설계서·아키텍처설계서*
  - 1-3 XSS 필터링 방법 정의(Filter 적용 대상이 웹 서버 설정파일에 정의, 개별 Controller·View 필터링 코딩규칙이 개발가이드에 정의) → *아키텍처설계서·개발가이드*
- **진단 2**: XSS 필터링 점검 테스트 계획 → *단위테스트케이스*
  - **테스트 입력값**: 필터 우회 입력값(`<IMG SRC="javascript:alert('XSS');">` 등), OWASP XSS Filter Evasion Cheat Sheet 참조

### 요구사항 ② DB조회결과 XSS 필터링
- **진단 1**: DB조회 결과의 XSS 공격코드 필터링 보안설계 적용 여부
  - 1-1 요구사항정의서·아키텍처설계서·요구사항추적표
  - 1-2 XSS 필터 컴포넌트 설계(화이트 리스트 정책) → *아키텍처설계서·프로그램명세서·클래스설계서·유즈케이스설계서*
  - 1-3 DB조회 결과에 XSS 필터 또는 HTML 인코딩 적용 코딩규칙의 개발가이드 정의 여부 → *아키텍처설계서·개발가이드*
- **진단 2**: DB조회 결과 XSS 필터링 점검 테스트 계획 → *단위테스트케이스*

## 시험 포인트

- 2대 대책 구분: 사용자 입력값 → XSS 필터링 / DB조회결과 → HTML 인코딩 또는 XSS 필터링
- 입력값 검증 3방식: 필터·인터셉터·Validator
- DB조회결과는 View 컴포넌트 HTML 인코딩 + XSS 필터
- XSS 필터 규칙은 안전한 화이트 리스트 정책
- 테스트는 필터 우회 입력값, OWASP XSS Filter Evasion Cheat Sheet 참조
