# 경로 조작 및 자원 삽입 (COURSE-IMP-IV-03)

- **단원**: Ⅴ. 구현 단계 보안약점 진단 > 입력데이터 검증 및 표현
- **유형**: 교재 카드 (course)
- **분류**: 입력 데이터 검증 및 표현 (input_validation)
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정, 310-314쪽
- **관련 진단 라이브러리**: IMP-IV-03

## 요약

검증되지 않은 외부입력값을 파일 및 서버의 시스템 자원에 접근하거나 식별에 이용하는 경우 발생하는 보안약점이다. 공격자가 입력값을 조작하여 보호된 자원에 임의 접근하거나 인증·인가를 우회하여 설정 파일을 열람·변경·실행할 수 있다. 외부입력값을 자원 식별자로 사용할 때 철저히 검증하고, 사용 가능 자원을 리스트로 제한하며, 경로순회 문자를 제거하는 필터를 적용한다.

## 개요 — 정의와 영향

- **정의**: 검증되지 않은 외부입력값을 파일 및 서버의 시스템 자원에 접근하거나 식별에 이용하는 경우 발생한다.
- **영향 ①**: 공격자는 입력값을 조작하여 시스템이 보호하는 자원에 임의로 접근할 수 있다.
- **영향 ②**: 공격자는 허용되지 않는 권한을 획득하거나, 인증·인가를 우회하여 설정에 관계된 파일을 열람·변경·실행할 수 있다.

## 보안대책

- 외부입력값을 자원의 식별자로 사용하는 경우, 철저히 검증을 수행한 후 사용한다.
- 사용자별 사용 가능한 자원을 사전에 리스트로 정의하여 사용 범위를 제한한다.
- 파일을 사용하는 경우, 파일명에 경로순회공격 위험이 있는 문자( `..` `/` `\` `"` )를 제거하는 필터를 이용한다.
- **진단 흐름**: 경로 생성 또는 자원 제어 기능에서 외부입력값 미사용이면 안전, 사용 시 입력값 필터링 또는 리스트를 통한 선택이 없으면 위험으로 판정한다.

## 코드 예제 핵심 — 경로순회 문자 제거

- **JSP 파일 다운로드**: 외부 입력 `fileName`을 검증 없이 `FileInputStream("C:/datas/" + fileName)`에 사용하면 위험하다. → 경로순회 문자(`.` `/` `\`)를 `replaceAll`로 제거한 뒤 파일 경로에 사용한다.
- **Java ShowHelp**: `args[0]`의 `helpFile`을 `safeDir`에 그대로 결합하면 위험하다. → 경로조작 문자열 포함 여부를 확인하고 정규식 `replaceAll`로 제거(조치)한 후 사용한다.
- 핵심은 안전한 기준 디렉터리(`safeDir` / `C:/datas`)는 유지하되, 파일명에서 `..` `/` `\` 등 상위 경로 이동 문자를 제거하는 것이다.

## 핵심 개념

| 용어 | 정의 |
| --- | --- |
| 경로 조작(Path Traversal) | 외부입력값으로 파일 경로를 조작하여 `../` 등으로 보호된 디렉터리·파일에 접근하는 공격 |
| 자원 삽입 | 검증되지 않은 외부입력값을 시스템 자원의 식별자로 사용해 임의 자원에 접근·제어하게 되는 약점 |
| 경로순회 문자 필터 | 파일명에서 `..` `/` `\` `"` 등 경로 이동 위험 문자를 제거하는 필터링 대책 |
| 자원 화이트리스트 | 사용자별 사용 가능한 자원을 사전에 리스트로 정의하여 접근 범위를 제한하는 방식 |

## 시험 포인트

- 경로 조작 및 자원 삽입은 검증되지 않은 외부입력값을 파일·시스템 자원 접근 또는 식별에 사용할 때 발생한다.
- 영향: 보호 자원 임의 접근 / 권한 획득·인증·인가 우회로 설정 파일 열람·변경·실행
- 보안대책 3가지: 외부입력값 자원 식별자 사용 시 검증 / 사용 가능 자원 리스트로 범위 제한 / 경로순회 문자( `..` `/` `\` `"` ) 제거 필터
- 안전한 코드는 기준 디렉터리는 고정하고 파일명에서 경로순회 문자를 `replaceAll`로 제거
