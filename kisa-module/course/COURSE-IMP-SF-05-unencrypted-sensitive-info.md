# 암호화되지 않은 중요정보 (COURSE-IMP-SF-05)

- 단계: Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려
- 항목: 2-5 암호화되지 않은 중요정보
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정 (pp.388-393)
- 관련 라이브러리 항목: IMP-SF-05

## 요약
프로그램에서 패스워드, 개인정보 등을 전송 시 암호화 또는 안전한 통신채널을 이용하지 않거나, 저장 시 암호화하지 않는 경우 발생하는 보안약점이다. 저장 파일·DB 유출 시 또는 네트워크 스니핑을 통해 인증정보·개인정보가 노출될 수 있다.

## 정의와 영향
- 정의: 패스워드·개인정보 등 전송 시 암호화 또는 안전한 통신채널을 이용하지 않거나, 저장 시 암호화하지 않는 경우 발생한다.
- 영향(저장): 저장된 파일이나 DB 정보 유출 시 중요 개인정보나 인증정보들이 유출될 수 있다.
- 영향(전송): 네트워크 스니핑(훔쳐보기)을 통해 암호화되지 않은 인증정보나 개인정보가 노출된다.

## 보안대책
- 민감한 데이터를 저장할 때는 반드시 평문이 아닌 암호화된 형태로 보관한다.
- 디스크나 메모리에 있는 민감한 데이터는 지울 때도 안전한 방식으로 삭제한다.
- 로그인은 반드시 HTTPS와 같은 안전한 통신 채널을 사용한다.
- 중요정보들은 안전하게 암호화하여 전송하거나 HTTPS와 같은 안전한 통신 채널을 사용한다.
- 쿠키로 전송되는 중요정보의 경우 HTTPS 통신으로만 값이 전달될 수 있도록 보안속성을 설정한다.

## 진단 흐름
- 중요정보 저장 또는 사용 시 암/복호화 절차가 없으면 위험, 있으면 알려진 취약 알고리즘 사용 여부를 확인(취약 알고리즘이면 위험, 아니면 안전).
- 중요정보 전송 시 암호화를 사용하지 않으면 위험, 사용하면 취약 알고리즘 여부 확인(취약이면 위험, 아니면 안전).
- HTTPS에서 쿠키 사용 기능 확인 — 보안속성 미설정이면 위험, 설정이면 안전.

## 안전하지 않은 코드 vs 안전한 코드 (저장)
- 안전하지 않은 코드: 입력받은 `pwd`를 평문 그대로 `stmt.setString(2, pwd)`로 customer 테이블에 INSERT하여 DB에 평문 저장한다.
- 안전한 코드: `MessageDigest.getInstance("SHA-256")`로 솔트값(salt)을 포함해 패스워드를 해시(`digest.update(salt); digest.digest(...)`)한 뒤 저장한다.
- 핵심: 패스워드 등 민감정보는 솔트를 포함한 SHA-256 해시로 변환하여 저장한다.

## 안전하지 않은 코드 vs 안전한 코드 (전송)
- 안전하지 않은 코드: 소켓으로 `password`를 평문 그대로 `o.write(password)` 전송한다.
- 안전한 코드: `Cipher.getInstance("AES/CBC/PKCS5Padding")`으로 암호화한 `encPassword`를 `o.write(encPassword, 0, encPassword.length)`로 전송한다.
- 핵심: 중요정보 전송 시 AES 등 강력한 알고리즘으로 암호화하거나 안전한 통신채널(HTTPS)을 사용한다.

## 시험 포인트
- 약점 정의: 중요정보 전송 시 암호화/안전채널 미사용 또는 저장 시 미암호화
- 영향: (저장) 파일·DB 유출 시 노출, (전송) 네트워크 스니핑으로 노출
- 보안대책: 저장 시 암호화 보관, 안전 삭제, 로그인은 HTTPS, 전송 암호화/HTTPS, 쿠키는 HTTPS 전용 보안속성
- 안전한 저장 코드: SHA-256 + 솔트로 해시 후 저장
- 안전한 전송 코드: AES/CBC/PKCS5Padding으로 암호화 후 전송
