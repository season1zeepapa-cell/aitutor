# 비밀번호 관리 (COURSE-DSG-SF-03)

- 단원: Ⅳ. 분석·설계 단계 보안약점 진단 — 보안기능
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정, pp.185-200
- 관련 라이브러리: DSG-SF-03
- 관련 보안약점: (보안기능) 하드코드된 중요정보, 취약한 비밀번호 허용

## 개요
안전한 비밀번호 조합규칙(길이·허용문자 조합 등)을 설정하고, 안전한 저장 정책, 재설정·변경 정책, 패스워드 관리규칙(주기적 변경 등)이 적용되도록 설계해야 한다.

- 패스워드 설정 시 KISA 『패스워드 선택 및 이용 안내서』의 생성 규칙을 적용해야 한다.
- 네트워크를 통해 패스워드 전송 시 반드시 암호화하거나 암호화된 통신 채널을 이용해야 한다.
- 패스워드 저장 시 솔트가 적용된 안전한 해쉬함수를 사용해야 하며, 해쉬함수 실행은 서버에서 해야 한다.
- 패스워드 재설정/변경 시 안전하게 변경할 수 있는 규칙을 정의해서 적용해야 한다.
- 패스워드 관리 규칙을 정의해서 적용해야 한다.

## 설계 시 고려사항

### 1. 패스워드 생성 규칙 (KISA 안내서)
| 구분 | 안전한 비밀번호 | 안전하지 않은 비밀번호 |
| --- | --- | --- |
| 설명 | 두 종류 이상의 문자 구성 + 8자리 이상(문자 종류는 대·소문자·특수문자·숫자 등 4가지), 또는 10자리 이상 길이. ※숫자로만 구성 시 취약 | 특정 패턴(동일 문자 반복 '123123', 키보드 연속 'qwerty', 숫자가 앞·뒤 '1security'), 개인정보(가족·이름·생일·주소·전화번호) 기반, 이용자 ID 이용('kisa'→'kisa1'), 사전적 단어('바다나라','love12'), 특정 인물·널리 알려진 단어, 문자 치환(O→0, I→1), 시스템 초기/예제 비밀번호, 한글↔영문 발음 변환 |

### 2. 패스워드 전송 시 암호화
- 공중망에서 패스워드 송·수신 시 TLS·VPN 등 통신 암호기술 적용.
- TLS·솔루션 도입 시 표준 준수·상호호환성·검증 제품·오픈소스 여부 확인.

### 3. 패스워드 저장 (솔트 적용 해쉬함수, 서버 실행)
- 복호화되지 않는 일방향 해쉬함수로 암호화 저장.
- SHA-2 계열(SHA-224/256/384/512), SHA-3 계열 사용.
- 랜덤 생성 솔트값 사용, 솔트값은 데이터 암·복호화 암호키가 저장되는 장소에 저장.
- 해쉬함수를 이용한 일방향 암호화는 서버에서 수행.

### 4. 패스워드 재설정/변경 규칙
- 변경: 주기적 변경(일반 3~6개월 이하), 노출 시 즉시 변경, 이전과 연관성 없는 새 패스워드.
- 재설정: '패스워드 찾기' 시 이메일·휴대전화·질의 답변 검증으로 권한 확인, 등록 이메일로 재설정 링크 전송.

### 5. 패스워드 관리 규칙
- 변경주기: 3개월(또는 6개월)마다 주기적 변경.
- 만료기간 설정: DB에 개인정보 변경주기 추가, 일단위 업데이트, 만료 시 로그인 시 변경 요청, 변경 시 초기화.
- 성공한 로그인 시간 관리: 마지막 성공 로그인 시간 저장·통지로 계정 도용 점검.

## 진단 기준 및 방법 (요구사항 01~05)
- 01 패스워드 설정 규칙(문자구성·길이, 특정 정보·패턴 조건, 기타 조건) 안전 정의 — 길이 최소 8자리 이상, 숫자·영어 대·소문자·특수문자 조합, 전화번호·동일 문자열 반복 제한. 규칙 위배 입력값 점검 테스트 계획.
- 02 네트워크 전송 패스워드 암호화(안전한 암호알고리즘) 또는 TLS·VPN 채널 사용, 패킷 스니핑 점검 테스트 계획.
- 03 솔트 적용 SHA-2/SHA-3 해쉬함수로 암호화, 솔트값은 암호키 저장 장소에 저장, 일방향 암호화 서버 실행, 패스워드 크랙 도구 점검 테스트 계획.
- 04 변경 시 기존 패스워드 확인·설정 규칙 적용, 재설정 시 안전한 본인인증(휴대전화·인증서·신용카드) 후 등록 이메일 링크 전송, 본인인증 우회·직접 접근 점검 테스트 계획.
- 05 변경주기·만료기간·성공 로그인 시간 관리 규칙 설계, 패스워드 최종변경일·만료기간·변경주기 정보 관리, 정책 적용 점검 테스트 계획.

> 모든 요구사항의 1-1 진단방법은 공통: 요구사항정의서 대책 + 아키텍처설계서 적용계획 + 요구사항추적표 추적 가능 여부 확인.

## 시험 포인트
- 안전한 비밀번호: 2종 이상 문자+8자리 이상 또는 10자리 이상. 숫자로만 구성 시 취약.
- 패스워드 전송 시 안전한 암호알고리즘 또는 TLS·VPN 암호화 통신채널 사용.
- 패스워드 저장은 솔트 적용 + 일방향 해쉬함수(SHA-2/SHA-3), 해쉬 실행은 서버에서.
- 솔트값은 암호키가 저장되는 장소에 저장.
- 변경주기 3~6개월, 변경 시 이전 패스워드와 연관성 없어야 하며 기존 패스워드 확인.
- 재설정 시 안전한 본인인증(휴대전화·인증서·신용카드) 후 등록 이메일 링크 전송.
