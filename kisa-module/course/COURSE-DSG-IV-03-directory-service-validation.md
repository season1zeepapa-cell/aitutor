# 디렉토리 서비스 조회 및 결과 검증 (COURSE-DSG-IV-03)

- **단원**: Ⅳ. 분석·설계 단계 보안약점 진단 > 보안설계 기준 및 설계 기준 실습
- **출처**: 2025년 SW보안약점 진단원 기본(양성)과정, pp.119-122
- **관련 진단가이드 항목**: DSG-IV-03
- **관련 보안약점**: 입력 데이터 검증 및 표현 > LDAP 삽입

## 개요 — 설계기준과 보안대책

디렉터리 서비스 조회(LDAP 등) 시 사용되는 입력값과 조회결과에 대한 검증방법(필터링 등)을 설계하고, 유효하지 않은 값에 대한 처리방법을 설계해야 한다.

**보안대책**: LDAP 인증서버를 통해 인증을 구현하는 경우, 인증요청을 위해 사용되는 외부입력값은 LDAP 삽입 취약점을 가지지 않도록 필터링해서 사용해야 한다.

## 설계 시 고려사항

- LDAP 인증이 포함되는 기능 설계 시, 외부입력값이 LDAP 조회를 위한 검색 필터 생성에 삽입되어 사용되는 경우, 필터에서 인식 가능한 특수문자(`= + < > # ; \`)들을 제거하고 사용할 수 있도록 시큐어코딩 규칙을 정의해야 한다.

## 진단기준 및 방법 (요구사항 01)

> LDAP 인증서버 인증 구현 시 인증요청에 사용되는 외부입력값은 LDAP 삽입 취약점을 가지지 않도록 필터링해서 사용해야 한다.

- **진단 1**: 외부입력값이 LDAP 필터생성에 삽입될 때 안전하게 사용되도록 보안설계 적용 여부
  - 1-1 요구사항정의서 대책 + 아키텍처설계서 적용계획 + 요구사항추적표 추적 → *요구사항정의서·요구사항추적표·아키텍처설계서*
  - 1-2 LDAP 조회필터 입력값 필터링 기능 설계 또는 안전한 외부 라이브러리 사용 → *프로그램명세서·컴포넌트설계서·유즈케이스설계서·클래스설계서*
  - 1-3 LDAP 필터링 적용 코딩규칙의 개발가이드 정의 여부 → *개발가이드*
- **진단 2**: LDAP 삽입 취약점 점검 테스트 계획 → *단위테스트케이스*
  - **테스트 입력값**: `= + < > # ; \` 등

## 시험 포인트

- 관련 약점: LDAP 삽입
- LDAP 삽입 유발/테스트 특수문자: `= + < > # ; \`
- 외부입력값이 검색 필터 생성에 삽입될 때 특수문자 제거 시큐어코딩 규칙
- 진단방법-관련산출물 짝 매핑
