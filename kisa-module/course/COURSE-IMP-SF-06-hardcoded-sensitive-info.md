# 하드코드된 중요정보 (IMP-SF-06)

> 2025년 SW보안약점 진단원 기본(양성)과정 — Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려 2-6 (pp.394-399)

## 요약

프로그램 코드 내부에 비밀번호나 암호화 키 등 중요정보를 하드코딩하면 관리자 정보가 노출되거나, 실행파일 역컴파일을 통해 키가 유출되어 암호화된 정보가 복호화될 수 있다. 비밀번호와 키는 암호화하여 별도 파일이나 DB의 안전한 위치에 저장하고, 사용 시 복호화하여 사용해야 한다.

## 정의 — 약점이 발생하는 경우

- 프로그램 코드 내부에 비밀번호를 하드코딩하는 경우
- 암호화에 사용되는 키를 소스코드에 하드코딩하여 암호화를 수행하는 경우

## 위협

- 하드코드된 비밀번호를 내부 인증/외부 컴포넌트 통신에 사용 시 관리자 정보 노출
- 하드코드된 비밀번호가 인증 실패를 야기하면 원인 파악이 어려움
- 실행파일 유출 → 역컴파일로 암호화 키 유출 → 암호화된 중요정보 복호화에 악용

## 대책

- 비밀번호는 암호화하여 별도의 파일이나 DB에 안전하게 저장하여 사용
- 디폴트 패스워드 대신 '최초 로그인' 모드로 사용자가 직접 패스워드 입력하도록 설계
- 암호화 키는 암호화하여 안전한 별도의 위치에 저장

## 진단 흐름

1. 식별/인증 요청 기능 확인 → 소스 내 하드코딩 정보 없으면 안전, 있으면 위험
2. DB 접속 등 패스워드 사용 로직 확인 → 암호화 여부 '아니오'면 위험
3. 암호화된 경우라도 소스 내 암호화된 패스워드 존재 여부 확인 → 소스 내 없으면 안전

## 코드 예시

### 비밀번호 하드코딩

- 안전하지 않은 코드: `private static final String PASS = "TIGER";` (평문 저장)
- 안전한 코드: `props.getProperty("EncryptedPswd")`로 읽어 `cipher.doFinal`로 복호화 후 사용

### 암호화 키 하드코딩

- 안전하지 않은 코드: `String key = "22df3023sf~2;asn!@#/>as";` (소스 내부 사용)
- 안전한 코드: `getPassword("./password.ini")`로 읽어 `decrypt(key)`로 복호화 후 사용

## 시험 포인트

- 약점: 비밀번호 또는 암호화 키를 소스코드에 하드코딩
- 위협: 관리자 정보 노출 / 인증 실패 원인 파악 곤란 / 역컴파일로 키 유출 후 복호화 악용
- 대책: 암호화하여 별도 파일·DB 저장 + 사용 시 복호화, 디폴트 패스워드 대신 최초 로그인 모드
