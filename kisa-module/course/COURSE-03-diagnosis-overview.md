# COURSE-03 · Ⅲ. SW보안약점 진단의 이해

> **유형** 교육자료 (양성과정 교재) · **출처** 2025년 SW보안약점 진단원 기본(양성)과정 (p.46–85)

## 개요

SW보안약점 **진단원의 역할·자격기준**과 관련 법규(지침 제2조·제53조·제54조), **분석·설계단계 / 구현단계 진단 절차**와 단계별 진단원 역할, 진단 범위·점검 기준(설계 20개·구현 49개 항목), 인증 진단도구 사용 제약, 감리법인과의 관계를 학습한다.

## 1. 진단원의 역할·자격·교육

- **정의**(지침 제2조 14호): 보안약점이 남아있는지 진단하여 **조치방안 수립·조치결과 확인** 등을 수행하는 자
- **역할**: 분석·설계 산출물의 보안설계 항목 식별·반영 진단(안전한 설계 지원) + 구현 소스코드 보안약점 검출·대응방법 제시(보안성 강화), **감리법인 소속**으로 수행
- **자격기준(별표4 제1호)**

| 구분 | 자격기준 |
|------|------|
| **기본요건** | SW 개발 6년 이상 **또는** 보안약점·취약점 진단·분석 3년 이상 |
| **교육요건** | 기본요건 만족 + 제2호 기본교육 이수 |

- **교육(별표4 제2호)**: 기본교육 **40시간(5일)**, 보수교육 **1년마다 8시간**. 보수교육 미이수 시 차년도부터 **자격정지**

> 📌 시험: 진단원 정의·자격(6년/3년)·교육시간(기본40h·보수8h) 단골 출제

## 2. 관련 법규·제도와 진단 대상·범위·기준

- **근거**: 구축·운영 지침 **제50~54조**, 모바일 전자정부 서비스 관리 지침 제26조 (전자정부법)
- **대상**: 정보시스템 감리 대상 정보화사업(시행령 제71조 2항) + 모바일 서비스, 단계적 확대
- **범위**: 설계 산출물 및 소스코드 **전체**(신규 전체 + 유지보수 변경분), **상용 SW 제외**
- **기준(별표3)**

| 구분 | 항목 수 |
|------|------|
| 설계단계 보안설계 기준 | **20개** (4개 영역) |
| 구현단계 보안약점 제거 기준 | **49개** (7개 영역) |
| 모바일 앱 보안약점 점검기준 | 26개 |

**제53조(보안약점 진단절차)** — 5개 항
1. 감리 시 감리법인이 별표3 SW 보안약점 제거 여부 진단
2. 감리기준 제10조1항 세부검사항목에 보안약점 제거 여부 포함
3. 감리기준 제5조3항에 따라 **제54조 진단원 우선 배치** 가능
4. 인증된 진단도구 사용(별표3 진단 여부 확인)
5. 영 제71조1항 비해당 사업도 진단·제거 결과 확인 가능

## 3. 분석·설계단계 진단 절차와 진단원 역할

**절차: 착수 → 진단 → 보고서 작성/제출 → 종료** (감리법인·개발기관 공동)

- **착수**: 착수회의에서 진단 목적·적용기준·진단항목·일정 공유, 필요 산출물 요청
- **진단**: 산출물 접수·검토 → 보안약점 진단·개선방안 도출 → **공동리뷰** → 개선방안 확정 (객관적 근거 필요)
- **보고서**: 초안 작성 → 공동리뷰(사실 여부·증적·개선일정) → 최종 제출 (진단원·기간·기준·대상범위·개선방안 명시)
- **비용효과**: 설계 미반영 시 구현단계 **5배**, 출시 이후 **30배** 추가 비용. 설계 시 XSS 등 공통모듈로 일관성 방어

## 4. 구현단계 진단 절차와 진단도구

**절차: 1차 진단 → 보안약점 제거 → 2차 진단(이행점검, 필요시 3차+) → 종료**

- **1차 진단보고서**: 검출 **파일명·라인번호·보안약점명·원인설명·대응방법** 포함
- **2차 진단보고서**: 1차 검출 보안약점의 **제거 여부** 추가, 종료단계에서 1·2차 결과 요약 보고
- **진단도구**: 자동화 도구 미탐 최소화를 위해 **수동진단 병행**, 오탐은 제외처리하고 제외사유 근거 마련
- **개발사**: 인증 도구 의무 없음 → OWASP ZAP·SpotBugs·FindSecBugs 등 사용, **2개 이상 도구 병행** 권장

## 5. 진단도구 인증과 CC·EAL

- **인증 진단도구 3가지(제53조④)**: ①국가보안기술연구소장 인증(CC인증) ②한국인터넷진흥원장 확인 ③국정원 보안기능 확인서 발급
- **CC인증**: 정보보호시스템 보안기능·보증 요구사항 평가 국제 기준. 국제용은 CCRA 가입국 상호 인정

| CC 구성요소 | 내용 |
|------|------|
| **TOE** | 인증·평가의 직접 대상인 보안제품 |
| **PP** | 공통평가기준 (Protection Profile) |
| **ST** | 특정제품의 보안기능 평가기준 자료 |

- **EAL(평가보증등급)**: EAL1(기능적시험) ~ EAL7(정형화된 설계검증·시험). 진단도구는 **EAL2 이상** 사용

## 🎯 시험 출제 포인트

1. 진단원 정의: 보안약점 진단 → 조치방안 수립 → 조치결과 확인 (제2조 14호)
2. 자격 기본요건: SW 개발 6년 이상 **또는** 보안약점·취약점 진단·분석 3년 이상
3. 교육: 기본 40시간(5일), 보수 1년마다 8시간, 미이수 시 자격정지
4. 진단 기준: 설계 **20개**·구현 **49개**·모바일 26개 (모두 별표3), 상용 SW 제외
5. 분석·설계 절차: 착수→진단→보고서 작성/제출→종료 (공동리뷰)
6. 구현 절차: 1차→제거→2차(이행점검)→종료, 1차 보고서 5요소(파일·라인·약점명·원인·대응)
7. 진단도구 CC인증(EAL2 이상)·수동진단 병행, CC 구성요소 TOE·PP·ST
