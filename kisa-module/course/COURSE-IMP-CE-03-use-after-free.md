## 요약

C나 C++ 프로그램처럼 메모리 해제를 개발자가 수행하는 경우, 해제된 자원을 다시 해제(이중 해제)하거나 해제된 자원을 사용할 때 발생하는 보안약점이다. 해제한 메모리를 참조하면 예상치 못한 값이나 코드를 실행하게 되어 오류나 비정상 실행이 될 수 있다. 메모리 해제 후 포인터에 NULL 값을 저장하면 예상치 못한 코드의 실행을 막을 수 있다.

## 개요 — 정의·영향·대책

- **정의**: C나 C++ 프로그램처럼 메모리 해제를 개발자가 수행해야 하는 경우, 해제된 자원을 (다시) 해제하거나 해제된 자원을 사용하는 경우 발생한다.
- **영향**: 해제한 메모리를 참조하게 되면 예상치 못한 값 또는 코드를 실행하게 되어 오류나 비정상 실행이 될 수 있다.
- **대책 ①**: 동적으로 할당된 메모리를 해제한 후, 그 메모리를 참조하던 포인터를 참조 추적·형 변환·수식의 피연산자 등으로 사용하여 해제된 메모리에 접근하지 않도록 한다.
- **대책 ②**: 메모리 해제 후 포인터에 NULL 값을 저장하거나 다른 적절한 값을 저장하면 예상치 못한 코드의 실행을 막을 수 있다.
- **진단 흐름**: 자원 해제 확인 → 중복 해제 또는 해제된 자원에 접근하면 위험 → 포인터 변수인 경우 NULL 배정 여부, 배정하면 안전 / 아니면 위험

## 코드 예제 ① — 해제 후 사용(Use-After-Free)

- **안전하지 않은 코드**: `malloc()`으로 temp를 할당하고 `free(temp)`로 해제한 뒤, 해제한 자원에 `strncpy(temp, argv[1], BUFFER_SIZE-1)`를 수행하여 의도하지 않은 결과가 발생한다.
- **안전한 코드**: 할당된 자원을 최종적으로 사용(strncpy)한 뒤 마지막에 `free(temp)`로 해제한다. 즉 사용을 끝낸 후에 해제한다.

## 코드 예제 ② — 이중 해제(Double Free) 방지

- **안전하지 않은 코드**: `data_type==val_1`일 때 `free(data)` 후, `data_type==val_2` 분기에서 다시 `free(data)`를 호출하여 이미 해제된 자원을 이중 해제해 문제가 발생한다.
- **안전한 코드**: 동적 할당 포인터를 해제한 후 `data = NULL`로 설정하여 동일 메모리에 대해 한 번만 해제하도록 한다. 해제 후 NULL을 할당하면 이중 해제하더라도 무시된다.

## 핵심 개념

| 용어 | 정의 |
| --- | --- |
| 해제된 자원 사용(Use-After-Free) | 해제된 메모리를 가리키는 포인터로 다시 접근·사용하여 예상치 못한 값이나 코드 실행을 유발하는 보안약점 |
| 이중 해제(Double Free) | 이미 해제된 동일 메모리를 다시 free하여 발생하는 문제. 해제 후 포인터에 NULL을 할당하면 이중 해제가 무시되어 방지된다 |
| 해제 후 NULL 배정 | 메모리 해제 직후 포인터에 NULL(또는 적절한 값)을 저장하여 해제된 메모리 접근과 이중 해제를 막는 방어 기법 |

## 시험 포인트

- 해제된 자원 사용은 C/C++처럼 개발자가 메모리를 해제하는 환경에서 해제된 자원을 사용하거나 이중 해제할 때 발생한다.
- 영향: 해제한 메모리를 참조하면 예상치 못한 값 또는 코드가 실행되어 오류·비정상 실행이 된다.
- 대책: 자원은 최종 사용 후 해제하고, 해제 후 포인터에 NULL을 저장하여 이중 해제와 해제 후 접근을 방지한다.
- 이중 해제 방지의 핵심은 free 직후 `data = NULL;` 할당이다.
