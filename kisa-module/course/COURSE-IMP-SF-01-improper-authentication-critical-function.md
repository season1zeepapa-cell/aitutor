# 적절한 인증 없는 중요기능 허용 (COURSE-IMP-SF-01)

- 단계: Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려
- 항목: 2-1 적절한 인증 없는 중요기능 허용
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정 (pp.375-377)
- 관련 라이브러리 항목: IMP-SF-01

## 요약
적절한 인증과정 없이 패스워드, 개인정보, 금융정보와 같은 중요정보를 열람 또는 변경하는 경우 발생하는 보안약점이다. 권한 없는 사용자가 중요기능을 사용하거나 주요 정보를 변조할 수 있다.

## 정의와 영향
- 정의: 적절한 인증과정 없이 패스워드·개인정보·금융정보와 같은 중요정보를 열람 또는 변경하는 경우 발생한다.
- 영향: 권한 없는 사용자가 중요기능을 사용하거나 주요 정보를 변조할 수 있다.

## 보안대책
- 클라이언트가 보안검사를 우회하여 서버에 접근하지 못하도록 설계한다.
- 중요한 정보가 있는 페이지에 접근하는 경우 재인증을 적용한다.
- 안전하다고 확인된 라이브러리나 프레임워크(OpenSSL, ESAPI의 보안기능 등)를 사용한다.

## 진단 흐름
- 중요 정보 및 기능 사용 여부를 먼저 확인한다.
- 사용하지 않으면 안전, 사용하면 접근/변경 시 인증 여부를 확인한다.
- 인증을 거치면 안전, 인증 없이 접근/변경이 가능하면 위험으로 판정한다.

## 안전하지 않은 코드 vs 안전한 코드 (회원정보 수정)
- 안전하지 않은 코드: 세션의 `userId`로 패스워드만 확인(`loginService.checkUserId`)한 뒤, 실제 수정 대상 사용자와 로그인 사용자의 일치 여부를 확인하지 않고 `service.modifyMember()`로 회원정보를 수정한다.
- 안전한 코드: `memberModel.getUserId()`로 `requestUser`를 얻어, 세션 `userId`와 `requestUser`가 동일한지 먼저 검증(`!userId.equals(requestUser)`이면 차단)한 후 패스워드 확인 및 수정을 수행한다.
- 핵심: 인증(로그인 여부)만이 아니라 '실제 수정하는 사용자 == 로그인 사용자' 여부까지 확인해야 한다.

## 시험 포인트
- 약점 정의: 적절한 인증 없이 패스워드·개인정보·금융정보 등 중요정보를 열람/변경하는 경우
- 영향: 권한 없는 사용자가 중요기능 사용 또는 주요 정보 변조
- 보안대책 3가지: 클라이언트 보안검사 우회 차단, 중요 페이지 접근 시 재인증, 검증된 라이브러리/프레임워크(OpenSSL·ESAPI) 사용
- 안전한 코드 핵심: 로그인 사용자(userId)와 실제 수정 대상 사용자(requestUser)의 일치 여부를 확인한 뒤 수정 수행
