# XML 조회 및 결과 검증 (COURSE-DSG-IV-02)

- **단원**: Ⅳ. 분석·설계 단계 보안약점 진단 > 보안설계 기준 및 설계 기준 실습

- **관련 진단가이드 항목**: DSG-IV-02
- **관련 보안약점**: 입력 데이터 검증 및 표현 > XML 삽입, 부적절한 XML 외부개체 참조

## 개요 — 설계기준과 보안대책

XML 조회를 위한 질의문(XPath, XQuery 등) 생성 시 사용되는 입력값과 조회결과에 대한 검증방법(필터링 등)을 설계하고, 유효하지 않은 값에 대한 처리방법을 설계해야 한다.

**보안대책**: XML문서를 조회하는 기능을 구현하는 경우 XML쿼리에 사용되는 파라미터는 반드시 XML쿼리를 조작할 수 없도록 필터링해서 사용하거나, 미리 작성된 쿼리문에 입력값을 자료형에 따라 바인딩해서 사용해야 한다.

## 설계 시 고려사항

- **공통 검증 컴포넌트를 이용한 입력값 필터링**: XML삽입 공격이 가능한 문자열을 필터링하는 Validator 컴포넌트를 개발하여 일괄 적용되도록 설계.
- **필터 컴포넌트를 이용한 입력값 필터링**: Filter 컴포넌트에서 XML 삽입이 실행될 수 있는 입력값(`" [ ] / = @` 등)을 필터링하여 프레임워크에서 일괄 적용.
- **개별 코드에서 입력값 필터링 시큐어코딩 규칙**: 각 컴포넌트에서 XML삽입 유발 문자열(`" [ ] / = @` 등)을 제거 또는 안전하게 치환.
- **안전한 API 사용 시큐어코딩 규칙**: XML 조회 쿼리문 작성 시 외부입력값이 쿼리문 구조를 바꿀 수 없는 API(예: Java API - XQuery)를 사용.

## 진단기준 및 방법 (요구사항 01)

> XML쿼리 파라미터는 XML쿼리를 조작할 수 없도록 필터링하거나, 미리 작성된 쿼리문에 입력값을 자료형에 따라 바인딩해서 사용해야 한다.

- **진단 1**: 외부입력값이 조회 구문을 변경하지 않도록 보안 설계 적용 여부
  - 1-1 요구사항정의서 대책 + 요구사항추적표 추적 → *요구사항정의서·요구사항추적표·아키텍처설계서*
  - 1-2 안전한 필터링 기능 설계 또는 안전한 외부 라이브러리 사용 → *프로그램명세서·컴포넌트설계서·유즈케이스설계서·클래스설계서*
  - 1-3 XML 필터링 코딩 규칙·안전한 API 설명의 개발가이드 정의 여부 → *개발가이드*
- **진단 2**: XML 삽입 취약점 점검 테스트 계획 → *단위테스트케이스*
  - **테스트 입력값**: 쿼리예약어, `" [ ] / = @` 등

## 시험 포인트

- 보안대책 2갈래: 조작 불가 필터링 / 자료형에 따른 바인딩
- 설계 고려사항 4가지: 공통 검증 컴포넌트 / 필터 컴포넌트 / 개별 코드 시큐어코딩 / 안전한 API
- XML 삽입 유발 문자: `" [ ] / = @`
- 관련 약점: XML 삽입 + 부적절한 XML 외부개체 참조
