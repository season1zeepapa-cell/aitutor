# 중요한 자원에 대한 잘못된 권한 설정 (COURSE-IMP-SF-03)

- 단계: Ⅴ. 구현 단계 보안약점 진단 > 보안기능 항목에 대한 고려
- 항목: 2-3 중요한 자원에 대한 잘못된 권한 설정
- 출처: 2025년 SW보안약점 진단원 기본(양성)과정 (pp.380-382)
- 관련 라이브러리 항목: IMP-SF-03

## 요약
소프트웨어가 중요한 보안관련 자원에 대해 읽기 또는 수정 권한을 의도하지 않게 허가하는 경우 발생하는 보안약점이다. 인가되지 않은 사용자가 자원을 사용할 수 있다.

## 정의와 영향
- 정의: 소프트웨어가 중요한 보안관련 자원에 대해 읽기 또는 수정 권한을 의도하지 않게 허가하는 경우 발생한다.
- 영향: 인가되지 않은 사용자가 자원을 사용할 수 있다.

## 보안대책
- 설정 파일, 실행파일, 라이브러리 등은 SW 관리자만 읽고 쓸 수 있도록 설정한다.
- 허가 받지 않은 사용자가 중요한 자원에 접근 가능한지 검사한다.

## 진단 흐름
- SW에서 중요 자원 생성 여부를 확인한다.
- 읽기·쓰기·실행 권한이 사전 정의되어 있는지 확인한다 — 정의되어 있지 않으면 위험.
- 사전 정의 권한에 맞는 접근 권한 허용을 확인하고, 문서/설정 파일에 실행권한이 설정되어 있으면 위험, 없으면 안전으로 판정한다.

## 안전하지 않은 코드 vs 안전한 코드 (파일 권한 설정)
- 안전하지 않은 코드: `system.ini` 파일에 `setExecutable(true,false)`·`setReadable(true,false)`·`setWritable(true,false)`로 모든 사용자에게 실행/읽기/쓰기 권한을 허용한다.
- 안전한 코드: `setExecutable(false)`·`setReadable(true)`·`setWritable(false)`로 소유자에게만 읽기 권한을 허용하고 실행/쓰기 권한을 금지한다.
- API 참고: `setExecutable(허용여부, ownerOnly)` — ownerOnly=false는 모든 사용자 대상, true(또는 1-인자형 기본)는 소유자 한정.

## 시험 포인트
- 약점 정의: 중요 보안관련 자원에 읽기/수정 권한을 의도하지 않게 허가하는 경우
- 영향: 인가되지 않은 사용자가 자원을 사용
- 보안대책: 설정파일·실행파일·라이브러리는 SW 관리자만 읽기/쓰기 가능하게 설정, 비인가 접근 가능 여부 검사
- 안전한 코드 핵심: `setExecutable(false)`/`setReadable(true)`/`setWritable(false)` — 소유자에게만 읽기, 실행·쓰기 금지
- API: `setExecutable(허용여부, ownerOnly)` — ownerOnly=false면 모든 사용자에게 적용되어 위험
