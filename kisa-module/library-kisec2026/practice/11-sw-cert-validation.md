# 실습 11 — 소프트웨어 서명에 사용된 인증서 검증 진단

> 출처: KISEC 2026 기본과정 교재 p329–330 (Ⅳ-02 보안설계 기준 및 설계 기준 실습)
> 형식: 참고자료(p329 화면정의 SP-ENCRYPTION-02)를 보고 **p330 진단 양식**을 채우는 실습
> 유형: **검증 설계 진단** — 외부 패치파일 서명 인증서의 검증 방식이 보안기준에 부합하는지 진단한다.

| 항목 | 내용 |
|------|------|

| 화면명 | 로그인 화면 |
| 업무시스템 | 전자정부 프레임워크 공통컴포넌트 |
| 업무기능 | 인증서 서명 검증 |
| 단위시스템 | 로그인 |
| 처리개요 | 인증서 서명 검증에 대하여 정의 |

**검증 설계 내용**
- 설명: 외부 협력업체로부터 들어오는 **패치파일**에 올바른 인증서로 서명했는지 검증해야 한다.
- 검증 방법: 「안전한 방식으로 **Self-signed Certificate**(자체서명 인증서)를 이용한다.」
- 검증 항목: 「Certificate의 **expire date(만료일)** 가 유효해야 한다.」

### 식별된 결함 상세

| # | 검증 설계 내용 | 결함 | 개선 |
|---|--------------|------|------|
| ❶ | 「Self-signed Certificate를 이용」 | 자체서명 인증서는 신뢰된 제3자(CA)의 보증이 없어 위조·중간자 공격에 취약. "올바른 인증서로 서명했는지" 검증 목적과 모순 | 신뢰된 CA가 발급한 코드서명 인증서 사용 |
| ❷ | 검증 항목이 「expire date(만료일)」 만 | 유효기간만 확인하고 **신뢰체인(루트 CA까지)·폐기상태(CRL/OCSP)** 를 검증하지 않음 | 체인 검증 + 폐기 검증 추가 |
| ❸ | 서명 무결성 검증 절차 미명시 | 인증서 유효성과 별개로 파일 해시-서명 대조(무결성) 절차가 설계에 없음 | 서명값-파일해시 일치 검증을 명시 |

## 💡 진단 해설

**① 설계서가 제시한 내용** — 외부 협력업체가 보내는 패치파일이 올바른 인증서로 서명되었는지 검증하되, 그 방법으로 「안전한 방식의 Self-signed Certificate 이용」과 「인증서 만료일 유효」 두 가지를 든다. 진단 대상은 이 검증 설계다.

**② 보안기준 충족 여부 — 미적용(N)** —
- **Self-signed 인증서(❶)**: 자체서명 인증서는 발급자=주체로, 신뢰된 제3자(CA)의 보증이 존재하지 않는다. 공격자도 동일하게 자체서명 인증서를 만들 수 있으므로, "외부에서 들어오는 패치파일이 올바른 출처인지"를 가리는 본래 목적을 달성할 수 없다. 외부 신뢰 검증에는 공인 CA 발급 코드서명 인증서가 전제다. 가이드의 "안전한 방식으로 Self-signed를 이용"이라는 서술 자체가 형용모순이다.
- **만료일만 검증(❷)**: 인증서 검증은 ⓐ 신뢰체인(해당 인증서가 신뢰된 루트 CA까지 연결되는지), ⓑ 유효기간, ⓒ 폐기상태(CRL/OCSP로 탈취·오발급된 인증서가 무효화되었는지), ⓓ 용도(코드서명 EKU) 적합성을 모두 확인해야 한다. 본 설계는 ⓑ만 다루어 ⓐ·ⓒ·ⓓ가 누락되었다. 만료 전이라도 키 탈취로 폐기된 인증서로 서명된 악성 패치를 그대로 신뢰하게 된다.
- **무결성 검증 범위(❸)**: 인증서가 유효해도 서명값과 파일 해시의 일치(무결성)를 별도로 대조해야 변조 패치를 차단할 수 있는데, 그 절차가 명시되지 않았다.

**③ 설계단계 진단방법** — 암호화 설계서·외부 인터페이스 설계서에서 ⓐ 검증에 사용하는 인증서가 신뢰된 CA 발급인지, ⓑ 신뢰체인·유효기간·폐기·용도를 모두 검증하도록 설계되었는지, ⓒ 서명-파일해시 무결성 대조 절차가 있는지를 검토한다. 요구사항정의서·요구사항추적표로 외부 콘텐츠 무결성 검증 대책의 적용 여부를 추적한다.
