## 💡 진단 해설

웹 에디터 게시물 등록은 **사용자가 HTML 본문을 직접 작성 → DB 저장 → 목록/상세로 재출력 + 파일 첨부**가 결합된 기능이라, 화면 중 가장 다양한 입력데이터 검증 기준이 동시에 적용된다.

### 1. 웹 서비스 요청 및 결과 검증 (DSG-IV-05) — 핵심
- **왜 적용되는가**: 웹 에디터는 태그·스타일을 포함한 HTML을 그대로 입력받는다. 사용자가 `<script>` 등 악성 스크립트를 본문에 넣어 저장하면, 다른 사용자가 그 게시물을 조회할 때 스크립트가 실행되는 **저장형 XSS**가 발생한다. 입력 시점뿐 아니라 **DB조회 결과를 응답페이지에 출력할 때**도 외부입력값으로 간주해 필터링해야 하므로 두 측면(요청 검증 ①, 출력 검증 ②)이 모두 해당된다.
- **설계단계 진단방법**: 입력값·DB조회결과에 대한 XSS 필터링/HTML인코딩 설계가 **요구사항정의서**에 대책으로 수립되고 **아키텍처설계서**에 적용계획(공통 Filter/Interceptor/Validator 또는 View 출력 인코딩)이 반영되어 **요구사항추적표**로 추적 가능한지 확인한다. 코딩규칙은 **개발가이드**, 동작 점검은 **단위테스트케이스**를 검토한다.
- **결함 포인트**: 입력 필터링만 두고 출력 인코딩을 누락하거나, 웹 에디터라는 이유로 HTML 태그를 무검증 허용해 스크립트가 그대로 저장·재출력되는 경우.

### 2. DBMS 조회 및 결과 검증 (DSG-IV-01)
- **왜 적용되는가**: 업무흐름이 "제안내용을 DB에 추가" + "목록 조회 출력"이다. 입력값이 SQL 질의문에 동적으로 결합되면 SQL 삽입이 가능하다.
- **설계단계 진단방법**: 정적쿼리 사용·최소권한 DB 계정·동적쿼리 시 입력 필터링 설계가 **요구사항정의서·아키텍처설계서·개발가이드**에 반영되었는지, 쿼리 구조 변경 점검 계획이 **단위테스트케이스**에 있는지 확인한다.
- **결함 포인트**: 입력값을 문자열 연결로 SQL에 삽입하는 동적쿼리 설계.

### 3. 업로드·다운로드 파일 검증 (DSG-IV-10)
- **왜 적용되는가**: 처리개요에 "첨부파일을 입력"이 명시된다. 위험 확장자(jsp/php/asp 등) 파일이 업로드·실행되면 웹셸 공격으로 이어진다.
- **설계단계 진단방법**: 업로드 파일의 타입·크기·개수·실행권한 제한 정책과 안전한 저장위치(외부 비식별 경로·랜덤 파일명) 설계가 **요구사항정의서·아키텍처설계서·유즈케이스설계서·클래스설계서·DB설계서**에 있는지, 제한 정책 점검이 **단위테스트케이스**에 있는지 확인한다.
- **결함 포인트**: MIME-TYPE과 확장자를 동시 검사하지 않거나, 업로드 경로에 실행권한이 남아있는 설계.

### 4. 웹 기반 중요기능 수행 요청 유효성 검증 (DSG-IV-06)
- **왜 적용되는가**: 등록버튼 클릭은 DB 상태를 변경하는 데이터 처리 요청이다. 정상 절차를 거치지 않은 위조 요청(CSRF)으로 게시물이 등록될 수 있다.
- **설계단계 진단방법**: 모든 요청의 유효성 판별(세션별 CSRF 토큰·CAPTCHA·재인증) 설계가 **요구사항정의서·아키텍처설계서·클래스설계서**에 반영되고, 검증 동작 점검이 **단위테스트케이스**에 있는지 확인한다.
- **결함 포인트**: 등록 요청에 CSRF 토큰 검증 등 유효성 판별 절차가 없는 경우.
