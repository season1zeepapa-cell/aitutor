## 💡 진단 해설

p323 설계에는 "ASP/PHP/JSP 확장자를 **거부**하는 로직"과 "키워드 검사 단위테스트"가 명시되어 있다. 이는 보안설계를 시도한 것처럼 보이지만, **거부(블랙리스트) 방식**이라는 점에서 전형적인 결함 설계다.

### 업로드·다운로드 파일 검증 (DSG-IV-10) — 핵심
- **왜 적용되는가**: 게시판 파일 업로드는 업로드된 파일이 서버에서 실행되면 웹셸로 이어지는 대표적 고위험 기능이다. DSG-IV-10 ①(타입·크기·개수·실행권한 제한), ②(외부 비식별 저장)가 직접 적용된다.
- **블랙리스트의 한계(결함 포인트)**: ASP/PHP/JSP만 거부하면 목록에 없는 실행 가능 확장자(jspx, phtml, php5 등), 대소문자·이중확장자(`shell.jsp.txt`→`shell.jsp`), MIME-TYPE 위조로 우회된다. 보안설계 기준은 **확장자와 MIME-TYPE 동시 검사**, 가능하면 **화이트리스트** 방식을 요구한다.
- **설계단계 진단방법**: 업로드 파일 제한 정책(타입·크기·개수·실행권한)과 안전한 저장위치(외부 비식별 경로·랜덤 파일명·실행권한 제거) 설계가 **요구사항정의서·아키텍처설계서·유즈케이스설계서·클래스설계서·DB설계서**에 수립되고 **요구사항추적표**로 추적 가능한지 확인한다. 검증 동작과 우회 케이스 점검 계획은 **단위테스트케이스**를 검토한다. 본 사례는 단위테스트가 키워드 일치 검사에 머물러, 우회 케이스를 다루지 못하는 점이 추가 결함이다.

### DBMS 조회 및 결과 검증 (DSG-IV-01)
- **왜 적용되는가**: 처리개요에 "업로드된 파일을 저장하기 위해 DB를 설계한다"가 명시된다. 파일 메타정보(작성내용·원본/저장 파일명)를 DB에 입력·조회하는 과정에서 입력값이 동적 SQL에 결합되면 SQL 삽입이 가능하다.
- **설계단계 진단방법**: 정적쿼리·입력 필터링·최소권한 DB 계정 설계가 **요구사항정의서·아키텍처설계서·개발가이드**에 반영되었는지, 쿼리 구조 변경 점검이 **단위테스트케이스**에 있는지 확인한다.
- **결함 포인트**: 파일명·작성내용을 문자열 연결로 SQL에 삽입하는 동적쿼리 설계.
