## 💡 진단 해설

관리자 페이지는 처리개요에 "**관리자만 접근 가능**"이 명시되어 있어, 화면 자체에 대한 **접근통제·인증**이 1순위 보안설계기준이다. 여기에 검색 기능이 있으므로 입력데이터 검증이 더해진다.

### 1. 중요자원 접근통제 (DSG-SF-04) — 핵심
- **왜 적용되는가**: 관리자 페이지는 일반 사용자에게 노출되어선 안 되는 중요자원/중요기능이다. DSG-SF-04는 ③항에서 관리자 페이지 접근통제를 직접 다룬다 — URL을 추측 불가하게, 외부망이면 IP통제·80번 외 포트·SSL·추가인증, 내부망이면 별도 포트·SSL 권고.
- **설계단계 진단방법**: 관리자 페이지 접근통제 정책이 **요구사항정의서**에 수립되고 **아키텍처설계서**에 적용계획(URL·포트·SSL·IP통제·RBAC)이 반영되어 **요구사항추적표**로 추적 가능한지 확인한다. 접근통제 점검은 **단위테스트케이스**를 검토한다.
- **결함 포인트**: 관리자 페이지 URL이 쉽게 추측되거나, 역할 검사 없이 URL만 알면 접근 가능한 경우(파라미터 변조·강제 브라우징).

### 2. 인증 대상 및 방식 (DSG-SF-01)
- **왜 적용되는가**: 관리 기능은 중요기능이므로 '인증 후 사용' 정책이 우회 없이 적용되어야 한다. 인증을 거치지 않거나 권한상승으로 관리 기능에 도달하면 안 된다.
- **설계단계 진단방법**: 중요기능 분류(요구사항정의서)와 중앙집중식 인증·인증우회 방지 설계가 **아키텍처설계서·유즈케이스설계서·클래스설계서**에 반영되었는지, 2-factor 인증 고려 여부를 확인한다. 우회·권한상승 점검은 **단위테스트케이스**를 검토한다.
- **결함 포인트**: 인증을 각 기능에 산발 적용해 일부 관리 기능이 인증 없이 호출 가능하거나, 클라이언트 측 값만으로 관리자 여부를 판단하는 경우.

### 3. DBMS 조회 및 결과 검증 (DSG-IV-01)
- **왜 적용되는가**: 검색창 검색어가 공지사항 조회 SQL에 사용된다. 입력값을 동적쿼리에 결합하면 SQL 삽입으로 전체 공지사항·타 테이블이 노출될 수 있다.
- **설계단계 진단방법**: 정적쿼리·입력 필터링·최소권한 DB 계정 설계가 **요구사항정의서·아키텍처설계서·개발가이드**에 있는지, 쿼리 구조 변경 점검이 **단위테스트케이스**에 있는지 확인한다.
- **결함 포인트**: 검색어를 문자열 연결로 SQL에 삽입하는 동적쿼리.

### 4. 웹 서비스 요청 및 결과 검증 (DSG-IV-05)
- **왜 적용되는가**: 검색어가 결과화면에 다시 표시되거나(반사형 XSS), DB에 저장된 공지사항이 목록으로 출력될 때(저장형 XSS) 스크립트가 실행될 수 있다.
- **설계단계 진단방법**: 입력값·DB조회결과에 대한 XSS 필터링/HTML인코딩 설계가 **아키텍처설계서·개발가이드**에 반영되고, 동작 점검이 **단위테스트케이스**에 있는지 확인한다.
- **결함 포인트**: 검색어·조회결과를 인코딩 없이 응답페이지에 그대로 출력.

### 5. 세션통제 (DSG-SC-01)
- **왜 적용되는가**: 관리자 세션은 탈취 가치가 높다. 세션ID 노출·재로그인 시 미변경·장시간 미종료는 세션 하이재킹으로 이어진다.
- **설계단계 진단방법**: 세션ID 노출금지·재로그인 시 세션ID 변경·미사용 세션 종료 설계가 **요구사항정의서·아키텍처설계서**에 반영되었는지 확인한다.
- **결함 포인트**: 로그인 후 세션ID를 재발급하지 않거나(세션고정), 세션 유효기간·비활성 종료를 설계하지 않은 경우.
