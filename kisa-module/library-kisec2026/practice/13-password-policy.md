# 실습 13 — 패스워드 설정 규칙 진단

> 출처: KISEC 2026 기본과정 교재 p333–335 (Ⅳ-02 보안설계 기준 및 설계 기준 실습)
> 형식: 참고자료(p333 요구사항·규정 / p334 구현내용·테이블)를 보고 **p335 진단 양식**을 채우는 실습
> 유형: **규정 충족(적합성) 진단** — 패스워드 규정(요구사항) 대비 실제 설계/구현이 적합한지 항목별로 대조한다.

## 📄 참고자료 요약

| 항목 | 내용 |
|------|------|
| ID | SP-PASSWORD-01 |
| 화면명 | 패스워드 처리 화면 |
| 업무시스템 | 전자정부 프레임워크 공통컴포넌트 |
| 업무기능 | 패스워드 처리 |
| 단위시스템 | 인증 |

**요구사항(p333)**: [SEC-005] 개인정보보호법 준수, [REQ#102] 기관 패스워드 지침 준수
**규정(제6조) — 패스워드 규칙 9개**
| # | 규정 |
|---|------|
| 1 | 3가지 유형으로 9자리 이상 (대/소문자·특수기호·숫자 각 1개 이상) |
| 2 | 초기 패스워드는 변경 후 사용 |
| 3 | 90일마다 강제 변경 |
| 4 | 변경 후 최소 10일간 재변경 불가 |
| 5 | 직전 4개 패스워드 기억 (1년 내 재사용 금지) |
| 6 | ID와 동일한 패스워드 사용 불가 |
| 7 | 자동 로그인 사용 불가 |
| 8 | 연속 5회 입력 실패 시 계정 잠금 (10분 후 자동 해제) |
| 9 | 타 시스템과 동일 패스워드 사용 금지 |

**구현 내용(p334)**
- ID=PW 동일 여부, 3조합 9자리 설정 여부를 **javascript 함수**로 검증
- **초기 패스워드는 `00000000` 으로 설정**
- 패스워드 변경주기 3개월
- 자동 로그인은 구현하지 않음
- 입력 실패 count를 DB에 기록(로그인 성공 시 0으로 초기화)
- 변경일을 `update_date` 컬럼에 기록

**테이블 구조**: `id`, `pass`(varchar2 64, 예시 `8C6976E5B52…`), `update_date`, `prev1~prev4`(varchar2 20, 예시 `passW0rd!`·`Dkagh123$`…), `lock_flag`(Char 1, 예시 `N`), `deny_count`(Int, 예시 `4`)

| **보안설계기준** | **비밀번호 관리** (DSG-SF-03), **인증 시도 제한** (DSG-SF-02), **중요정보 저장** (DSG-SF-07) |
| **기준 설명** | 안전한 비밀번호 조합·저장(솔트 해시, 서버 실행)·재설정/변경·관리 규칙을 규정에 맞게 설계하고, 인증 시도 제한과 평문 저장 금지를 적용해야 한다. |

| **현황 및 문제점** | 규정 9개 중 부적합/누락 항목 존재(아래 대조표) 및 저장 보안 결함 |
| **관련 산출물** | 요구사항정의서, 규정/지침, 테이블 설계서, 화면설계서, 요구사항추적표 |
| **개선 방안** | 초기PW 무작위화·서버측 검증·10일 제한 컬럼/로직 추가·직전PW 해시 저장·잠금 해제(10분) 명시 |

### 규정 대비 구현 대조 (적합성 진단)

| # | 규정 | 구현 | 판정 |
|---|------|------|------|
| 1 | 3유형 9자리 이상 | javascript로 3조합·9자리 검증 | △ **부분적합** — 규칙은 맞으나 클라이언트 검증만으로는 우회 가능, **서버측 재검증 필요** |
| 2 | 초기PW 변경 후 사용 | **초기PW를 `00000000` 고정** | ✕ **부적합** — 추측 가능한 고정 초기값. 무작위·일회용 발급 필요 |
| 3 | 90일 강제 변경 | 변경주기 3개월(≈90일), `update_date` 기록 | ○ **적합** |
| 4 | 변경 후 10일 재변경 불가 | **관련 컬럼·로직 없음** | ✕ **누락(부적합)** — 최소 변경간격 제어 미설계 |
| 5 | 직전 4개 기억(1년 내 재사용 금지) | `prev1~prev4` 컬럼 보유 | △ **부분적합** — 컬럼은 있으나 **평문 저장**(예시 `passW0rd!`)이라 저장 보안 결함, 1년 기준 로직 확인 필요 |
| 6 | ID=PW 불가 | javascript로 동일여부 검증 | △ **부분적합** — 클라이언트 검증만, **서버측 재검증 필요** |
| 7 | 자동 로그인 불가 | 자동 로그인 미구현 | ○ **적합** |
| 8 | 5회 실패 잠금(10분 후 해제) | `deny_count` 기록·성공 시 0, `lock_flag` 보유 | △ **부분적합** — 잠금 컬럼은 있으나 **5회 임계·10분 자동해제 로직이 설계에 미명시** |
| 9 | 타 시스템 동일PW 금지 | (구현 없음) | ✕ **검증불가/한계** — 단일 시스템에서 강제 불가, 정책·교육으로 보완 명시 필요 |

> 저장 결함(공통): `prev1~prev4`를 **평문**(`passW0rd!` 등)으로 보관 → DSG-SF-07(중요정보 평문저장 금지) 위반. `pass` 컬럼도 솔트 적용 여부가 산출물상 불명확.

## 💡 진단 해설

**① 설계가 제시한 내용** — 기관 규정(제6조 9개 항목)을 충족하기 위한 패스워드 처리 기능과 테이블 설계다. 진단은 규정 대비 구현의 적합/부적합을 항목별로 판정하는 적합성 진단이다.

**② 보안기준 충족 여부 — 미적용(N)** — 적합 항목(3·7)도 있으나 다음이 결함이다.
- **초기PW `00000000` 고정(규정2, ✕)**: 규정은 "초기PW를 변경 후 사용"인데, 고정 추측가능값을 초기값으로 두면 변경 전 무단 로그인 위험이 크다. 사용자별 무작위·일회용 초기PW를 발급하고 최초 로그인 시 변경을 강제해야 한다(DSG-SF-03 ④ 재설정/변경 규칙).
- **10일 재변경 제한 미구현(규정4, ✕)**: 최소 변경간격을 통제할 컬럼(예: 마지막 변경시각 비교)·로직이 없어 규정을 강제할 수 없다. `update_date`를 활용한 간격 검증 로직 추가가 필요하다.
- **클라이언트 편중 검증(규정1·6, △)**: 3조합·9자리·ID≠PW를 javascript로만 검증하면 프록시·요청 변조로 우회된다. DSG-SF-03은 안전한 비밀번호 규칙 적용을 요구하며, 검증은 **서버에서** 재수행해야 한다(해시 실행도 서버, DSG-SF-03 ③).
- **직전 PW 평문 저장(규정5, △/저장결함)**: `prev1~prev4`에 `passW0rd!`처럼 평문이 들어간다. 재사용 금지 비교는 입력값의 해시를 저장된 해시와 대조하는 방식이어야 하며, 과거 비밀번호도 해시로 보관해야 한다(DSG-SF-07 평문저장 금지).
- **계정 잠금(규정8, △)**: `deny_count`·`lock_flag`는 있으나 "5회 임계 도달 시 잠금, 10분 후 자동해제"라는 임계값·해제 정책이 설계 산출물에 명시되지 않았다. DSG-SF-02(인증 시도 제한)에 맞춰 임계·잠금시간·해제방식을 명문화해야 한다.
- **타 시스템 동일PW(규정9, ✕/한계)**: 단일 시스템 차원에서 타 시스템 비밀번호와의 동일성은 기술적으로 검증 불가하다. 정책·이용자 안내로 보완하고, 진단서에는 "기술적 강제 불가, 정책 통제" 사유를 명시한다.

**③ 설계단계 진단방법** — 요구사항정의서·기관 패스워드 지침과 테이블/화면 설계서를 대조하여 규정 9개 항목별 적합·부적합을 판정한다. 특히 ⓐ 서버측 검증 설계 여부, ⓑ 초기PW 발급 방식, ⓒ 최소/최대 변경주기 제어, ⓓ 과거 비밀번호·현재 비밀번호의 해시 저장 여부, ⓔ 잠금 임계·해제 정책을 산출물에서 확인한다. 요구사항추적표로 규정 각 항목이 설계에 추적되는지 검증한다.
